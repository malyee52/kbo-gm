## 0. 요약

- 사용자 판단: "대대적인 경기 진행 규칙에 대한 수정이 있어야 할 것 같아." 고친 데만 덧대지 않고 경기 진행 규칙 전체를 다시 짠다.
- **사용자 결정 (2026-10-22, 클사장 전달)**
  1. **두 엔진을 함께 둔다.** 자동 진행(시즌 시뮬, AI 구단끼리의 경기, 하루·한 번에 진행)은 **B 타석 단위 엔진**, 플레이어가 직접 지휘하는 수동 경기는 **A 투구 단위 엔진**을 쓴다.
  2. **진행 속도는 제약이 아니다.** 지금보다 훨씬 느려져도 된다. 속도는 단계마다 재는 측정 항목으로만 둔다.
  3. **범위**: 투구 수, 타구 유형·수비, 능력치 체계에 더해 대타·대주자·수비 교체, 고의4구, 홈 이점 방향 바로잡기, 그리고 2장 "현실과 다른 점" 목록의 나머지 전부.
  4. **수동 경기의 지시는 1단계로 감독 작전만** (투수 교체, 대타·대주자·수비 교체, 도루, 번트, 고의4구 등). 공 하나하나는 지켜보기만 한다. 공마다 구종·코스를 고르는 기능은 나중 단계로 두고 A에 구종 자리와 구종별 능력 확장 여지를 열어 둔다 (3.4.1).
- 이 기획의 뼈대: **경기 상태와 규칙(주루·수비·교체·기록)은 한 벌로 두 엔진이 같이 쓰고, "타석을 어떻게 끝내는가"만 두 가지로 둔다.**
  A는 볼카운트를 한 공씩 진행하고, B는 같은 볼카운트 모형을 계산으로 접어 타석 결과와 투구 수를 한 번에 뽑는다. 그래서 두 엔진의 타석 분포는 맞춤값으로 비슷하게 만드는 것이 아니라 **식으로 같다** (3.6절). 남는 차이(타석 중 도루·폭투·피로, 플레이어 지시)는 3.6.3에서 따로 처리하고 동등성 테스트로 잰다.
- 추천 순서는 6장 (0~19단계, 나중 단계 20 구종·코스 지시). 엔진 1을 그대로 옮기는 구조 분리부터 하고, 투구 수 → 타구 모형 → 주루 → AI 감독 → 시대·규칙 → 화면 → A 엔진 → 수동 경기 저장 순서로 간다.

## 2. 현실과 다른 점 목록 (플레이어가 보고 느끼는 증상별)

★ = 사용자가 짚은 것, ● = 이미 알려진 것, ○ = 이번에 코드를 읽다 찾은 것. 괄호는 1장 규칙 번호.

### 2.1 투수 운용이 투구 수와 따로 논다
1. ★ 투구 수가 없다. 박스스코어·중계에 투구 수가 없고, 선발 교체·피로·연투가 모두 상대 타자 수로 정해진다 (P7, C1, F1).
2. ○ 공 15개로 1이닝을 끝낸 구원과 35개를 던진 구원이 다음 날 같은 피로다 (F1). 연투·누적 피로가 구위에 영향이 없다 (F3).
3. ● 블론이 팀당 5~10개 많다 (기회당 40~44%, 실제 28~35%). 세이브 기회도 팀당 +4~12번 (C7, `reports/luck-check.md`).
4. ○ 구원 전용 투수의 이닝 몫이 36~38% (실제 28~33%).
5. ○ 좌우 원포인트·불펜의 손 고려가 없다 (C7).
6. ○ 선발 한계가 매 경기 ±18% 무작위라 투구 수 관리처럼 보이지 않는다 (C1).

### 2.2 타구와 수비가 따로 논다
7. ★ 타구가 땅볼인지 뜬공인지 선수와 무관한 50:50이다 (I2). 땅볼 투수·뜬공 타자가 없다.
8. ★ 수비는 8명 합 하나로 모든 안타를 줄인다. 외야 수비가 좋으면 내야 땅볼 안타도 준다 (T5).
9. ○ 타구 방향이 없어 외야수 어깨·좌우 방향이 주자 진루에 영향이 없다 (B1, B2, I5).
10. ○ 내야 뜬공이 따로 없어 3루 주자가 있는 모든 뜬공에서 76%가 희생플라이다 (I5).
11. ○ 병살이 타자 주력·땅볼 성향과 무관한 43%다 (I3). 땅볼 아웃 때 1루 주자 처리도 반반 (I3).
12. ○ 실책은 타구와 상관없이 몫으로 수비수를 고른다 (I1).
13. ○ 2025 개막 라인업 수비 자리 80개 중 23개가 그 해 실제 주 포지션 밖이다 (R6).

### 2.3 감독이 경기 중 손을 쓰지 않는다
14. ● AI 감독이 대타·대주자·수비 교체를 하지 않는다 (B10). 주전 의존이 크다 (상위 9명 타석 비중 0.755 대 0.708).
15. ● 고의4구가 없다 (T7).
16. ○ 라인업이 상대 선발의 손을 보지 않는다 (R8). 플래툰이 없다.
17. ○ AI 희생번트는 늘 성공한다 (B7).
18. ○ 도루는 2루 도루뿐이고 견제·퀵모션이 없다 (B5). 폭투는 투수 제구와 무관하다 (B6).
19. ○ 주력이 도루 시도율에서 나와 뛰지 않는 빠른 선수는 주루가 느리다 (P6).

### 2.4 리그 결과가 실제와 어긋난다
20. ● 팀 간 격차가 좁다 (승률 표준편차 0.060, 실제 0.073). 실점 퍼짐이 실제의 약 60%였다 (`docs/temp-values.md`).
21. ● 병살·희생플라이가 과다하다 (1985년 +41%·+32%) (Y4).
22. ● 홈 이점 방향이 반대인 해가 있다 (1985년 실제 홈 승률 0.459, 시뮬은 홈 우세). 홈 이점이 모든 시대에 같은 값이다 (T3, Y4).
23. ● 2000년 이전 득점이 높다 (1985년 +10%) (Y4).
24. ○ 2015년 이전은 구장 효과가 없다 (Y5).
25. ● 2021년 9이닝 무승부 규정이 없다 (E1).
26. ○ 결장 중인 선수가 인원이 모자라면 경기에 나온다 (R5).
27. ○ 경기 중 부상이 없다 (J1). 야수 피로가 없다 (F5).

### 2.5 기록 규정이 단순하다
28. ○ 세이브·블론에 동점 주자 조건이 없고, 세이브는 1아웃이면 된다 (E3, E4). 승리 투수 규정이 단순하다 (E2).
29. ○ 자책·비자책을 실책 재구성 없이 확률로 나눈다 (I6). 실책 출루 수를 비자책 비율로 거꾸로 추정한다 (P12).

### 2.6 능력치와 경기의 관계가 안 보인다
30. ★ 화면 등급은 경기 비율을 그 월드 기준 집단으로 바꾼 값이고 80에서 잘린다 (G2). 같은 등급이 해마다 다른 비율이다.
31. ○ 컨택 하나에 단타·장타·홈런·삼진이 섞여 있어 "컨택 60이면 경기에서 무엇이 얼마나"를 말할 수 없다 (G1).
32. ○ 투수의 피안타 억제는 경기에 쓰이지만 화면에 없다 (G3).
33. ○ 종합 등급(WAR 눈금)과 세부 등급(분포 눈금)의 눈금이 다르다 (G4).
34. ○ 자유 모드에서 80 넘는 선수를 만들 수 없다 (G6).
35. ○ 체력이 "상대 타자 수"라 화면 숫자가 투구 수로 읽히지 않는다 (P7).

### 2.7 직접 지휘
36. ○ 직접 지휘 중 고른 선택이 경기 도중 저장되지 않는다 (D2).
37. ○ 한 경기의 난수 소비가 그날 다른 경기 결과를 바꾼다 (D3). 수동 경기를 다른 엔진으로 돌리면 리그 전체가 흔들린다.

## 3. 새 경기 진행 구조: 두 엔진을 함께 둔다

### 3.1 무엇을 정했나

| 상황 | 엔진 |
|---|---|
| 시즌 시뮬, 환경 맞춤 예비 시즌, AI 구단끼리 경기, 하루·한 번에 진행, 검증 도구 | **B 타석 단위** |
| 플레이어가 직접 지휘하는 경기 (정규시즌·가을야구) | **A 투구 단위** |
| 올스타전 | B (지휘 기능이 생기면 A) |

속도는 제약이 아니다. 단계마다 시즌당 시간·시즌 시작 시간·수동 경기 한 경기 시간을 재서 기록만 한다.

### 3.2 전체 구조

```
                 ┌──────────────── 공통 ────────────────┐
 월드·능력치 ──▶ │ 경기 상태 GameState                  │
                 │  (이닝·아웃·주자와 책임 투수·점수·    │
                 │   타순·수비 배치·마운드 투수의 투구 수 │
                 │   ·교체로 빠진 선수·기록)             │
                 │ 규칙 계층                             │
                 │  AI 감독 판단 (타석 경계에서)          │
                 │  타석 결과 함수 (log5, 보정)           │
                 │  볼카운트 사슬 (공 하나의 확률)        │
                 │  타구 모형 (유형·방향·담당 수비수·    │
                 │   안타·아웃·실책·병살·희생플라이)       │
                 │  주루 (진루·도루·견제·폭투)           │
                 │  기록 (승·패·세이브·홀드·블론·자책)    │
                 └──────────────────────────────────────┘
                        │                       │
               ┌────────▼───────┐      ┌───────▼────────┐
               │ B 해결기        │      │ A 해결기        │
               │ 타석 한 번에:    │      │ 공 하나씩:      │
               │ 결과 + 투구 수   │      │ 볼·스트라이크·  │
               │ (사슬을 계산으로 │      │ 파울·인플레이   │
               │  접은 분포)      │      │ (사슬을 그대로) │
               └─────────────────┘      └─────────────────┘
```

- **두 엔진이 다른 곳은 "타석을 끝내는 방법" 하나뿐이다.** 주루·타구·수비·교체·기록 코드는 한 벌이다. 그래서 규칙을 고치면 두 엔진에 같이 들어간다.
- AI 감독 판단(투수 교체, 대타, 고의4구 등)은 두 엔진 모두 **타석 경계에서** 한다. A에서만 공 사이 판단을 허용하는 것은 플레이어의 직접 지휘와, 공 단위로만 정의되는 사건(카운트 도루, 피치아웃)뿐이다 (3.6.3).

### 3.3 B 타석 단위 엔진 (자동 진행)

한 타석을 다음 순서로 푼다.

1. **AI 감독 판단** (공통): 투수 교체, 대타·대주자·대수비, 고의4구, 도루·번트·히트앤드런 작전 (3.9).
2. **타석 전 주루** (공통): 도루(2루·3루·이중), 견제, 폭투·보크. 확률은 "이 타석에 던질 공 수의 기댓값"으로 공 하나 확률을 늘려 쓴다 (3.6.3).
3. **타석 결과**: 타석 결과 함수가 낸 목표 확률(삼진 K, 볼넷 W, 사구 H, 공을 맞힘 X)과 볼카운트 사슬로 **결과와 투구 수를 함께** 뽑는다. 카운트 0-0에서 시작하지 않아도 된다 (A에서 넘겨받은 타석, 3.8).
4. **타구** (X이면, 공통 타구 모형):
   1. 유형: 땅볼·라인드라이브·뜬공·내야 뜬공 (타자 성향 × 투수 성향 × 리그 기준).
   2. 방향: 당겨·가운데·밀어 → 9개 구역 (치는 손 기준).
   3. 결과: 홈런 / 안타(단타·2루타·3루타) / 아웃. 안타 확률 = 유형 기준 × 타자 타구 질 × 투수 타구 억제 × **그 구역 담당 수비수의 범위** × 구장 (방향별 홈런 값 포함).
   4. 아웃이면 처리: 땅볼 → 병살·포스·야수선택·실책 (담당 내야수의 포구·송구, 타자 주력), 뜬공 → 희생플라이·진루 (외야수 어깨, 깊이, 주자 주력), 내야 뜬공 → 진루 없음.
5. **투구 수 누적·피로** (공통): 마운드 투수의 투구 수 += 이 타석 공 수.

B는 자료가 없는 성향(땅볼 성향 등)을 모두 리그 평균으로 두면 지금 엔진과 거의 같은 결과로 줄어들게 만든다. 단계마다 "새 기능을 끈 상태 = 앞 단계와 같은 결과"를 검증 기준으로 쓴다.

### 3.4 A 투구 단위 엔진 (수동 경기)

**플레이어가 지시하는 것 (1단계, 2026-10-22 사용자 결정): 감독 작전만.** 투수 교체, 대타·대주자·수비 교체, 도루, 번트(희생·스퀴즈), 고의4구 같은 감독의 판단이다. **공 하나하나는 지켜보기만 한다.** 공마다 구종·코스를 고르는 기능은 나중 단계(6장 20단계)로 두고, 그때 붙일 수 있게 구조만 열어 둔다 (3.4.1).

한 공을 다음 순서로 푼다.

1. **작전 판단**: 플레이어가 맡은 쪽은 플레이어의 감독 작전, 다른 쪽은 AI 감독. 둘 다 타석 경계에서 묻는 것이 기본이고, 도루처럼 공 사이에 의미가 있는 작전은 주자가 있을 때 공 사이에서도 낼 수 있게 한다 (물음 시점은 7장 7번).
2. **공 사이 주루**: 도루 시도, 견제, 폭투·포일·보크 (공 하나 확률).
3. **공 하나의 결과**: 볼 / 스트라이크(보는 공·헛스윙) / 파울 / 맞힘 / 사구. 확률은 볼카운트 사슬 (3.6).
4. 볼넷·삼진·사구·맞힘으로 타석이 끝나면 B와 같은 공통 코드로 처리 (맞힘이면 같은 타구 모형).
5. 공마다 투구 수·피로가 오른다 (B는 타석 단위로 같은 값을 더한다).

화면: 볼카운트, 투구 수, 공마다 결과("2-2에서 헛스윙 삼진"), 타구 유형·방향("유격수 쪽 땅볼, 6-4-3 병살").

#### 3.4.1 구종·코스 자리 열어 두기 (나중 단계 대비)

1단계에서도 A의 공 하나는 다음 모양으로 만든다. 지금은 비어 있는 칸이 있어도 된다.

```
Pitch = {
  count: [볼, 스트라이크] (던지기 전),
  type?: 구종 (1단계: 비움 = "평균 구종" 하나),
  zone?: 코스 (1단계: 비움),
  result: 볼 | 보는 스트라이크 | 헛스윙 | 파울 | 맞힘 | 사구,
  pitches: 이 투수의 경기 투구 수 (던진 뒤)
}
```

- **공 하나의 확률 = 구종별 확률을 구종 비율로 섞은 값.** 1단계는 구종이 하나라 지금 사슬 그대로다. 나중에 구종을 넣으면 카운트 칸마다 "구종 비율 × 구종별 볼·헛스윙·파울·맞힘 확률"의 합이 그 칸의 확률이 된다.
- **B는 바뀌지 않는다.** 구종을 섞은 결과도 카운트 칸마다 하나의 확률표라서, B는 그 사슬을 똑같이 접는다. 구종 비율이 카운트에 따라 달라도(2스트라이크 뒤 변화구 등) 칸마다 섞으면 되므로 두 엔진의 분포가 같다는 성질(3.6.1)이 그대로 남는다.
- **능력치 확장 여지**: 투수 능력에 선택 항목 `arsenal?: { type, share, 구위·제구·장타 억제·땅볼 성향 배율 }[]`을 둔다. 없으면 지금의 투수 능력이 "평균 구종" 하나로 쓰인다. 넣을 때는 **구종을 섞은 평균이 그 투수의 지금 능력(삼진·볼넷·피홈런 배율)과 같아지도록** 구종별 배율을 정한다. 그래야 구종을 넣어도 시즌 기록과 B가 틀어지지 않는다.
- **플레이어의 구종·코스 지시**(나중): 플레이어가 고른 구종·코스는 그 공의 확률표만 바꾼다 (예: 몸쪽 높은 직구 → 헛스윙·장타 위험이 함께 오름). 지시하지 않은 공은 AI 포수가 구종 비율대로 고른다. 이 지시는 A에서만 생기므로 B와의 동등성 검증은 "지시 없음"으로 한다.
- 조작 기록에는 지금 공 단위 선택 자리를 만들지 않는다. 나중 단계에서 `choices`의 선택 모양에 `pitch?: {type, zone}`을 더한다 (물음 번호 방식이라 예전 기록과 섞여도 읽힌다).

### 3.5 두 엔진이 같은 능력치 체계를 쓰는가: 쓴다

- **선수 능력은 한 벌이다.** A만 쓰는 능력, B만 쓰는 능력이 없다. 능력은 모두 "리그 대비 배율"(1.00 = 리그 평균)로 저장하고, 화면 등급은 그 배율의 고정 변환이다 (4장).
- 능력이 두 엔진에 들어가는 길:

| 능력 | 들어가는 곳 | A에서 | B에서 |
|---|---|---|---|
| 컨택 (삼진 피하기) | 타석 결과 함수 K | 헛스윙 확률 | 같은 사슬을 접은 K |
| 선구 (볼넷) | W | 볼을 고르는 확률 | 같음 |
| 사구 | H | 공 하나의 사구 확률 | 같음 |
| 끈질김 (파울로 버티기) | 사슬의 파울 몫 | 2스트라이크 파울 | 투구 수 분포 |

### 3.6 두 엔진의 기록 분포를 같게 맞추는 방법

#### 3.6.1 원칙: 볼카운트 사슬을 기준 모형으로 두고, B는 그 사슬을 계산으로 접는다

- **기준 모형 = 볼카운트 사슬.** 카운트 12칸(볼 0~3 × 스트라이크 0~2)에서 공 하나마다 볼·스트라이크·파울·맞힘·사구로 옮겨 가는 확률표다. 칸마다 리그 기본 모양(임시값, 자료가 오면 맞춤)에 선수 능력 배율을 곱한다.
- 매치업(타자 × 투수 × 그 순간의 보정)마다 **사슬의 끝 확률이 타석 결과 함수의 목표(K·W·H)와 같아지도록** 사슬의 손잡이 세 개(볼 몫, 헛스윙 몫, 사구 몫)를 푼다. 끝 확률은 12칸 사슬이라 바로 계산된다 (반복 몇 번으로 풀림. 같은 매치업은 저장해 다시 쓴다).
- **A**는 이 사슬을 공 하나씩 그대로 돌린다.
- **B**는 같은 사슬에서 계산한 **(끝 결과, 투구 수)의 결합 분포**에서 한 번에 뽑는다. 사슬이 같으므로 한 매치업 안에서 B의 분포는 A의 분포와 **식으로 같다.** "B의 확률표를 A에서 뽑는" 것을 시뮬레이션 대신 계산으로 하는 셈이다.
- 맞힘(X) 뒤는 두 엔진이 같은 타구 모형을 쓴다. 홈런·안타 몫은 "목표 홈런 ÷ X" 같은 조건부 비율이라 선수의 홈런·안타 능력이 사슬과 상관없이 보존된다.
- 리그 맞춤(`calibrate`)은 B로만 돌린다. 맞춤 계수는 타석 결과 함수에 들어가므로 A도 자동으로 같은 계수를 받는다.

#### 3.6.2 사슬의 모양은 어디서 오나

| 손잡이 | 자료가 있을 때 | 없을 때 (임시값) |
|---|---|---|
| 리그 타석당 투구 수 | 연도별 리그 P/PA로 맞춤 | 사슬 기본 모양이 내는 값 그대로 (현대 약 3.9 안팎을 목표로 한 임시값, 확인 안 됨) |
| 선수별 타석당 투구 수 | 타자 P/PA, 투수 P/PA로 끈질김·투구 효율 맞춤 | 삼진·볼넷 비율에서 사슬이 저절로 낸다 (삼진은 공 3개 이상, 볼넷은 4개 이상이 필요해서 삼진·볼넷이 많은 선수는 공을 더 쓴다) |
| 카운트별 모양 (초구 스트라이크, 3볼에서 보는 공) | 카운트별 결과 표로 맞춤 | 관례적 모양 (임시값) |
| 카운트에 따른 타구 질 (유리한 카운트에서 잘 맞음) | 카운트별 타율로 맞춤 | 1단계에서는 넣지 않는다 (카운트와 무관). 넣으면 B는 "맞힐 때의 카운트 분포"로 섞어 같은 값을 낸다 |

자료 없이도 투구 수가 생긴다는 점이 중요하다. 자료는 분포를 조금 바로잡는 데만 쓴다.

#### 3.6.3 두 엔진이 달라질 수 있는 곳과 처리

| 차이 | 처리 |
|---|---|
| 타석 중 도루·폭투 (A는 공 사이, B는 타석 전) | B는 "공 하나 확률 × 이 타석 기대 투구 수"로 한 번에. 투구 수 기댓값은 사슬에서 계산 |
| 타석 중 피로 증가 (A는 공마다) | B는 타석 중간 투구 수 시점의 피로로 계산 |
| 타석 중 투수 교체·지휘 (A만) | 플레이어 지휘에서만 생긴다. AI 감독은 타석 경계에서만 판단해 차이가 없다 |
| 카운트를 보는 작전 (공 사이 도루 출발 등) | AI 감독은 쓰지 않는다 (타석 단위 확률로 접는다). 플레이어만 A에서 쓴다 |
| 구종·코스 지시 (나중 단계) | A에서만 생긴다. 동등성 검증은 지시 없이 한다 (3.4.1) |

#### 3.6.4 검증 (엔진마다, 그리고 둘 사이)

| 구분 | 무엇을 | 기준 |
|---|---|---|
| 사슬 계산 | 12칸 사슬의 계산 끝 확률 = 목표 K·W·H | 오차 1e-9 (단위 테스트) |
| 매치업 동등성 | 대표 매치업 50쌍(강타자·약타자 × 삼진형·제구형·땅볼형 투수 × 피로) A 20만 타석 대 B 20만 타석: 삼진·볼넷·사구·홈런·단타·2루타·3루타·땅볼·뜬공·투구 수 분포 | 모든 칸 차이가 표본 오차 3배 안 (카이제곱 검정 p > 0.001) |
| 경기 동등성 | 같은 두 팀 2,000경기씩 A(양쪽 AI 감독)·B: 득점 평균·분산, 타율, 삼진·볼넷·홈런 비율, 경기당 투구 수, 선발 투구 수·이닝, 투수 교체 수, 병살, 도루 | 평균 차이가 표본 오차 3배 안 |

| A 리그 검증 | `npm run validate -- --engine A --years 2025 --seasons 20` (느려도 됨) | B와 같은 기준. B와의 차이가 표본 오차 안 |
| 재현 | 같은 시드·같은 지휘 → 같은 결과. 경기 중 저장 뒤 이어가기 = 끊지 않은 결과 | 완전히 같음 |

### 3.7 난수·저장·재현

#### 3.7.1 경기별 난수 줄기 (먼저 바꿀 것)

- 지금은 그날 모든 경기가 한 줄기(`rng.fork('games')`)를 차례로 쓴다. A로 한 경기를 치르면 난수 소비가 달라져 **그날 뒤 경기들이 모두 바뀐다.**
- 바꿀 안: 경기마다 따로 줄기를 뽑는다. 정규시즌 `seasonRng.fork('g/<날짜>/<홈>-<원정>')`, 가을야구 `fork('ps/<라운드>/<경기 번호>')`. 경기 안에서는 해결기 줄기와 규칙 줄기를 다시 나눌 수 있다.
- 효과: 한 경기를 A로 하든 B로 하든 다른 경기가 그대로다. 저장에 경기 난수 위치(`rngGames`)를 넣을 필요가 없어진다 (날짜만 있으면 된다).
- 대가: 같은 시드의 결과가 지금과 달라진다 → 시즌 저장 형식(`SeasonSave.format`)을 올린다.
- 라인업 휴식·부상은 지금처럼 하루 줄기(`dayRng`)에서 경기 전에 뽑는다. 경기 중 부상을 넣으면(6장 13단계) 그 경기 줄기에서 뽑는다.

#### 3.7.2 조작 기록 (`GameAction`)

- 지금: `{type: 'command', day, choices}`, 선택은 물음 번호(`n`) 순서 목록.
- 바꿀 안: `{type: 'command', engine: 'A', day, game, choices, handoff?}`
  - `game`: 경기 키 (가을야구 포함). 하루에 우리 경기가 둘(더블헤더)이 생겨도 구분된다.
  - `choices`: A는 공마다 물을 수 있어 물음이 수백 개가 된다. 빈 선택(자동)은 적지 않고 `[물음 번호, 선택]` 짝만 적는다.
  - `handoff`: 수동 → 자동 전환 지점 (3.8).
- 재현(`GameSession.replay`): 그날 경기들을 경기별 줄기로 돌리고, 우리 경기는 기록된 지휘로 A를 다시 돌린다.

#### 3.7.3 수동 경기 도중 저장

- 지금은 경기 도중 선택이 화면에만 있다 (D2).
- 바꿀 안: 진행 중인 수동 경기를 세션 저장에 `pendingGame: {day, game, choices, at}`로 넣는다 (자동 저장 포함). 불러오면 **경기 처음부터 A를 기록된 선택으로 다시 돌려 `at` 물음에서 멈춘다.** A가 결정적이라 경기 상태 전체를 저장할 필요가 없다 (경기 하나를 다시 돌리는 시간은 측정 항목).
- 고른 선택은 확정으로 본다 (한 번 진행한 공은 되돌리지 않는다). 미리보기·되돌리기를 남길지는 7장 4번.

#### 3.7.4 저장 호환

| 대상 | 영향 | 처리 안 |
|---|---|---|
| 시즌 저장 (`SeasonSave`) | 경기 난수 방식, 피로(투구 수), 새 기록(투구 수·땅볼·고의4구 등) | `format` 2. 형식 1은 불러와서 **다음 경기부터 엔진 2로** 이어 한다 (진행한 기록은 그대로). 피로는 상대 타자 수 × 리그 P/PA로 바꿔 넣는다 |
| 세션 저장 (`format: 2`) | 리그 상태 선수에 새 능력 | `format` 3. 새 능력이 없는 예전 선수는 자료에서 다시 뽑거나(실존) 리그 평균(가상)으로 |
| 조작 기록 재현 | 엔진 1로 만든 기록은 엔진 2에서 같은 결과가 안 나온다 | 저장에 `engine: 2` 표시. 엔진 1 기록의 재현은 지원하지 않거나, 엔진 1 코드를 남긴다 (7장 8번) |
| 월드 지문 (`rosterFingerprint`) | 선수 구성은 그대로 | 그대로 |

### 3.8 수동 경기 중간에 자동으로 넘기기 (이어 붙이기)

경기 상태(`GameState`)가 두 엔진 공통이므로 어느 공에서든 넘길 수 있다.

| 방식 | 하는 일 | 장점 | 단점 |
|---|---|---|---|
| ① A로 계속 (AI 감독) | 남은 경기를 같은 A로, 지휘만 AI에게 | 엔진이 안 바뀌어 가장 단순. 결과 분포 같음 | 한 경기를 끝까지 공 단위로 돌려 조금 느림 (그래도 한 경기) |
| ② B로 전환 ("빠르게 끝내기") | 지금 상태를 B에 넘겨 남은 경기를 B로 | 빠름 | 넘기는 지점·줄기를 기록해야 함 |

②의 규칙:
- 넘기는 순간의 카운트(예: 2-1)와 투구 수를 그대로 넘긴다. B는 사슬을 그 카운트에서 시작해 접으므로 남은 타석도 분포가 같다.
- 넘긴 뒤 난수는 경기 줄기의 하위 줄기 `…/b@<물음 번호>`. 조작 기록 `handoff: {at: 물음 번호, to: 'B'}`. 재현 때 같은 지점에서 같은 줄기로 넘어가 결과가 같다.
- 반대 방향(자동 진행 중 우리 경기에 끼어들기, B → A)도 같은 방법으로 된다. 지금 "위기 상황에서 멈춤"(`isCrisis`)을 A 경기로 여는 기능이다 (7장 6번).

### 3.12 검토했지만 쓰지 않는 길

- **지금 구조에 덧대기** (투구 수만 붙이고 땅볼 비율만 선수별로): 사용자가 원하지 않았다. 수비 합(T5)·주루 근거(B1)·감독 판단이 그대로 남는다.

- **A를 대량 시뮬레이션해 B의 확률표를 만들기**: 가능하지만 매치업 조합이 많아 표가 커지고 표본 오차가 남는다. 사슬이 12칸이라 계산으로 접는 편이 정확하고 작다. 실제 자료로 사슬을 맞추는 도구(`tools/fit_count_chain.ts`, 새로 만듦)만 오프라인으로 돈다.

## 4. 능력치 체계 정리

### 4.1 원칙

1. **내부 값 = 리그 대비 배율 하나** (1.00 = 그 해 리그 평균). 두 엔진이 같이 쓴다.
2. **화면 등급 하나 = 경기 손잡이 하나.** 한 등급이 여러 사건을 섞지 않는다 (지금의 컨택처럼).
3. **등급과 배율은 고정된 식으로 오간다** (해마다·월드마다 바뀌지 않는다).
   - 등급 g → 배율 r = exp((g − 50) ÷ 10 × s), 배율 → 등급 g = 50 + 10 × ln(r) ÷ s.
   - s = 그 능력의 "한 칸 폭" (10점이 몇 배인가). 2015~2025 주전의 ln(배율) 표준편차로 한 번 정하고 고정한다 (임시값, 도구로 정함).
   - 50 = 리그 평균 배율 1.00. 60 = 한 칸 위, 70 = 두 칸 위.
4. **등급 옆에 "기대 기록"을 같이 보여 준다**: 리그 평균 상대·600타석(투수는 선발 30경기 또는 구원 60이닝) 기준 그 사건의 기대 횟수. 등급이 무엇을 뜻하는지 숫자로 바로 보인다.
5. 지금 화면의 상대 등급(그 해 선수 사이 순위)은 "리그 내 순위" 같은 별도 표시로만 남긴다.

### 4.3 예시 계산: 파워 70 타자 대 장타 억제 40 투수 (2025년)

- 리그 타석당 홈런 0.0213 (2025 실제, `docs/engine.md` 4장).
- 한 칸 폭 s: 타자 홈런 0.45, 투수 피홈런 0.25 (**임시값**, 도구로 정할 값).
- 타자 파워 70 → 배율 r = exp(2 × 0.45) = **2.46** → 타자 쪽 홈런 확률 0.0213 × 2.46 = 0.0524.
  - 리그 평균 투수 상대 600타석 기대 홈런 = 600 × 0.0524 ≈ **31개** ← 화면에 등급 옆으로 보일 숫자.
- 투수 장타 억제 40 → 피홈런 배율 exp(1 × 0.25) = **1.28** (한 칸 나쁨) → 투수 쪽 0.0213 × 1.28 = 0.0273.
- 승산비 결합 (지금과 같은 식):
  - 타자 승산 0.0524 ÷ 0.9476 = 0.0553, 투수 승산 0.0273 ÷ 0.9727 = 0.0281, 리그 승산 0.0213 ÷ 0.9787 = 0.0218.
  - 결합 승산 = 0.0553 × 0.0281 ÷ 0.0218 = 0.0714 → 확률 0.0714 ÷ 1.0714 = **0.0667**.
- 그 밖의 보정(좌우·홈·피로·구장)은 지금처럼 배율로 곱한 뒤 결합한다.
- A에서는 이 0.0667이 "공을 맞힐 확률 X × 맞혔을 때 홈런일 확률"로 나뉘어 들어간다. 예를 들어 이 매치업의 X가 0.70이면 맞혔을 때 홈런 확률 = 0.0667 ÷ 0.70 = 0.095. B는 0.0667을 바로 쓴다. 두 엔진의 홈런 확률은 같다.

투구 수 예시: 선발 체력 "약 100구", 투구 효율 50인 투수가 리그 평균 타석당 3.9구(임시값)면 한계까지 약 26타자. 투구 효율 60(타석당 공 수가 한 칸 적음, 한 칸 폭 0.05로 가정하면 3.9 × e^−0.05 ≈ 3.7구)이면 약 27타자.

지금 상태: 엔진은 배율을 쓰므로 상한이 없다. 화면(`display.ts`·`ui/grades.ts`·`defense.ts defenseGrade`)이 20~80에서 자르고, 자유 모드 입력(`fantasy/free.ts runsForGrade`)도 80에서 잘라 80 넘는 선수를 못 만든다.

## 6. 추천안과 만드는 순서

추천: **3장 구조 그대로** (공통 상태 + 공통 규칙 + B·A 두 해결기). 범위는 2장 목록 전부.
순서 원칙: 결과를 바꾸지 않는 구조 분리 → 자동 진행(B)에서 하나씩 바꾸고 검증 → 화면 → A를 마지막에 얹는다 (A는 B와 같은 규칙을 쓰므로 B가 맞은 뒤에 붙이는 편이 검증이 쉽다).
모든 단계 공통 기준: `npm test` 통과, `npm run typecheck`, `npm run validate -- --years 2025,2019,2012 --seasons 100`에서 맞춤 지표 ±1%·경기당 득점 ±5% (`docs/engine.md` 4장), 시즌당 시간·시즌 시작 시간 기록 (제약 아님).
"결과 같음" 단계는 같은 시드 결과가 완전히 같아야 한다.

| 단계 | 내용 | 검증 기준 |

| 0 | **기준값 고정**: 지금 엔진으로 검증 지표 전부(득점·병살·희생플라이·도루·홈 승률·승률 표준편차·상위 9명 타석·이닝 상위 5명·블론·QS·구원 이닝 몫·BABIP 퍼짐)를 `reports/engine2-baseline.md`로. 검증 도구에 새 지표 자리 마련 | 보고서 생성. 결과 같음 |

| 단계 | 내용 | 검증 기준 |
|---|---|---|
| 20-1 | **구종 능력**: 투수 `arsenal` 채우기 (구종 비율 자료가 있으면 그것, 없으면 리그 평균 비율 임시값). 구종별 배율은 섞은 평균이 지금 능력과 같게 | 구종을 섞은 사슬의 끝 확률 = 지금 목표 (1e-9). 시즌 기록·B 결과 그대로 |
| 20-2 | **AI 포수 볼 배합**: 지시 없는 공의 구종을 카운트별 비율로 고름 (A에서만 보임) | 카운트별 구종 비율이 자료(있으면)와 맞음. 매치업 동등성 그대로 |
| 20-3 | **플레이어 구종·코스 지시**: 물음에 구종·코스 칸, 조작 기록 `pitch` 칸, 중계에 구종 표시 | 같은 지시 → 같은 결과 (재현). 지시 없는 경기의 동등성 그대로 |
| 20-4 | **구종 균형 점검**: 특정 구종·코스만 계속 고르면 너무 유리해지지 않는지 (같은 공 반복의 손해, 타자의 노림수) | 한 구종만 고르는 전략의 실점이 AI 배합보다 크게 좋지 않음 (측정 도구) |

5·6·16단계에 자료가 오지 않았으면 대안(5장)으로 진행하고, 자료가 오면 맞춤만 다시 한다.

## 7. 사용자가 정할 것

1. **화면 등급 50의 기준**: 리그 평균(배율 1.00, 추천) / 지금처럼 주전 평균.
2. **80 넘는 등급 표시**: ① 그대로 표시(추천) / ② "80+" / ③ 눈금 넓히기 (4.4).
3. **새 능력의 표시 방식**: 땅볼 성향·방향 성향을 등급(20~80)으로 할지 글("땅볼형")로 할지. 한계 투구 수를 등급 대신 "약 100구"로 보일지.
4. **수동 경기 미리보기·되돌리기**: 지금은 미리보기로 경기 끝까지 돌려 본 뒤 다른 선택을 할 수 있다 (결과 엿보기). 경기 중 저장이 생기면 한 번 진행한 공은 되돌리지 않게 할지(추천), 지금처럼 둘지.
5. **수동 경기에서 "자동으로 끝내기"의 기본**: ① A로 계속(추천, 분포 같음) / ② B로 전환(빠름). 둘 다 두고 기본만 정해도 된다.
6. **자동 진행 중 우리 경기에 끼어들기**(B → A, 위기 상황에서 멈춤)를 넣을지.
7. **수동 경기 작전 물음 시점** (지시 내용은 감독 작전만으로 정해짐): 타석 사이에만 물을지 / 주자가 있을 때 공 사이에도 물을지(도루 출발) / 화면의 "멈춤"을 누를 때만 공 사이에서 물을지. 히트앤드런·피치아웃·전진 수비를 1단계 감독 작전에 넣을지도 함께.
8. **예전 저장·조작 기록**: 예전 저장은 다음 경기부터 엔진 2로 이어 하기만 지원(추천) / 엔진 1 코드를 남겨 예전 조작 기록 재현도 지원.
9. **고의4구 시대 구분**: 자동 고의4구(공 없이) 도입 연도를 사용자가 확인해 줄지 (이 문서는 확인하지 못했다).
10. **홈 이점**: 연도별 실제 값(부드럽게 섞음, 추천) / 시대 묶음 값 / 0으로 두고 말 공격 이점만.
11. **연장·무승부 연표** (최대 이닝, 2021년 9이닝 무승부 등) 확인.
12. **하드힛 자료 받기**: 5장 표 중 어떤 표가 하드힛에 있는지 확인하고, 1·2순위부터 받을지.
13. **경기 중 부상**을 넣을지 (넣으면 실존 선수는 지금처럼 사유 없이 기간만).
14. **야수 체력(피로)** 능력을 넣을지.
15. **구종·코스 지시를 언제 시작할지** (나중 단계 20). 구속 표시는 자료가 없어 넣지 않는 것에 동의하는지.
