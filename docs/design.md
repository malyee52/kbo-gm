# KBO 단장 시뮬레이션 게임 기획서 v1.0

확정일: 2026-10-08
이전 버전: v0.1 (2026-10-08, 제안 항목 포함)

v0.1에서 제안으로 남아 있던 항목을 모두 확정했다. 이 문서의 내용은 전부 확정 사항이며, 수치 중 "임시값"으로 표시한 것은 구현하며 조정한다.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 플랫폼 | 웹 브라우저 (서버 없음) |
| 장르 | 야구 구단 운영 시뮬레이션 (단장 역할) |
| 리그 | KBO, 실제 선수와 팀 사용 |
| 성격 | 수익을 내지 않는 실험적 게임 |
| 진행 | 여러 해에 걸친 다년 운영 |
| 시작 연도 | 1982년 ~ 2026년 중 선택 (2026년부터 구현, 이후 과거로 확장) |

**한 줄 소개**: 원하는 연도의 KBO 구단을 맡아, 전면 드래프트로 바뀐 역사 속에서 팀을 여러 해에 걸쳐 키우는 단장 게임.

**핵심 재미**
- 누가 대성할지 아는 상태에서 역사를 다시 쓰는 것
- 알고 뽑아도 육성과 관리에 실패하면 무너지는 긴장

---

## 2. 플레이어 역할과 범위

- 플레이어는 단장이다. 선수단 구성과 예산을 다룬다.
- 경기 중 작전(타순, 투수 교체, 대타)은 AI 감독이 처리한다.
- 경기는 자동 시뮬레이션으로 진행하며 하루·일주일 단위로 넘길 수 있다.

---

## 3. 연간 사이클

1. **오프시즌**: FA 영입·잔류, 외국인 선수 계약, 신인 드래프트, 연봉 협상
2. **정규시즌**: 1군·2군 엔트리 조정, 트레이드, 부상 대응
3. **포스트시즌**
4. **결산**: 구단주 목표 달성 평가, 선수 성장 판정, 다음 해 예산 결정

시대에 따라 존재하지 않는 단계는 생략한다 (FA는 1999년 시즌 뒤부터, 외국인 선수는 1998년부터).

## 4. 시대와 리그 구조

### 4.1 구단 수와 제도
- 구단 수, 팀당 경기 수, 제도 도입 시점은 현실을 따른다. 값은 자료집의 "시즌구조"와 "제도연표" 시트를 기준으로 한다.
- **리그 방식은 단일 시즌으로 통일한다.** 전기·후기 리그(1982~1988)와 양대 리그(1999~2000)는 재현하지 않는다. 포스트시즌 진출 팀 수만 시대를 반영한다.
- 창단·매각·해체는 해당 연도의 고정 이벤트로 발생한다.
- 매각·인수 시 팀명과 예산만 바뀌고 선수단은 유지한다.
- **해체 구단은 후속 구단이 선수단을 승계한다.** 쌍방울(1999) → SK(2000), 현대(2007) → 히어로즈(2008). 플레이어가 맡은 구단이어도 같다.
- **신생팀 선수 수급은 NC 방식으로 통일한다.** 신인 드래프트 2명 우선 지명과 2라운드 뒤 5명 추가 지명(2년간), 기존 구단 보호선수 20명 외 1명씩 지명.
- 2027년 이후에는 2026년 제도를 그대로 유지한다. 샐러리캡만 2028년까지 발표된 인상률(연 5%)을 따르고 이후 같은 비율로 올린다.

### 4.2 주요 연혁 (출처 확인 완료)

| 연도 | 사건 |
|---|---|
| 1982 | 6구단 출범 (OB, 삼성, MBC, 해태, 롯데, 삼미) |
| 1986 | 빙그레 합류 (7구단) |
| 1991 | 쌍방울 합류 (8구단) |
| 1998 | 외국인 선수 제도 도입 |
| 1999 시즌 뒤 | FA 제도 도입 |
| 2000 | SK 창단 (쌍방울은 1999년이 마지막 시즌) |
| 2008 | 히어로즈 창단 (현대는 2007년이 마지막 시즌) |
| 2013 | NC 합류 (9구단) |
| 2015 | KT 합류 (10구단), 팀당 144경기 |
| 2023 | 샐러리캡 도입 |
| 2026 | 아시아쿼터 도입, 1군 엔트리 29명 |

## 5. 드래프트

- 과거 시즌의 드래프트 풀은 현실과 같다 (실제 입단 선수, 입단 연도 기준).
- 지명 방식은 전 시대 전면 드래프트로 통일한다. 지명 순서는 전년도 순위의 역순이다.
- 라운드 수는 11라운드로 통일한다.
- 육성선수 출신은 드래프트 종료 뒤 자유 영입 풀로 제공한다.
- 외국인 선수는 1998년부터 해당 연도에 실제로 온 선수들로 풀을 구성한다.
- **해외로 직행한 선수는 풀에 넣지 않는다.** KBO에 실제로 입단한 해에 풀에 나타난다.
- 2027년부터는 가상 신인을 생성한다.
- **2차 드래프트는 1차 버전에서 제외한다.** (확장 단계에서 추가)

## 6. 선수 능력과 성장

### 6.1 능력 모델
- 내부 값은 **타석 결과별 상대 비율**이다. 리그 평균이 1.00이고, 시대가 달라도 같은 엔진으로 계산한다.
  - 타자: 삼진, 볼넷, 사구, 홈런, 단타, 2루타, 3루타, 도루 시도
  - 투수: 삼진, 볼넷, 사구, 피홈런, 피안타(홈런 제외), 체력
- **시작 시점의 능력은 직전 3시즌 기록의 가중 평균에서 뽑는다** (가중 5:4:3, 최근이 큼). 그 해의 실제 성적은 미리 반영하지 않는다.
- 표본이 적을수록 사전 평균 쪽으로 회귀시킨다. 사전 평균은 리그 평균이 아니라 출전이 적은 선수들의 평균이다.
- 직전 기록이 없는 신인과 신규 외국인은 잠재력에서 초기 능력을 만든다. 잠재력 모델을 넣기 전(M5 이전)에는 데뷔 시즌 기록을 크게 회귀시킨 값을 임시로 쓴다.

### 6.2 화면 표시
- **능력치는 20~80 등급으로 환산해 보여준다.** 50이 리그 평균 주전, 10이 1 표준편차다.
  - 타자: 컨택, 파워, 선구안, 주력
  - 투수: 구위, 제구, 장타 억제, 체력
- 실제 기록(타율, 홈런 등)은 기록 화면에서 따로 본다.

### 6.3 잠재력과 성장
- 드래프트된 선수는 현실 커리어를 그대로 따르지 않는다. 실제 커리어는 잠재력으로만 쓴다.
- 잠재력의 변동 폭은 크지 않다. 실명에 대한 지식이 유효하다.
- 선수가 반드시 잠재력만큼 성장하지는 않는다.
- 잠재력은 실제 커리어 성적에서 산출한 전성기 상한이다. 1군 기록이 거의 없는 실제 지명자는 낮은 잠재력 범위에서 생성한다.
- 성장 판정은 매 오프시즌에 선수별로 한다. 입력은 잠재력과의 격차, 나이, 그 해 출전 기회, 소폭의 운이다.

### 6.4 성장을 꺾는 요소
- **부상**: 경미, 장기, 시즌아웃. 큰 부상은 잠재력을 깎는다. 투수는 이닝 혹사, 야수는 나이가 발생 확률을 높인다.
- **병역**: 복무 기간 공백과 복귀 후 감각 저하.
- **슬럼프와 조기 노쇠**
- **이탈 이벤트**: 7장 규칙을 따른다.

## 7. 실존 인물 표현 규칙

- **구체적 사건(스캔들)은 가상 선수에게만 발생한다.**
- 실존 선수에게는 사유를 특정하지 않는 중립 이벤트만 발생한다 ("개인 사정으로 이탈", "구단 내 갈등", "징계성 출전 정지").
- 실제 있었던 사건을 해당 선수에게 재현하지 않는다.
- 사용: 선수 이름, 공개된 기록. 미사용: 구단 로고·엠블럼·유니폼 디자인, 선수 사진·초상.
- 팀은 텍스트와 팀 컬러로 표현한다.
- 선수 데이터는 게임 코드와 분리하고, 가상 선수 데이터로 교체해도 게임이 돌아가게 한다.
- 데이터에 선수별 `real` 표시를 두고, 구체적 사건 이벤트는 이 값이 거짓인 선수에게만 걸리도록 자동 검사한다.

비수익이어도 권리 문제가 사라지는 것은 아니므로 공개 범위를 넓히기 전에 다시 검토한다 (M9).

## 8. 재정

- 1차 버전은 야구 예산(총연봉 한도)만 다룬다. 이후 상세형(관중 수입, 시설·스카우트·의료 투자)으로 확장한다.
- 연봉은 능력치, 나이, 연차, 시대별 물가 계수로 생성한다.
- 예산은 모기업 지원금(구단별 등급)과 성적 연동분으로 구성한다.
- 샐러리캡은 2023년부터 적용한다 (2026년 143억 9,723만 원).

### FA
- 자격 연한과 등급(A·B·C)은 현행 규정을 따른다.
- **보상은 보상금만 적용한다.** 보상선수 지명은 넣지 않는다. A등급 전년 연봉의 300%, B등급 200%, C등급 150%.

## 9. 구단주 평가와 목표

- 매년 팀 전력에 맞는 목표가 주어진다 (탈꼴찌, 가을야구 진출, 우승).
- 달성 여부에 따라 신뢰도가 오르내리고, 바닥나면 해고된다.
- 해고되면 하위권 구단의 영입 제의로 플레이를 이어간다.
- 정해진 엔딩은 없다. 통산 우승 횟수, 왕조 건설 같은 업적으로 장기 목표를 준다.

---

## 10. 트레이드와 AI 구단

- **선수 가치 함수**: 현재 능력, 나이를 반영한 잠재력, 연봉 부담, 포지션 희소성을 합친 점수. 트레이드, 드래프트, FA에 같은 함수를 쓴다.
- **구단 성향**: 순위와 선수단 연령에 따라 우승 도전 또는 리빌딩. 도전 구단은 즉시 전력을, 리빌딩 구단은 유망주를 높게 친다.
- **수락 규칙**: 받는 가치가 주는 가치보다 약간 커야 수락한다. 부족한 포지션을 채우는 제안에는 가산점을 준다.
- **난이도**: AI 구단의 잠재력 평가 정확도. 쉬움은 오차가 크고, 어려움은 거의 정확하다.

## 11. 경기 시뮬레이션 엔진

- 타석 단위로 결과를 확률로 정한다. 결과는 삼진, 볼넷, 사구, 홈런, 단타, 2루타, 3루타, 범타(땅볼·뜬공), 실책 출루다.
- 타자와 투수의 상대 비율을 그 시즌의 리그 평균과 결합한다 (승산비 방식). 과거 시즌은 그 해의 실제 리그 평균을, 2027년 이후는 최근 5시즌 평균을 쓴다.
- 주루, 병살, 희생플라이, 도루는 확률로 자동 처리한다.
- 보정 요소: 투수 피로, 좌우 상성, 홈 구장 이점.
- AI 감독이 타순, 선발 로테이션, 투수 교체, 주전 휴식을 정한다.
- **난수는 시드로 고정한다.** 같은 시드와 같은 입력이면 같은 결과가 나온다.
- 검증: 반복 시뮬레이션의 리그 평균(타율, 경기당 득점, 타석당 홈런·볼넷·삼진)을 실제 값과 비교한다.

## 12. 데이터

- 원자료: `KBO_단장게임_자료집.xlsx` (선수마스터, 타자시즌, 투수시즌, 시즌순위, 리그평균).
- 변환: `tools/build_data.py`가 엑셀을 읽어 `public/data/`의 JSON을 만든다. 엑셀을 고치고 다시 돌리면 게임 데이터가 갱신된다.
- 구조: 선수 마스터 1개 + 시즌별 파일(선수×시즌 기록, 구단, 리그 평균). 시작 연도별로 따로 만들지 않는다.
- 검증: `tools/validate_data.py`가 빈칸, 범위, 중복 ID, 구단별 인원을 검사한다.
- 실시간 연동 없이 고정된 JSON만 쓴다.

알려진 공백은 자료집의 "데이터공백" 시트에 정리돼 있다. 2026년 시작에 영향을 주는 것은 2026년 신규 선수의 세부 포지션 없음, 시즌 미종료 스냅샷, 수비 포지션별 기록 없음이다.

## 14. 기술 구조

- **React + TypeScript**, 빌드는 Vite, 테스트는 Vitest.
- 폴더:
  - `src/engine/` 경기 엔진. 화면과 브라우저에 의존하지 않는 순수 함수와 타입.
  - `src/data/` 데이터 타입과 로더.
  - `src/ui/` 화면.
  - `tools/` 데이터 변환·검증·시뮬 검증 스크립트.
  - `public/data/` 게임 데이터 JSON.
- 저장: 브라우저 저장소(IndexedDB)와 JSON 파일 내보내기·가져오기.
- 엔진은 화면 없이 Node에서 그대로 돌릴 수 있어야 한다. 검증 스크립트와 자동 테스트가 이를 이용한다.

## 16. 남은 확인 사항

결정이 아니라 조사가 필요한 항목이다.

- KBO 공식 사이트 이용약관. 자동 수집 도구로는 약관 페이지를 열 수 없었다 (사이트가 자동 접근을 막아 둠). 브라우저로 직접 확인해야 한다.
- 제도연표의 미확인 8건과 출처 간 차이 2건 (M8 전까지).
- 연도별 신인 지명 명단 (M8).
- 마일스톤별 목표 날짜.
