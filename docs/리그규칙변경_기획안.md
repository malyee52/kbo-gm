# 리그 규칙 변경과 개막 "올해 달라지는 규칙" 알림 기획안

> **초안 — 사용자 승인 전.** 코드는 고치지 않았다. 새 기능은 모두 "제안"이며 사용자가 허락하기 전에는 만들지 않는다.

작성 2026-10-22. 사용자 요청: "리그 시작 시 변경된 규칙과 공인구 반발계수 등의 수정사항이 나오는 걸 개발하고, 리그 수정사항은 뭐가 있을지도 기획해."

근거:
- 조사 결과 두 건 (잼쨩, 웹 조사, 2026-10-22): 리그 규칙·제도 연표 1982~2026과 공인구 반발계수 표, 고의4구·연장·무승부 연표. 이 문서에서 **"조사값"은 모두 "웹 조사(잼쨩), 제도연표로 확인 전"** 이다. 출처끼리 다른 곳은 "출처 갈림"으로 적었다.
- 자료집 엑셀 "제도연표" 시트 (읽기만). 여기서 "출처 확인"인 항목은 **자료집 확인**으로 적는다.
- 게임 코드: `src/league/eras.ts`, `src/engine/eras.ts`, `src/league/rules.ts`, `src/league/salary.ts`, `src/league/owner.ts`, `src/league/offseason.ts`, `src/league/postseason.ts`, `src/league/world.ts`, `src/engine/season.ts`, `src/game/session.ts`, `tools/build_data.py`의 `rules_for` (→ `public/data/meta.json`의 `rules`).
- 리그 기록: `public/data/seasons/*.json`, `data-src/pbp_derived/`, `data-src/hardhit_derived/`.
- 경기 엔진 2 기획안 (`docs/경기엔진2_기획안.md`) 0장·3.10절·6장.

## 0. 요약

- **게임과 값이 다른 제도가 꽤 있다.** 가장 큰 것: 연장 최대 이닝(1982~2002 15회인데 게임 12회, 2008 무제한), 승률 계산(무승부 처리가 네 번 바뀜, 게임은 늘 "무승부 제외"), 포스트시즌 시리즈 길이(게임은 모든 해에 지금 방식), 1군 엔트리(1982~2000 게임 26명, 실제 25명 이하)와 "등록·출장" 구분 없음, 외국인 출전 한도(2001~02·2014~19는 3명 보유·2명 출전인데 게임은 3명 모두 출전), 대졸 FA 연한(2001~2010), 2026년 샐러리캡 제재 완화와 프랜차이즈 예외. 목록은 1.2절.
- **경기 규칙(공인구·스트라이크존·ABS·베이스·시프트·피치클락)은 지금 게임에 하나도 없다.** 과거 연도는 환경 맞춤(그 해 실제 리그 평균에 맞춤)이 결과를 대신 맞춰 주므로 없어도 리그 평균은 맞는다. 미래 연도(2027~)는 2022~2026 평균 환경에 고정이다.
- **개막 알림 "올해 달라지는 규칙"** (2장): 오프시즌 "개막 준비" 단계에 미리 보기 카드, 개막일에 전용 창 한 번 + 소식 한 줄. 지난해와 달라진 항목을 분류별로, 수치 전후와 확인 상태(자료집 확인 / 조사값 / 출처 갈림 / 미확인)를 붙여 보여 준다. 공인구는 기준 범위와 **개막 전에 발표된 검사값만** 보여 주고, 시즌 중 검사는 그 날짜에 소식으로 낸다. 시작 연도에는 "출범(시작) 규칙 요약". 표시만 하는 기능이라 저장·조작 기록·재현에 주는 영향이 없다.
- **규칙이 경기에 닿는 방식** (3장): 항목마다 (a) 표시만 (b) 리그 운영 (c) 경기 엔진. (c)는 두 층으로 나눈다. **리그 평균 층**은 엔진 손잡이 대신 "환경 맞춤 목표값을 옮기는" 방식으로 넣고(과거 연도는 실제값이 목표라 이중 반영이 생기지 않는다), **모양 층**(누가 이득을 보나: 시프트 제한 → 당겨치는 좌타자, 공인구 → 뜬공 타자, 베이스 확대 → 빠른 주자)만 엔진 손잡이로 넣는다.
- **2027년 이후** (4장): 안 네 가지 — ① 바뀌지 않음(지금) ② 리그 흐름에 따라 바뀜(타고투저가 심하면 공인구 조정 등) ③ 무작위 제도 변화 ④ 단장 의견 이벤트(②·③ 위에 얹음). 추천은 **② + ④를 나중에**.
- 만드는 순서는 5장 (0~8단계). 엔진 2의 13단계(시대 규칙)·14단계(기록 규정)와 겹치는 곳을 표시했다.

## 2. 개막 알림 "올해 달라지는 규칙" (제안)

### 2.1 언제·어디에

| 때 | 어디에 | 내용 |
|---|---|---|
| 새 게임 시작 직후 (부임 소식과 같은 때) | **전용 창** 한 번 (닫으면 끝) + 소식 한 줄 | "시작 연도 규칙 요약" (2.4) + 그 해 바뀐 것 |
| 해마다 오프시즌 "개막 준비" 단계 (`off.stage === 'ready'`) | 오프시즌 화면의 카드 | 다음 시즌 "달라지는 규칙" 미리 보기 (FA·외국인·캡처럼 오프시즌 결정에 닿는 것이 먼저 보이게) |
| 시즌 시작 (개막일, `day 0`) | **전용 창** 한 번 + 소식 한 줄 ("2019 시즌: 달라지는 규칙 7가지 — 공인구 반발계수 기준 하향 외") | 2.2의 전체 목록 |
| 시즌 중 그 날짜 | 소식 (`news`, kind `season`) | 날짜가 있는 시즌 중 변화: 공인구 2·3차 검사 발표, 2014 후반기 합의 판정, 2021 후반기 연장 폐지, 2025 체크스윙 판독(8월 19일) |
| 언제든 | "리그" 메뉴 안 "규칙 연표" 쪽 | 지금 연도 규칙 전체 + 지난 해들의 변화 목록 (다시 보기) |

- 창은 자동 진행(하루·한 번에 진행) 중이면 띄우지 않고 소식만 남긴다 (진행을 막지 않게). 다음에 화면을 볼 때 "새 규칙 소식" 배지.
- 자동으로 넘기기 전용 설정("규칙 알림 창 띄우지 않기")은 브라우저 설정(localStorage)에만 두고 저장 파일에 넣지 않는다.

### 2.2 무엇을

- **지난해와 달라진 항목만** (시작 연도는 2.4). 분류 순서: ① 경기 규칙 ② 공인구 ③ 엔트리·외국인 ④ FA·드래프트·샐러리캡 ⑤ 리그 운영(구단·경기 수·포스트시즌). 분류마다 위에서 "게임에 반영됨"을 먼저, "표시만"을 뒤에.
- 항목 한 줄: **제목 · 전 → 후 · 게임 반영 표시 · 확인 상태**.
  - 게임 반영 표시: `경기에 반영` / `리그 운영에 반영` / `표시만 (게임에서는 그 해 리그 평균으로 반영)` / `표시만`.
  - 확인 상태 배지: `자료집 확인` / `조사값` / `출처 갈림` / `미확인`. 게임이 실제와 다르게 단순화한 값이면 `게임은 단순화: …`를 붙인다 (예: "1군 엔트리 29명 등록·27명 출장 — 게임은 29명 모두 출장 가능").
- **공인구 줄**: 기준 범위(바뀌었으면 전 → 후), 단일·복수 공인구, **개막 전에 발표된 검사 평균만** ("1차 수시검사 평균 0.4093, 3월 30일 발표, 지난해 1차 0.4123"). 개막 뒤에 나온 2·3차 값은 그 날짜 소식으로 낸다 — 개막 때 그 해 뒤쪽 정보를 미리 보이지 않게 (원칙 "그 해 성적을 미리 반영하지 않는다"와 같은 결). 1982~1998처럼 공표가 없던 해는 "검사 결과 공표 없음".
- **수치가 게임 값과 같은 출처에서 나오게**: 리그 운영(b) 항목(엔트리·외국인·FA 연한·캡·연장)은 문구용 JSON에 값을 따로 적지 않고 게임이 실제로 쓰는 값(`meta.rules`, `foreignRule`, `faServiceNeeded`, `salaryCap` 등)을 전해·올해로 불러 비교해 만든다. 그래야 알림과 실제 규칙이 어긋나지 않는다. JSON에는 그 항목의 설명·출처·확인 상태만.
- 지난해 대비 바뀐 리그 기록은 넣지 않는다 (개막 시점에 그 해 성적은 모른다). 대신 "지난 시즌 리그: 경기당 홈런 ○개, 경기당 득점 ○점"(게임 안 지난 시즌 값) 같은 직전 시즌 요약 한 줄은 넣을 수 있다 (게임 안 시즌 결과라 미리 보기 아님).

### 2.3 데이터 형식 (제안)

원자료 `data-src/규칙변경.csv` (사용자가 엑셀처럼 고친다, UTF-8 BOM) → `python tools/build_data.py --rules-only` → `public/data/rule_changes.json`.
`--traits-only`·`--military-only`처럼 이것만 다시 만들 수 있게 하고, 선수 월드 지문(`rosterFingerprint`)에 들어가지 않으므로 **데이터를 고쳐도 예전 저장을 그대로 쓴다.**

CSV 열: `연도, 날짜(선택, MM-DD), 분류, 키(선택), 제목, 전, 후, 단위, 반영, 확인, 출처, 비고`

```json
{
  "version": 1,
  "items": [
    { "year": 2019, "cat": "ball", "title": "공인구 반발계수 기준 하향", "before": "0.4134~0.4374", "after": "0.4034~0.4234",
      "effect": "show-env", "status": "research", "source": "스포티비뉴스 2018-12-21" },
    { "year": 2026, "cat": "roster", "key": "rosterSize", "title": "1군 엔트리 확대",
      "effect": "league", "status": "confirmed", "simplified": "게임은 등록 인원 모두 출장 가능" },
    { "year": 2025, "date": "08-19", "cat": "game", "title": "체크스윙 비디오 판독 도입", "effect": "show", "status": "research" }
  ],
  "ball": [
    { "year": 2026, "range": [0.4034, 0.4234], "single": true,
      "tests": [{ "round": 1, "date": "03-30", "avg": 0.4093, "max": 0.4113 }], "status": "research" }
  ]
}
```

- `key`가 있으면 전·후 값은 게임 값에서 계산하고 `before`·`after`를 쓰지 않는다 (2.2).
- `effect`: `show`(표시만) / `show-env`(표시만, 환경 맞춤으로 결과에 녹음) / `league`(리그 운영에 반영) / `engine`(경기 엔진에 반영, 3장 만든 뒤).
- `status`: `confirmed`(자료집 확인) / `research`(조사값) / `conflict`(출처 갈림) / `unknown`(미확인). 자료집 "제도연표"에서 확인하면 CSV의 `확인` 열만 고친다.
- 실존 선수 이름은 넣지 않는다 (규칙 문구에 선수 사건이 들어가지 않게. "LG가 처음 캡 초과"처럼 구단 이름까지만).
- 2027년 이후 변화(4장)는 이 파일이 아니라 리그 상태(`LeagueState`)에 쌓인다. 알림은 두 곳을 합쳐 만든다.

### 2.4 시작 연도 요약 ("출범 규칙 요약")

1982 시작 판의 첫 해는 바뀐 것이 없으므로 "출범 규칙 요약"을 보여 준다. 다른 시작 연도도 첫 해는 "○○년 리그 규칙" 요약 + 그 해 바뀐 것.

1982 요약 초안 (내용은 조사값, 게임 값과 다른 곳은 그대로 밝힌다):
- 6구단, 팀당 80경기. 실제는 전·후기 리그였고 게임은 단일 시즌으로 진행.
- 지명타자 전 구단. 정식 경기 5이닝. 연장 — 실제 15회, 게임 값(지금 12회, D1을 고치면 15회).
- 외국인 선수 없음 (1998년 도입). FA 없음 (1999년 시즌 뒤 도입). 샐러리캡 없음 (2023년 도입).

## 3. 규칙이 경기에 닿는 방식

### 3.1 지금 구조와 이중 반영 문제

- 엔진은 시즌을 열 때 사건별 계수(cal)를 구해 리그 비율(단타·2루타·3루타·홈런·볼넷·사구·삼진)을 **그 해 실제 리그 평균**에 맞춘다 (`season.ts` `calibrate`, 엔진 2 기획안 P11). 공인구·스트라이크존·마운드의 효과는 이미 그 해 평균 안에 들어 있다.
- 미래(2027~)는 2022~2026 다섯 시즌 평균이 목표다 (`world.ts` `projectedEnvironment`). 해마다 같다.
- 그래서 과거 연도에 "공인구 반발계수 → 홈런 배율" 손잡이를 엔진에 더하면 맞춤이 그만큼 계수를 되돌려 **리그 평균에는 효과가 없다**(맞춤이 손잡이 뒤에 돈다면). 반대로 맞춤 앞에서 계수를 고정한 채 손잡이를 더하면 **두 번 반영**된다. 둘 다 원하는 결과가 아니다.

**제안 원칙: 두 층으로 나눈다.**

| 층 | 무엇 | 어떻게 넣나 | 과거 연도 | 미래 연도 |
|---|---|---|---|---|
| 리그 평균 층 | 리그 전체 홈런·볼넷·삼진·도루·인플레이 안타 비율이 얼마나 움직이나 | **엔진 손잡이가 아니라 환경 맞춤의 목표값을 옮긴다**: 목표 = 기준 환경 × 규칙 효과 배율의 곱 | 목표가 실제값이므로 배율을 곱하지 않는다 (이미 들어 있음). 이중 반영 없음 | 기준(2022~2026 평균) × 2027년 이후 바뀐 규칙의 배율 |
| 모양 층 | 같은 규칙에서 누가 이득·손해를 보나 (선수 사이 분배) | 엔진 손잡이 (엔진 2의 타구·주루 모형) | 손잡이를 켜고 맞춤이 리그 평균을 다시 맞춘다 → 평균은 그대로, 분배만 바뀐다 | 같음 |

- 리그 평균에 없는 것(경기 시간, 투구 수, 투수 피로, 무승부 비율, 엔트리 운영)은 맞춤 대상이 아니므로 손잡이가 그대로 효과를 낸다. 이런 것은 해당 해의 실제 기록(투구 단위 자료 2023~)으로 직접 검증한다.
- 미래 연도의 목표값을 옮기는 방식은 엔진을 건드리지 않아 엔진 2와 따로 만들 수 있다 (5장 4단계).

### 3.3 효과 크기 재는 법 (공통)

1. 바뀐 해 Y와 앞 해 Y-1의 리그 값 차이를 낸다 (시즌 자료, 2015~는 하드힛 월별 표, 2023~는 투구 단위).
2. 같은 해에 다른 변화가 겹치면(2024: ABS·베이스·시프트·피치클락 시범·공인구) 하나로 나누지 않고 **"그 해 변화 묶음"의 효과**로 적는다. 나눌 근거 없이 나누면 임시값이 된다.
3. 시즌 중 바뀐 것(2018 후반기 공인구, 2014 후반기 합의 판정)은 월별 표로 전후를 본다.
4. 해마다 표본 오차가 있으므로(득점 ±2% 안팎) 효과가 그보다 작으면 (a) 표시만으로 내린다.
5. 값은 `params.ts`에 모으고 근거 없이 정한 값은 "임시값"이라고 적는다. 표(`reports/rule-effects.md`)로 남긴다.

| ② 리그 흐름에 따라 바뀜 | 해마다 결산 때 게임 안 리그 기록을 본다. 정해 둔 범위를 벗어나면(예: 경기당 득점이 기준보다 10% 넘게 높은 해가 2년 이어짐) 위원회가 다음 시즌 규칙을 바꾼다 — 공인구 기준 조정, 존 조정, 엔트리·외국인 한도, 캡 증가율. 바꾸는 폭과 방향은 표로 정하고(임시값), 무엇을 고를지는 시드 난수로 | 높음: 리그가 살아 있는 느낌, "타고투저 시대"·"투고타저 시대"가 생긴다. 단장은 다음 해 규칙을 보고 선수 구성을 바꿀 이유가 생긴다 | 중간: 판정 규칙 + 3.1 목표값 층 (엔진 손잡이 없이 가능) + 알림 | 결정적: 결산 시점의 리그 기록(이미 재현됨) + `Rng`(시드 + 연도) → 같은 시드는 같은 변화. 저장: 리그 상태에 변화 기록(연도, 키, 전, 후, 이유)을 더한다 (선택 항목이라 예전 저장도 열림) |
| ③ 무작위 제도 변화 | 리그 흐름과 무관하게 몇 년에 한 번 제도 하나가 바뀐다 (엔트리 +1, 외국인 한도, 연장 이닝, 캡 증가율 등) | 중간: 놀라움은 있지만 이유가 없어 "왜?"가 남는다 | 작음 | ②와 같음 (`Rng`만) |
| ④ 단장 의견 이벤트 | ②·③에서 바뀔 후보가 생기면 개막 전에 "단장 회의" 이벤트: 안 두세 개 중 하나에 표를 던진다. AI 구단은 자기 전력에 유리한 쪽에 던지고(타선이 강한 구단은 공인구 하향 반대 등), 다수안이 채택된다 | 높음: 단장 게임다운 결정. 다만 내 표 하나로 결과가 거의 정해지면 악용(우리에게 유리한 규칙만 고르기) | 큼: 이벤트 화면, AI 표 계산(`src/ai/value.ts` 전력 비교), 조작 기록 | 플레이어 표는 **새 조작 기록**(`{ year, type: 'rule-vote', choice }`)으로 `dispatchOff`를 거친다 → 재현 유지. AI 표는 난수 없이 결정적 |

**추천: ②를 먼저, ④는 ②가 자리 잡은 뒤.**
- ②는 엔진 2를 기다리지 않고 3.1의 목표값 층만으로 만든다. 공인구처럼 리그 평균을 움직이는 변화가 대부분이라 엔진 손잡이가 없어도 결과가 바뀐다.
- 바꿀 수 있는 항목은 처음에 **공인구 기준(홈런 목표), 존(볼넷·삼진 목표), 연장 이닝, 1군 엔트리, 외국인 한도, 캡 증가율** 정도로 좁힌다. 각 항목의 폭은 실제 연표에서 본 크기 안 (예: 공인구 기준을 한 번에 0.01 안쪽).
- 화면 문구는 게임이 만든 가상 사건임을 밝힌다 ("2031 시즌 규칙 변경 (게임 속 가상 결정)"). 실존 인물·실제 기사 문구를 쓰지 않는다.
- 다른 게임의 규칙·이름·수치를 옮기지 않는다. 변화 항목과 폭은 KBO 연표에서 실제로 있었던 종류 안에서 정한다.
- 판정 범위·확률·폭은 모두 임시값으로 시작해 장기 진행 도구(`tools/longsim.ts`)로 50시즌에서 규칙이 몇 번 바뀌는지, 리그 득점이 범위 안에 머무는지 본다.

## 6. 사용자가 정할 것

1. **연표 확인**: 1.2의 "조사값" 항목을 자료집 "제도연표"에 옮겨 확인할지, 확인 전에는 알림에 "조사값" 배지로 보여도 되는지.
2. **알림 범위**: (a) 표시만 항목(비디오 판독·3피트·이물질 검사 등)까지 다 보일지, 게임에 반영되는 것과 공인구만 보일지.
3. **알림 위치**: 개막일 전용 창 + 오프시즌 카드 + 소식(추천) / 소식만 / 전용 창만.
4. **공인구 검사값을 개막 때 어디까지 보일지**: 개막 전 발표만 보이고 시즌 중 검사는 그 날짜 소식으로(추천) / 그 해 값 모두 개막 때.
5. **값이 다른 리그 운영 규칙(D13~D29) 중 무엇을 실제대로 바꿀지**. 특히 ① 1군 등록·출장 구분과 확대 엔트리 ② 외국인 출전 한도(2001~02·2014~19) ③ 2026년 캡 제재 완화·프랜차이즈 예외·2027 하한 ④ 대졸 FA 연한(2001~2010) ⑤ 1999~2019 FA 보상(등급제 이전).
6. **기록 규정(D1~D12)**: 연장 15회 시대·2008 무제한·2021 후반기 9회, 승률 계산 변화, 포스트시즌 방식(1986~88 플레이오프, 1993~2000 승차 제한, 시리즈 길이)을 실제대로 넣을지. 1986~1988 플레이오프는 전·후기 리그가 없는 게임에서 "몇 위까지"로 바꿔야 한다 (안: 4팀).
7. **경기 규칙을 엔진에 넣을지**: 3.2의 추천(공인구·ABS·베이스·시프트 제한만 모양 층, 피치클락·견제는 표시만)대로 갈지.
8. **미래 규칙 변화 안**: ① 바뀌지 않음 / ② 리그 흐름(추천) / ③ 무작위 / ④ 단장 의견 이벤트(②·③ 위에). ②를 고르면 바꿀 수 있는 항목 목록(4장 추천 여섯 가지)과 한 해에 바뀌는 최대 개수.
9. **미래 환경 기준**: 지금 2022~2026 평균에 고정. ②를 고르지 않아도 "리그 평균이 해마다 조금씩 떠도는" 방식이 필요한지 (안 고르면 그대로).
