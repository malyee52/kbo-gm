# 리그 규칙 변경과 개막 "올해 달라지는 규칙" 알림 기획안

> **v1 — 결정 반영 (2026-10-22).** 6장의 결정 9개는 클사장이 정함 (사용자 위임, 2026-10-22). 코드는 아직 고치지 않았다. 5장 "1차 개발 묶음"부터 개발 카드로 만든다. 미래 규칙 ④(단장 투표 이벤트)는 ②가 자리 잡은 뒤 따로 허락을 받고 만든다. 6.2절의 남은 결정은 해당 단계 전에 정한다.

작성 2026-10-22 (초안 커밋 7ed3d23), 같은 날 결정 반영. 사용자 요청: "리그 시작 시 변경된 규칙과 공인구 반발계수 등의 수정사항이 나오는 걸 개발하고, 리그 수정사항은 뭐가 있을지도 기획해."

근거:
- 조사 결과 두 건 (잼쨩, 웹 조사, 2026-10-22): 리그 규칙·제도 연표 1982~2026과 공인구 반발계수 표, 고의4구·연장·무승부 연표. 이 문서에서 **"조사값"은 모두 "웹 조사(잼쨩), 제도연표로 확인 전"** 이다. 출처끼리 다른 곳은 "출처 갈림"으로 적었다.
- 자료집 엑셀 "제도연표" 시트 (읽기만). 여기서 "출처 확인"인 항목은 **자료집 확인**으로 적는다.
- 게임 코드: `src/league/eras.ts`, `src/engine/eras.ts`, `src/league/rules.ts`, `src/league/salary.ts`, `src/league/owner.ts`, `src/league/offseason.ts`, `src/league/postseason.ts`, `src/league/world.ts`, `src/engine/season.ts`, `src/game/session.ts`, `tools/build_data.py`의 `rules_for` (→ `public/data/meta.json`의 `rules`).
- 리그 기록: `public/data/seasons/*.json`, `data-src/pbp_derived/`, `data-src/hardhit_derived/`.
- 경기 엔진 2 기획안 (`docs/경기엔진2_기획안.md`) 0장·3.10절·6장.

## 0. 요약

- **게임과 값이 다른 제도가 꽤 있다.** 가장 큰 것: 연장 최대 이닝(1982~2002 15회인데 게임 12회. 2008 무제한은 main에서 고침), 승률 계산(무승부 처리가 네 번 바뀜, 게임은 늘 "무승부 제외"), 포스트시즌 시리즈 길이(게임은 모든 해에 지금 방식), 1군 엔트리(1982~2000 게임 26명, 실제 25명 이하)와 "등록·출장" 구분 없음, 외국인 출전 한도(2001~02·2014~19는 3명 보유·2명 출전인데 게임은 3명 모두 출전), 대졸 FA 연한(2001~2010), 2026년 샐러리캡 제재 완화와 프랜차이즈 예외. 목록은 1.2절.
- **경기 규칙(공인구·스트라이크존·ABS·베이스·시프트·피치클락)은 지금 게임에 하나도 없다.** 과거 연도는 환경 맞춤(그 해 실제 리그 평균에 맞춤)이 결과를 대신 맞춰 주므로 없어도 리그 평균은 맞는다. 미래 연도(2027~)는 2022~2026 평균 환경에 고정이다.
- **개막 알림 "올해 달라지는 규칙"** (2장, 결정 1~4): 개막일 전용 창 한 번 + 오프시즌 "개막 준비" 카드 + 소식 한 줄 (자동 진행 중에는 소식만). 위에는 게임에 반영되는 규칙과 공인구, 아래에는 표시만 하는 항목 전부를 "그 밖의 변경" 접힌 목록으로. 제도연표로 확인되기 전 값은 **"조사값" 배지**를 붙여 그대로 보인다. 공인구는 기준 범위와 **개막 전에 발표된 검사값만** 개막 때, 시즌 중 2·3차 검사는 그 날짜 소식으로. 시작 연도에는 "출범(시작) 규칙 요약". 표시만 하는 기능이라 저장 형식·조작 기록·재현에 주는 영향이 없다.
- **실제와 다른 운영 규칙은 모두 실제대로 고친다** (결정 5·6, 사용자 방침 "현실과 똑같이"). 외국인 출전 한도·2026 캡 제도·2001~2010 대졸 FA·등급제 이전 FA 보상은 개막 알림과 같은 **1차 개발 묶음**, 1군 등록·출장 구분과 확대 엔트리는 **엔진 2 13단계**, 기록 규정(연장·무승부·승률·포스트시즌)은 **엔진 2 14단계**. 1986~1988 플레이오프는 "4팀"으로.
- **규칙이 경기에 닿는 방식** (3장, 결정 7): 항목마다 (a) 표시만 (b) 리그 운영 (c) 경기 엔진. (c)는 두 층. **리그 평균 층**은 엔진 손잡이 대신 "환경 맞춤 목표값을 옮기는" 방식(과거 연도는 실제값이 목표라 이중 반영이 없다), **모양 층**은 공인구·ABS·베이스 확대·시프트 제한만 엔진 손잡이로. 피치클락·견제·마운드·비디오 판독은 표시만.
- **2027년 이후** (4장, 결정 8·9): **② 리그 흐름에 따라 바뀜**을 먼저 만든다. 바꿀 수 있는 항목 6가지(공인구 기준, 존, 연장 이닝, 1군 엔트리, 외국인 한도, 캡 증가율), 한 해에 최대 1개 (임시값). 리그 환경은 2022~2026 평균에 고정하고 ②의 변화만 얹는다. ④ 단장 투표 이벤트는 나중(따로 허락). 환경 맞춤 때문에 게임 안 리그 득점은 늘 목표에 붙어 있어서, ②의 판정 신호는 4.2절처럼 잡는다 (6.2절 남은 결정 1).
- 만드는 순서는 5장: **1차 개발 묶음** 8단계(1-1~1-8)와 엔진 2 13·14단계로 넘기는 일.

## 2. 개막 알림 "올해 달라지는 규칙" (결정 1~4)

### 2.1 언제·어디에 (결정 3)

| 때 | 어디에 | 내용 |
|---|---|---|
| 새 게임 시작 직후 (부임 소식과 같은 때) | **전용 창** 한 번 (닫으면 끝) + 소식 한 줄 | "시작 연도 규칙 요약" (2.4) + 그 해 바뀐 것 |
| 해마다 오프시즌 "개막 준비" 단계 (`off.stage === 'ready'`) | 오프시즌 화면의 카드 | 다음 시즌 "달라지는 규칙" 미리 보기 (FA·외국인·캡처럼 오프시즌 결정에 닿는 것이 먼저 보이게) |
| 시즌 시작 (개막일, `day 0`) | **전용 창** 한 번 + 소식 한 줄 ("2019 시즌: 달라지는 규칙 7가지 — 공인구 반발계수 기준 하향 외") | 2.2의 전체 목록 |

- 자동 진행(하루·한 번에 진행) 중에는 창을 띄우지 않고 소식만 남긴다 (진행을 막지 않게). 다음에 화면을 볼 때 "새 규칙 소식" 배지.
- "규칙 알림 창 띄우지 않기" 설정은 브라우저 설정(localStorage)에만 두고 저장 파일에 넣지 않는다.

### 2.2 무엇을 (결정 1·2·4)

- **지난해와 달라진 항목만** (시작 연도는 2.4).
- **두 칸으로 나눈다** (결정 2):
  1. **위 — 게임에 반영되는 규칙과 공인구** (늘 펼침). 분류 순서: ① 공인구 ② 경기 규칙 중 엔진 반영(3장 모양 층이 생긴 뒤) ③ 엔트리·외국인 ④ FA·드래프트·샐러리캡 ⑤ 리그 운영(구단·경기 수·연장·포스트시즌).
  2. **아래 — "그 밖의 변경 (N가지)"** 접힌 목록. 표시만 하는 항목(비디오 판독, 3피트, 피치클락, 견제, 마운드, 홈 충돌, 슬라이딩, 이물질 검사, 배트, 파울라인 등)을 **빠짐없이 전부** 넣는다. 펼치면 위와 같은 한 줄 모양.
- 항목 한 줄: **제목 · 전 → 후 · 게임 반영 표시 · 확인 상태**.
  - 게임 반영 표시: `경기에 반영` / `리그 운영에 반영` / `표시만 (게임에서는 그 해 리그 평균으로 반영)` / `표시만`.
  - 확인 상태 배지 (결정 1): `자료집 확인` / `조사값` / `출처 갈림` / `미확인`. 제도연표로 확인되기 전 값은 숨기지 않고 `조사값` 배지를 붙여 보인다. 배지 위에 마우스(모바일은 누르기)로 "웹 조사 값, 자료집 제도연표 확인 전" 설명.
  - 게임이 실제와 다르게 단순화한 값이면 `게임은 단순화: …`를 붙인다. 예: 엔진 2 13단계 전까지 "1군 엔트리 29명 등록·27명 출장 — 게임은 29명 모두 출장 가능". 그 단계가 끝나면 문구를 지운다 (데이터 CSV의 `비고`만 고침).
- **공인구 줄** (결정 4): 기준 범위(바뀌었으면 전 → 후), 단일·복수 공인구, **개막일 이전 날짜로 발표된 검사 평균만** ("1차 수시검사 평균 0.4093, 3월 30일 발표, 지난해 1차 0.4123"). 개막 뒤 날짜의 2·3차 값은 그 날짜 소식으로 낸다 — 개막 때 그 해 뒤쪽 정보를 미리 보이지 않게 ("그 해 성적을 미리 반영하지 않는다"와 같은 결). 발표일을 모르는 검사값은 시즌 끝(결산) 소식으로 미룬다. 1982~1998처럼 공표가 없던 해는 "검사 결과 공표 없음".
- **수치가 게임 값과 같은 출처에서 나오게**: 리그 운영(b) 항목(엔트리·외국인·FA 연한·캡·연장)은 문구용 JSON에 값을 따로 적지 않고 게임이 실제로 쓰는 값(`meta.rules`, `foreignRule`, `faServiceNeeded`, `salaryCap` 등)을 전해·올해로 불러 비교해 만든다. 그래야 1차 묶음에서 규칙 값을 고치면 알림도 같이 바뀌고, 알림과 실제 규칙이 어긋나지 않는다. JSON에는 그 항목의 설명·출처·확인 상태만.
- 지난해 대비 바뀐 리그 기록은 넣지 않는다 (개막 시점에 그 해 성적은 모른다). 대신 "지난 시즌 리그: 경기당 홈런 ○개, 경기당 득점 ○점"(게임 안 지난 시즌 값) 직전 시즌 요약 한 줄은 넣는다 (게임 안 시즌 결과라 미리 보기 아님).

### 2.3 데이터 형식

원자료 `data-src/규칙변경.csv` (사용자가 엑셀처럼 고친다, UTF-8 BOM) → `python tools/build_data.py --rules-only` → `public/data/rule_changes.json`.
`--traits-only`·`--military-only`처럼 이것만 다시 만들 수 있게 하고, 선수 월드 지문(`rosterFingerprint` = 선수 ID·소속만)에 들어가지 않으므로 **데이터를 고쳐도 예전 저장을 그대로 쓴다.**

CSV 열: `연도, 날짜(선택, MM-DD), 분류, 키(선택), 제목, 전, 후, 단위, 반영, 확인, 출처, 비고`

```json
{
  "version": 1,
  "items": [
    { "year": 2019, "cat": "ball", "title": "공인구 반발계수 기준 하향", "before": "0.4134~0.4374", "after": "0.4034~0.4234",
      "effect": "show-env", "status": "research", "source": "스포티비뉴스 2018-12-21" },
    { "year": 2026, "cat": "roster", "key": "rosterSize", "title": "1군 엔트리 확대",
      "effect": "league", "status": "confirmed", "simplified": "게임은 등록 인원 모두 출장 가능" },
    { "year": 2025, "date": "08-19", "cat": "game", "title": "체크스윙 비디오 판독 도입", "effect": "show", "status": "research" }
  ],
  "ball": [
    { "year": 2026, "range": [0.4034, 0.4234], "single": true,
      "tests": [{ "round": 1, "date": "03-30", "avg": 0.4093, "max": 0.4113 }], "status": "research" }
  ]
}
```

- `key`가 있으면 전·후 값은 게임 값에서 계산하고 `before`·`after`를 쓰지 않는다 (2.2).
- `effect`: `show`(표시만 → "그 밖의 변경") / `show-env`(표시만, 환경 맞춤으로 결과에 녹음 → "그 밖의 변경". 단 `cat: "ball"`은 위 칸) / `league`(리그 운영에 반영 → 위 칸) / `engine`(경기 엔진에 반영 → 위 칸, 3장 모양 층이 생긴 뒤).
- `status`: `confirmed`(자료집 확인) / `research`(조사값) / `conflict`(출처 갈림) / `unknown`(미확인). 엔진 2 14단계에서 제도연표로 옮겨 확인하면 CSV의 `확인` 열만 고친다.
- 실존 선수 이름은 넣지 않는다 (규칙 문구에 선수 사건이 들어가지 않게. "LG가 처음 캡 초과"처럼 구단 이름까지만). 검사 스크립트가 선수 이름 목록과 대조한다.
- 2027년 이후 변화(4장 ②)는 이 파일이 아니라 리그 상태(`LeagueState.ruleShifts`)에 쌓인다. 알림은 두 곳을 합쳐 만든다.

### 2.6 저장·조작 기록·재현

- 알림은 (데이터 파일 + 연도 + 게임 규칙 값 + `ruleShifts`)만으로 다시 계산하는 **표시 기능**이다. 새 `GameAction`이 없고, 난수를 쓰지 않으며, 저장 형식을 바꾸지 않는다. 같은 저장을 열면 같은 알림이 나온다.
- 소식(`news`)에 남는 한 줄은 기존 소식처럼 저장에 들어간다. 데이터 파일을 고쳐 문구가 바뀌어도 이미 남은 소식은 그대로다 (예전 문구). 시즌 중 날짜 소식은 진행 순서 안에서 날짜로만 정해지므로 저장 뒤 이어 돌린 결과와 끊김 없이 돌린 결과가 같아야 한다 (`tests/game.test.ts`).
- "창을 봤는가"는 저장하지 않는다 (불러오면 그 시즌 창을 다시 볼 수 있다). 브라우저 설정의 "띄우지 않기"만 따로.

## 3. 규칙이 경기에 닿는 방식 (결정 7·9)

### 3.1 지금 구조와 이중 반영 문제

- 엔진은 시즌을 열 때 사건별 계수(cal)를 구해 리그 비율(단타·2루타·3루타·홈런·볼넷·사구·삼진)을 **그 해 실제 리그 평균**에 맞춘다 (`season.ts` `calibrate`, 엔진 2 기획안 P11). 공인구·스트라이크존·마운드의 효과는 이미 그 해 평균 안에 들어 있다.
- 미래(2027~)는 2022~2026 다섯 시즌 평균이 목표다 (`world.ts` `projectedEnvironment`). 해마다 같다. 맞춤은 해마다 그 시즌 선수로 다시 돌므로 **게임 안 리그 비율은 늘 목표에 붙는다** (4.2절에서 중요).
- 그래서 과거 연도에 "공인구 반발계수 → 홈런 배율" 손잡이를 엔진에 더하면 맞춤이 그만큼 계수를 되돌려 **리그 평균에는 효과가 없다**. 반대로 맞춤 앞에서 계수를 고정한 채 손잡이를 더하면 **두 번 반영**된다.

**원칙: 두 층으로 나눈다.**

| 층 | 무엇 | 어떻게 넣나 | 과거 연도 | 미래 연도 |
|---|---|---|---|---|
| 리그 평균 층 | 리그 전체 홈런·볼넷·삼진·도루·인플레이 안타 비율이 얼마나 움직이나 | **엔진 손잡이가 아니라 환경 맞춤의 목표값을 옮긴다**: 목표 = 기준 환경 × 규칙 배율의 곱 | 목표가 실제값이므로 배율 1 (이미 들어 있음). 이중 반영 없음 | 기준(2022~2026 평균에 고정, 결정 9) × 4장 ②로 바뀐 규칙의 배율. 그 밖에 떠도는 변화는 넣지 않는다 |
| 모양 층 | 같은 규칙에서 누가 이득·손해를 보나 (선수 사이 분배) | 엔진 손잡이 (엔진 2의 타구·주루 모형) | 손잡이를 켜고 맞춤이 리그 평균을 다시 맞춘다 → 평균은 그대로, 분배만 바뀐다 | 같음 |

- 리그 평균에 없는 것(경기 시간, 투구 수, 투수 피로, 무승부 비율, 엔트리 운영)은 맞춤 대상이 아니므로 손잡이가 그대로 효과를 낸다. 이런 것은 해당 해의 실제 기록(투구 단위 자료 2023~)으로 직접 검증한다.
- 미래 연도의 목표값 층은 엔진을 건드리지 않아 엔진 2와 따로 만든다 (1차 묶음 1-8).

### 3.3 효과 크기 재는 법 (공통)

1. 바뀐 해 Y와 앞 해 Y-1의 리그 값 차이를 낸다 (시즌 자료, 2015~는 하드힛 월별 표, 2023~는 투구 단위).
2. 같은 해에 다른 변화가 겹치면(2024: ABS·베이스·시프트·피치클락 시범·공인구) 하나로 나누지 않고 **"그 해 변화 묶음"의 효과**로 적는다. 나눌 근거 없이 나누면 임시값이 된다.
3. 시즌 중 바뀐 것(2018 후반기 공인구, 2014 후반기 합의 판정)은 월별 표로 전후를 본다.
4. 해마다 표본 오차가 있으므로(득점 ±2% 안팎) 효과가 그보다 작으면 (a) 표시만으로 내린다.
5. 값은 `params.ts`에 모으고 근거 없이 정한 값은 "임시값"이라고 적는다. 표(`reports/rule-effects.md`)로 남긴다.

## 4. 2027년 이후 미래의 규칙 변경 (결정 8·9)

### 4.1 결정

- **② 리그 흐름에 따라 바뀜**을 먼저 만든다 (1차 묶음 1-8). ① 바뀌지 않음은 ②를 끈 상태와 같다. ③ 무작위 제도 변화는 넣지 않는다.
- **④ 단장 투표 이벤트는 나중**: ②가 자리 잡은 뒤 따로 허락을 받는다. 그때 설계(플레이어 표는 새 조작 `{ year, type: 'rule-vote', choice }`로 `dispatchOff`를 거침, AI 표는 난수 없이 전력 비교로 결정적, 내 표 하나로 결과가 정해지는 악용 막기)는 초안 4장 표(커밋 7ed3d23)를 다시 본다.
- 바꿀 수 있는 항목은 6가지: **공인구 기준, 존, 연장 이닝, 1군 엔트리, 외국인 한도, 캡 증가율.** 한 해에 최대 1개 (임시값).
- **미래 환경은 2022~2026 평균에 고정**하고 ②의 변화(목표 배율)만 얹는다. 해마다 따로 떠도는 변화는 넣지 않는다 (결정 9).
- 적용 범위: 기본 모드만. 자유 모드는 AI 게임 마스터가 `league.rules`를 바꾸는 장치가 이미 있어서 ②를 끈다 (6.2절 남은 결정 4에서 확인).
- 화면 문구는 게임이 만든 가상 결정임을 밝힌다 ("2031 시즌 규칙 변경 (게임 속 가상 결정)"). 실존 인물·실제 기사 문구를 쓰지 않는다. 다른 게임의 규칙·이름·수치를 옮기지 않고, 변화 항목과 폭은 KBO 연표에서 실제로 있었던 종류 안에서 정한다.

### 4.2 판정 신호 (환경 맞춤과 부딪치는 곳)

3.1처럼 미래 연도도 해마다 맞춤을 다시 돌기 때문에 **게임 안 리그 홈런·볼넷·삼진 비율은 늘 목표(2022~2026 평균 × 배율)에 붙어 있다.** 그래서 "경기당 득점이 기준보다 10% 높으면 공인구 조정" 같은 기록 기준은 거의 걸리지 않는다. 결정 9(따로 떠도는 환경 없음)를 지키면서 흐름을 만들려면 신호를 두 종류로 잡는다 (기획 직원 추천, 6.2절 남은 결정 1):

| 항목 | 신호 | 왜 이 신호인가 |
|---|---|---|
| 공인구 기준 | **선수층 장타 압력** = 그 시즌 맞춤 계수의 역수 `1 / cal.hr` × 지금 홈런 배율 | 맞춤 계수는 "이 선수들로 목표를 내려면 얼마나 눌러야 하나"라서 선수층의 타고·투저 쪽 흐름이 여기에 보인다. 목표 배율을 바꿔도 계수는 거의 그대로일 것 (1-8 첫 작업에서 확인) |
| 존 | **삼진 압력** `1 / cal.so`, **볼넷 압력** `1 / cal.bb` × 지금 배율 | 같음 |
| 연장 이닝 | 무승부 비율 (맞춤 밖) | 실제 2025 3.1% |
| 1군 엔트리 | 구단당 부상·피로 결장 선수-일 (맞춤 밖) | 엔트리 확대의 실제 명분이 선수 보호였다 |
| 외국인 한도 | 국내 선수층 지표: `tools/flow_longterm.ts`의 상위 270명 기여 합 (맞춤 밖) | 외국인 확대의 실제 명분이 선수 부족이었다 |
| 캡 증가율 | 캡 초과 구단 수, 구단 평균 캡 사용률 (맞춤 밖) | 캡 제도 운영 그대로 |

- 신호를 쓰는 곳은 결산(`beginOffseason`) 한 곳뿐이다. 맞춤 계수는 시즌 저장에 이미 있다 (`Season.toSave`의 `cal`).
- 압력 신호는 기록에 드러나지 않으므로 알림 이유 문구에 숫자를 쓴다: "선수들의 장타력이 리그 기준보다 12% 높아 반발계수 기준을 낮춘다 (게임 속 가상 결정)".

### 4.3 판정 규칙 (모두 임시값)

- **시작**: 다음 시즌이 2028년 이후일 때 (`FUTURE_RULES_FROM = 2028`). 2027년은 발표된 제도(캡 값·하한 예고)가 있어 2026 제도 + 그 값으로 간다.
- **문턱**: 같은 쪽으로 2시즌 이어서 벗어나면 후보. 쿨다운: 같은 항목은 바뀐 뒤 3시즌 동안 다시 후보가 되지 않는다.
- **고르기**: 후보가 여럿이면 `Rng`(리그 시드 + `rules:${year}` 갈래)로 하나. `fork`는 부모 난수를 쓰지 않으므로 후보가 없는 해에는 다른 결과가 하나도 바뀌지 않는다.

| 항목 | 기준 (벗어나면 후보) | 한 번에 바꾸는 폭 | 누적 범위 |
|---|---|---|---|
| 공인구 기준 | 장타 압력 1.10 초과 / 0.90 미만 | 홈런 목표 ×0.94 / ×1.06, 2루타 ×0.98 / ×1.02 (알림에는 "반발계수 기준 0.005 하향/상향") | 홈런 배율 0.75~1.25 |
| 존 | 삼진 압력 1.10 초과 또는 볼넷 압력 0.90 미만 → 존 축소 / 반대 → 존 확대 | 삼진 ×0.97·볼넷 ×1.05 / 반대 | 각 0.85~1.15 |
| 연장 이닝 | 무승부 4% 초과 / 1% 미만 | ±1회 | 10~15회 (0 = 무제한은 넣지 않음) |
| 1군 엔트리 | 결장 선수-일이 2027 시즌 값보다 20% 넘게 많음 / 적음 | ±1명 (13단계 뒤에는 등록·출장 같이) | 등록 28~32명 |
| 외국인 한도 | 국내 선수층 지표가 2027 시즌 값보다 8% 넘게 낮음 / 높음 | 정규 외국인 ±1명 (아시아쿼터 그대로) | 정규 2~4명 |
| 캡 증가율 | 초과 구단 2시즌 평균 3곳 이상 → +2%p / 초과 0곳이고 평균 사용률 60% 미만 → -2%p | ±2%p | 연 3~9% (지금 5%) |

### 4.4 저장·재현

- 리그 상태에 선택 항목 `ruleShifts?: { year, key, before, after, reason, signal }[]`를 더한다. 없으면 빈 목록 → **예전 저장도 열린다** (format 값은 그대로, 선택 항목만 늘어남).
- 그 해 값 = 2026 제도(2027 발표값 포함) + `year`가 그 해 이하인 `ruleShifts`를 차례로. 엔진 쪽은 `worldFromLeague`의 자료 없는 해 가지에서 목표 비율에 배율을 곱하고 `rules`의 `rosterSize`·`maxInnings`·`foreignLimit`을 바꾼 값을 넘긴다. 캡은 `salaryCap`의 2029년 이후 5% 대신 그 해 증가율.
- 같은 시드 → 같은 신호 → 같은 변화. 결산 시점의 리그 기록과 맞춤 계수는 이미 재현되므로 새 조작 기록이 필요 없다.
