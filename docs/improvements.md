## 0. 한눈에 보기

가장 먼저 손대야 할 다섯 가지 (2026-10-11 모두 고침. 5는 `docs/longterm-plan.md` 7장):

1. **창단 해 오프시즌 흰 화면 (C1)** — 1985·1990·2012·2014 시작 게임은 두 번째 시즌으로 넘어갈 수 없다. 자동 저장도 깨진 상태로 남는다.
2. **오류 경계 없음 (M15)** — 화면 한 곳의 오류가 앱 전체를 흰 화면으로 만들고 빠져나갈 길이 없다. C1 같은 버그가 또 나와도 피해를 줄일 장치가 없다.
3. **버그 보고용 재현 정보가 첫 시즌 뒤에는 틀린다 (M14)** — QA 공부라는 이 프로젝트의 목적과 바로 닿아 있다.
4. **외부 FA 한도를 플레이어만 넘을 수 있다 (H6)** — 한 오프시즌에 FA 6명을 데려올 수 있어 전략이 무너진다.
5. **장기 진행이 무너진다 (H1·H5·H7)** — 첫 오프시즌 입대 폭증, 20시즌 동안 기량 25% 하락, 포수 1명뿐인 구단. 다년 운영이 핵심인 게임에서 가장 큰 구조적 약점이다.

### 1.4 낮음

- 자동 저장 때마다 모든 저장 칸을 데이터째 읽는다 (진행 버튼마다 최대 10MB 안팎). 키만 읽으면 된다.
- 저장 크기가 해마다 커진다 (개막 0.47MB → 5년 뒤 2.1MB). 다음 시즌 열기 1.1~1.4초. 20~40년 진행하면 브라우저 저장소 한도에 닿을 수 있고, 용량 초과를 따로 처리하지 않는다.
- 저장 칸 "지우기"에 확인이 없다 (`SaveScreen.tsx:75`, **미해결**).
- 시작 연도 실제 명단이 정원을 넘는다 (2026 키움 71명). 첫 오프시즌에 정리된다.
- "외" 배지가 이름에 붙어 복사하면 "오스틴외"가 된다. 홈의 "0/ 0" 간격. 트레이드 상대 "전력 7위"가 언제 기준인지 설명 없음.

## 4. 화면과 사용 경험

- **처음 안내가 없다.** 단장 역할, 진행 버튼, 기용표, 오프시즌 7단계, 구단주 평가를 설명하는 곳이 없다. 처음 하는 사람이 가장 먼저 막힌다.
- **휴대폰 화면**: 760px 이하 규칙 하나뿐이다. 열이 많은 표는 가로 스크롤에 의존하고 왼쪽 메뉴 폭이 고정이다 (M9 할 일).
- **과거 시작 연도의 사실감**: 1982년부터 고를 수 있지만 제도연표 미확인 8건, 물가 계수·FA 연차·창단 수급이 임시값이다. "최저 연봉 3,000만 원" 안내가 과거 연도에서 물가와 맞지 않는다. 시작 화면에 "과거 시대는 추정값이 많다"는 표시를 두면 좋다.
- **화면 흐름 자동 테스트가 없다.** 엔진·리그·세션은 테스트가 있지만 화면은 수동 확인뿐이라 C1 같은 화면 버그를 못 잡았다. 해고·영입 제의 화면은 브라우저로 일으켜 본 적이 없다.

## 6. 개발·QA 환경

QA 학습이 목적인 프로젝트라 도구 쪽 빈틈도 적는다.

- **퍼저와 장기 검증 도구가 저장소에 없다.** `tmp-audit/fuzz.ts`는 커밋되지 않았고, `tools/validate_longterm.ts`는 빌드를 깨뜨려 PR #8에서 빼낸 뒤 지금 추적되지 않는 파일로만 남아 있다. 2차 조사의 핵심 도구라서 타입 오류를 고쳐 `tools/`에 정식으로 넣고 `npm` 명령으로 묶는 편이 좋다.
- **`expansion.md`가 main에 없다.** `qa-survey.md`가 `expansion.md` A4·E5·D3을 가리키지만 그 문서는 `expansion-plan` 브랜치에만 있다 (깨진 참조).
- **CLAUDE.md의 테스트 수(148개)가 낡았다** (2차 조사 때 179개).
- **엑셀 잠금 파일(`data-src/~$…xlsx`)이 커밋돼 있다.** 지금 작업 폴더에서는 지워진 상태로 잡힌다. `.gitignore`에 `~$*`를 더하고 저장소에서 빼면 된다.
- **화면 테스트 도구가 없다** (4장). Playwright 같은 도구로 "새 게임 → 시즌 끝 → 오프시즌 → 다음 개막" 한 바퀴만 자동으로 돌려도 C1급 버그를 막을 수 있다.
- **PR 단계 검사가 없다.** 워크플로는 `deploy.yml` 하나뿐이고 main에 push될 때만 테스트·빌드를 돌린다. 그래서 PR #7은 빌드가 깨진 채 병합됐고, PR #8로 따로 고쳐야 했다. `pull_request` 때도 `npm test`와 `npm run build`를 돌리게 하면 병합 전에 막을 수 있다.
