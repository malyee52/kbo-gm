## 0. 사용자 결정 (2026-10-22)과 요약

사용자 결정:
1. 컨디션은 **C 선수 단위**로 정의한다 (초안 1의 추천 A는 쓰지 않는다).
2. **원정 감소는 없앤다** (경기 엔진 2 기획안 7.1 10 "원정팀 기본 −1 + 거리 감소"를 뒤집음). 연고지 거리 표는 컨디션에 쓰지 않는다.
3. **고정 홈 이점 0.013은 그대로 둔다** (`params.homeEdge`, T3). 12단계의 "고정 홈 이점 제거"는 하지 않는다.
4. **화면에는 말로만**: "좋음 / 보통 / 나쁨" 세 단계 + 사유. 숫자는 없다. 숨은 능력 '기복'은 숨긴 채 둔다 (세 단계 낱말로 기복을 거꾸로 알아낼 수 없게).
5. (추가, 같은 날) **기복과 컨디션은 서로 다른 값이고 다르게 작용한다.** 기복을 컨디션에 섞지 않는다. 컨디션 낱말은 **컨디션 값만으로** 정한다. 사용자: "말했듯이 기복과 컨디션 스탯은 다르게 작용할 거야."

같은 날 초안 2의 "사용자가 정할 것" 9개도 정했다 (9장 결정): 며칠 이어지는 흐름, 효과 크기 **0.04**, 타석 결과에만, AI 감독은 쓰되 **반영 정도는 감독 성향**, 감기·몸살·컨디션 난조 이벤트를 컨디션 사건으로, 이름 "컨디션"(선수 개인 상태)과 "경기력"(구단 선택·환경 보정)을 나눔, 복귀 직후 하락 없음, 개막 시작값은 평소 분포에서, 낱말 경계 ±0.4.

요약:
- **컨디션 = 선수마다 하루 하나씩 갖는 몸 상태 값.** 연속값 −1.0 ~ +1.0, 평균 0. 두 부분의 합이다: ① **흐름** — 며칠씩 이어지며 0으로 천천히 돌아가는 무작위 값 (하루에 10%씩 0쪽으로, 반감 약 7일, 임시값). 모든 선수가 같은 퍼짐을 갖는다. ② **사건** — 감기·몸살·컨디션 난조 같은 허용 사건이 기간 동안 내리는 값.
- **기복(숨은 능력)과는 따로다**: 기복은 경기 하나마다 새로 뽑는 그날 흔들림이고 그 퍼짐이 선수마다 다르다 (숨김). 컨디션은 며칠 이어지는 상태이고 퍼짐이 모두 같다 (보임). 두 값은 서로를 읽지 않는다 (4장 나란히 표).
- **경기력과도 따로다**: 회식·특별 훈련·폭염·캠프·코치처럼 구단의 선택이나 환경이 팀에 주는 보정은 "경기력"이라 부르고 지금의 `FormBuff`·`coachEdge` 자리에 그대로 둔다. 컨디션은 선수 개인에게 저절로 흐르는 상태다 (9장 6).
- 컨디션은 **경기 결과를 보지 않는다** (잘 쳤다고 오르지 않는다). 결과를 보면 기복이 큰 선수의 낱말이 더 자주 바뀌어 기복이 새어 나간다. 출전·투구 수·연전도 보지 않는다 (투수 피로·혹사지수·야수 체력이 센다).
- 효과: 타석 보정 edge에 `(타자 컨디션 − 투수 컨디션) × 0.04` (임시값, 사용자 결정 크기). "좋음"인 날 평균 약 +0.023 (약 +2%p). 홈 이점(0.013)의 두 배 가까이, 좌우 상성(0.035)보다 조금 작다. 수비·주루에는 주지 않는다.
- AI 감독은 컨디션을 라인업·선발 고르기에 쓰고, 얼마나 반영하는지는 감독마다 다른 새 성향 '컨디션 반영'이 정한다 (7.4).
- 리그 평균 효과 0: 흐름은 대칭 분포라 기대값이 정확히 0이다. 크기 0.04에서도 남는 2차 효과는 리그 지표 기준(±1%)보다 훨씬 작을 것으로 본다 (7.1, 12-2에서 잰다). 검증의 닻은 "효과 크기 0 = 지금 엔진과 비트 단위로 같은 결과" (컨디션 난수 줄기가 경기 줄기와 따로라서 가능).

## 1. 선수 컨디션의 정의

### 1.1 값

| 항목 | 정의 |
|---|---|
| 대상 | 리그의 모든 선수 (1군·2군·결장 중 모두. 타자·투수 같은 규칙) |
| 값 | 연속값 `cond` ∈ [−1.0, +1.0], 단위 없음. 0 = 평소. 양수가 좋은 쪽 |
| 구성 | `cond = clamp(흐름 + 사건, −1, +1)` |
| 바뀌는 때 | 하루에 한 번, 그날 경기 전 (정규시즌 날짜 색인·가을야구 날짜마다). 경기가 없는 날·쉬는 선수도 흐름은 한 걸음 간다 |
| 보이는 것 | 낱말 세 단계 + 사유 (6장). 숫자는 어디에도 없다 |

### 1.2 흐름 (무작위, 며칠 이어짐)

- 하루 한 걸음: `흐름(내일) = ρ × 흐름(오늘) + 흔들림`, 흔들림 ~ 정규분포(0, σε).
- ρ = **0.90** (하루에 10%씩 0쪽으로 돌아감, 반감 약 6.6일, 임시값). σε = **0.153** (임시값) → 오래 두면 흐름의 퍼짐(표준편차) σ = σε ÷ √(1 − ρ²) ≈ **0.35**.
- 모든 선수가 같은 ρ·σε를 쓴다. **선수마다 다른 값(숨은 능력 포함)을 흐름에 넣지 않는다** (5장 새지 않게 하는 방법).
- 개막 날 시작값: 오래 둔 분포(평균 0, 퍼짐 0.35)에서 뽑는다 (결정, 9장 8). 오프시즌을 넘어 이어 가지 않는다.
- 자르기: ±1.0 밖은 잘라 낸다. 퍼짐 0.35에서 잘리는 비율은 양쪽 각 약 0.4%이고 대칭이라 평균은 0 그대로.

### 1.3 사건 (허용 사건만)

- 사건은 기간 동안 흐름 위에 덧붙는 음수 값이다. 끝나면 사라지고 흐름만 남는다.
- 사건의 출처는 **시즌 중 무작위 이벤트**(`league/events.ts`·`events-extra.ts`) 가운데 **몸 상태 계열(감기·몸살·컨디션 난조)** 만이다 (결정, 9장 5). 지금 이 이벤트들은 `FormBuff`(팀 경기력)로 들어가는데, 이것을 컨디션 사건으로 옮긴다. 예: '선수단 감기 확산'(`x-team-flu`)의 "7일 동안 팀 경기력 −2.0" → "7일 동안 해당 구단 선수 컨디션 사건 −0.5 (사유: 감기)" (크기 임시값). 크기 0.04에서 −0.5는 edge −0.02라, 지금 이벤트가 주던 팀 경기력 −0.02와 같은 크기다. 증상 있는 선수를 쉬게 하는 선택지(지금 3일 −0.01)는 3일 동안 −0.25.
- 지금 코드에서 이름이 맞는 이벤트는 '선수단 감기 확산' 하나다. **몸살·컨디션 난조라는 이벤트는 아직 없다.** 비슷한 '원정 숙소 단체 배탈'(`x-food-poison`)은 결정 목록에 없어서 경기력에 둔다. 몸살·컨디션 난조 이벤트를 새로 만들지(새 기능), 배탈을 몸 상태 계열로 옮길지는 12-4에 들어가기 전에 사용자에게 묻는다.
- 옮기지 않는 것: 선수단 미팅·회식·특별 훈련 같은 **사기·분위기 계열**과 폭염·미세먼지·야간 경기 연속 같은 **환경 계열**은 지금처럼 경기력(`FormBuff`)에 남는다 (9장 6: 구단 선택·환경 = 경기력). 물집·허리 통증·몸에 맞은 공 후유증 같은 **통증 계열**은 부상에 가까우므로 컨디션에 넣지 않고 경기력으로 남긴다 (11단계 부상·결장 표시를 정한 뒤 다시 본다).
- 이벤트는 지금 플레이어 구단에만 생긴다. 그래서 AI끼리 돌리는 검증 도구(`validate`·`longsim`·`engine2_baseline`)에서는 사건이 0이고 흐름만 남는다.

### 1.4 하루 회복

따로 회복 규칙을 두지 않는다. 흐름의 ρ가 날마다 0쪽으로 당기는 것이 회복이고, 사건은 기간이 끝나면 사라진다. 휴식일·결장·2군이라고 더 빨리 회복하지 않는다 (쉬어서 차는 값은 야수 체력·불펜 피로가 맡는다, 2장).

### 1.5 크기의 감 (임시값으로 계산)

- 퍼짐 0.35, 경계 ±0.4 (6장)면 어느 날 리그 선수의 약 **12.7%가 좋음, 74.7%가 보통, 12.7%가 나쁨**.
- ρ 0.90이라 좋음·나쁨은 보통 며칠 이어진다. 한 시즌(약 150일)에 한 선수가 좋음과 나쁨을 각각 여러 번 겪는다. 슬럼프(시즌 단위)처럼 길게 가지 않는다.

## 3. 경기에 주는 효과

### 3.1 자리와 식

- `pa.ts`의 타자 유리 정도(edge)에 한 항을 더한다: `+ condEdge × (cond[타자] − cond[투수])`. 지금 `ctx.form`(경기력)과 같은 꼴이고, 투수의 좋은 컨디션은 타자에게 불리하게 들어간다.
- `condEdge` = **0.04** (|cond| = 1일 때 edge ±0.04, 사용자 결정 크기, 근거 자료 없음이라 임시값 표시). 좋음(cond ≥ 0.4) 날의 평균 cond는 약 +0.57이므로 평균 효과 약 **+0.023** (약 +2%p), 나쁨은 약 −0.023.
- 맞대결의 크기 감: 좋음 타자(+0.57) 대 나쁨 투수(−0.57)면 edge 약 +0.046, 둘 다 보통이면 대개 ±0.02 안. 타자 항과 투수 항의 차이는 퍼짐 약 0.49(= 0.35 × √2)라, 한 타석 edge 컨디션 몫의 퍼짐은 약 0.020이다.
- edge는 지금처럼 안타·홈런·볼넷을 (1 + edge)배, 삼진을 (1 − edge)배 한다. **타석 결과에만** 준다: 사구·수비(담당 수비수의 안타 ↔ 아웃 판정)·주루(도루·추가 진루)·투구 수·한계 투구 수에는 주지 않는다 (결정, 9장 3). 타자 컨디션과 투수 컨디션 둘 다 이 맞대결 항으로만 들어간다.
- 두 엔진(B 타석 단위 자동 진행, A 투구 단위 수동 경기)은 같은 `paRates`를 거치므로 같은 효과다. 가을야구·직접 지휘도 같다.

### 3.2 크기의 근거

- **사용자가 정한 크기다 (초안 추천 0.02보다 크게). 근거 자료는 없다.** 비교: 좋음 날 평균 +0.023은 홈 이점 0.013의 약 1.8배이고 좌우 상성 0.035보다 작다. 이벤트 경기력(±0.01~0.04)과 같은 단위다. 낱말이 기용 판단을 실제로 움직일 만큼 크게 두려는 뜻이다.
- 실제 자료로 맞추지 않는다. 다만 12-2 측정 도구에서 2023~2026 투구 단위 자료의 **선수별 경기 기록이 며칠 동안 이어지는 정도**(연속 경기 사이 상관)를 재어, 컨디션이 만드는 이어짐이 실제보다 터무니없이 크지 않은지 확인한다 (상한 확인용, 맞춤 아님). 0.04는 0.02보다 이어짐을 약 두 배로 만들므로 이 확인이 더 중요해졌다. 실제 값을 아직 재지 않았으므로 지금은 아무 주장도 하지 않는다. 시뮬 쪽이 실제 상관을 뚜렷이 넘으면 크기를 줄일지 사용자에게 묻는다 (마음대로 줄이지 않는다).

## 4. 기복과 컨디션: 나란히 표 (사용자 결정 5)

**둘은 다른 값이고 다르게 작용한다. 기복은 컨디션에 섞이지 않고, 컨디션 낱말은 컨디션 값만으로 정한다.**

| 항목 | 기복 (숨은 능력 ⑤, 4.5) | 컨디션 (이 문서) |
|---|---|---|
| 무엇인가 | **선수의 성질**: 경기마다 얼마나 들쭉날쭉한가 | **선수의 상태**: 요즘 몸이 어떤가 |
| 선수마다 다른 것 | 퍼짐의 크기 자체 (숨은 값, 리그 평균 1.00 둘레) | 다른 것이 없다. 모든 선수가 같은 규칙·같은 퍼짐. 다른 것은 그날 값뿐 |
| 시간 단위 | 경기 하나. 경기마다 새로 뽑고 다음 경기와 이어지지 않는다 | 하루. 며칠 이어지며 천천히 0으로 돌아간다 (반감 약 7일) |
| 무엇이 정하나 | 경기 줄기(`gameRng`)에서 경기 시작 때 뽑음, 평균 0·퍼짐 = 기복 값 | 컨디션 줄기(`cond/${날}`)의 흐름 + 몸 상태 사건 (감기 등) |
| 원인이 보이나 | 없다 (그냥 그날 잘 되거나 안 됨) | 사유가 있다 ("감기 기운", "몸이 무거움" 등) |
| 경기에서 작용 | 그 경기 타석 edge에 그날 흔들림을 더함 (그 경기에만) | 그날 모든 타석 edge에 `condEdge × cond`(0.04 × cond)를 더함 (며칠 같은 방향으로 이어짐). 수비·주루에는 없음 |
| 시즌 기록에 주는 것 | 시즌 평균은 그대로, **경기 사이 퍼짐**이 커짐 (멀티히트와 무안타가 잦아짐) | 시즌 평균은 그대로, **며칠 단위 몰림**이 생김 (좋을 때 연속으로 잘 침) |
| 보이나 | 숨김. 기록이 쌓이면 짐작 문구 "꾸준한 편" / "날마다 들쭉날쭉한 편" (난이도 오차) | 보임. 낱말 "좋음 / 보통 / 나쁨" + 사유. 숫자 없음 |
| 플레이어가 아는 길 | 기록을 보고 짐작 (문구) | 오늘 화면을 보면 앎 |
| 플레이어가 쓰는 법 | 선수 고르기·영입 판단 (오래 가는 성질) | 오늘 기용표: 나쁨인 선수를 쉬게 하거나 좋음인 선수를 올림 |
| AI 감독 | 쓰지 않는다 (4.5: 숨은 능력은 경기 안 판단에 안 씀) | 쓴다. 얼마나 반영하는지는 감독 성향 '컨디션 반영' (결정, 9장 4, 7.4) |
| AI 단장 | 오차 섞은 짐작값으로 가치 판단 (16단계) | 쓰지 않는다 (며칠짜리 값이라 선수 가치와 무관) |
| 저장 | `LeaguePlayer.hidden` (리그 상태, 세션 형식 3) | 그날 흐름 값을 시즌 상태 `PlayerStates.cond`에 (시즌 저장) |
| 만드는 때 | 엔진 연결·저장은 16단계 (그 전까지 모두 1.00) | 12단계 |
| 서로 읽는가 | 컨디션을 읽지 않는다 | **기복을 읽지 않는다.** 경기 결과도 읽지 않는다 |

### 4.1 둘이 함께 쓰일 때

- 같은 타석의 edge 안에서 두 항은 **따로 계산해 따로 더한다**. 합계 값을 만들거나 보이지 않는다.
- 기복은 16단계 전까지 모두 1.00(퍼짐 리그 평균)이고 엔진에는 아직 없다. 컨디션을 먼저 넣어도 16단계에서 기복이 들어올 때 서로 건드리지 않는다.

## 5. 컨디션 낱말에서 기복이 새지 않게 하는 방법

1. **흐름의 규칙이 모든 선수에게 같다**: ρ·σε가 선수에 따라 다르지 않다. 숨은 능력(기복·회복력·부상 경향·실제 한계)은 흐름에 들어가지 않는다. 그래서 한 선수의 낱말이 시즌 내내 얼마나 자주 바뀌는지를 세어도 숨은 값에 대해 알 수 있는 것이 없다.
2. **경기 결과를 보지 않는다**: 어제 3안타를 쳤다고 컨디션이 오르지 않는다. 결과를 보면 기복이 큰 선수(결과가 크게 흔들림)의 컨디션이 더 크게 흔들려 낱말로 새어 나간다.
3. **난수 줄기가 따로다**: 컨디션 흔들림은 시즌 뿌리에서 가른 `cond/${날}` 줄기에서만 뽑는다. 기복의 그날 값은 경기 줄기(`g/${날}/${홈}-${원정}`)에서 뽑는다. 한쪽 소비가 다른 쪽 값을 바꾸지 않는다.
4. **숨은 흔들림을 엮지 않는다**: 투수의 그날 몸 상태(한계 투구 수 0.82~1.18배)와 혹사지수도 컨디션에 넣지 않는다. 낱말이 이 값들과 상관을 가지면 같은 이유로 새어 나간다.
5. **테스트** (12-1·12-6):
   - 같은 리그 시드에서 기복(또는 숨은 능력 전부)을 바꿔도 모든 선수의 컨디션 값과 낱말이 날마다 같다.
   - 화면(`src/ui`) 소스 검사: 컨디션 표시 코드가 기복·숨은 능력을 읽지 않고, 컨디션 숫자를 내보내지 않는다 (`tests/traits.test.ts`와 같은 꼴).
   - 측정 (12-2): 기복 값 구간별로 낱말 비율(좋음·보통·나쁨)과 낱말이 바뀌는 횟수가 표본 오차 안에서 같다.

## 6. 화면: 세 단계 낱말과 사유 (정보 명세, 모양은 UI 대개편에서)

### 6.1 경계 (결정 9장 9, 값은 임시값)

| 낱말 | 조건 | 오래 둔 분포에서 비율 |
|---|---|---:|
| 좋음 | cond ≥ +0.4 | 약 12.7% |
| 보통 | −0.4 < cond < +0.4 | 약 74.7% |
| 나쁨 | cond ≤ −0.4 | 약 12.7% |

- 낱말은 그날 **컨디션 값(흐름 + 사건)만**으로 정한다. 기복·경기력(`FormBuff`)·체력·피로는 넣지 않는다 (경기력·체력은 각자 자리에 따로 보인다).
- 경계에서 날마다 좋음 ↔ 보통이 깜빡이는 것을 막는 문턱(히스테리시스)은 두지 않는다 (기획 판단). 흐름이 하루 0.15 안팎으로만 움직여 깜빡임이 잦지 않을 것이고, 규칙이 한 줄이어야 QA가 쉽다. 측정(12-2)에서 낱말이 바뀌는 횟수를 보고 다시 판단한다.

### 6.2 사유 문구 (실존·가상 선수 같은 문구)

화면 꼴은 **"낱말 · 사유"** 한 줄이다 (사용자 결정 예: "나쁨 · 감기"). 사유가 없으면 낱말만. 사유는 하나만 보인다. 진행 중인 사건이 있으면 사건 사유가 앞선다 (낱말이 보통이어도 사건 사유는 보인다: "보통 · 감기").

| 경우 | 낱말 | 사유 문구 | 화면 예 |
|---|---|---|---|
| 흐름, 좋음 | 좋음 | "몸 상태 좋음" | 좋음 · 몸 상태 좋음 |
| 흐름, 보통 | 보통 | (사유 없음) | 보통 |
| 흐름, 나쁨 | 나쁨 | "몸이 무거움" | 나쁨 · 몸이 무거움 |
| 흐름, 아주 나쁨 (cond ≤ −0.7, 임시값) | 나쁨 | "컨디션 난조" | 나쁨 · 컨디션 난조 |
| 사건: 감기 이벤트 | 그날 값대로 | "감기" | 나쁨 · 감기 |
| 사건: 몸살 이벤트 (아직 없음, 1.3) | 그날 값대로 | "몸살" | 나쁨 · 몸살 |
| 사건: 컨디션 난조 이벤트 (아직 없음, 1.3) | 그날 값대로 | "컨디션 난조" | 나쁨 · 컨디션 난조 |

- **실존 선수 사건 규칙과의 관계**: 감기·몸살·컨디션 난조는 사유가 가볍고 누구에게나 생기는 일이라 **허용 사건**으로 본다 (사용자 지정). 사생활·스캔들·구체적 부상 부위·실제 있었던 일은 사유에 쓰지 않는다. 흐름 사유("몸 상태 좋음"·"몸이 무거움")는 사건을 지어내지 않는 중립 문구다.
- 통증·물집 같은 부상 계열은 컨디션 사유에 쓰지 않는다 (1.3, 11단계 부상 표시와 함께 정한다).
- 문구는 화면 단계에서 다듬어도 된다. 다만 문구가 기복·숨은 능력·경기 결과를 가리키면 안 된다 ("최근 타격감" 같은 결과 문구 금지).

### 6.3 어디에

선수 목록·선수 상세·기용표·경기 전 라인업에 낱말과 사유. 도움말: "컨디션은 며칠씩 이어지는 선수의 몸 상태입니다. 좋음이면 타석에서 조금 더 잘하고, 나쁨이면 조금 못합니다. 구단의 선택이나 날씨가 팀 전체에 주는 영향은 '경기력'으로 따로 보입니다." 크기 숫자는 도움말에도 쓰지 않는다 (사용자 결정 4).

## 7. 리그 평균·검증·저장·난수

### 7.1 리그 평균이 틀어지지 않는 조건 (컨디션 평균 효과 0)

크기 0.04 기준으로 다시 썼다.

- **1차 (기대값)**: 흐름은 흔들림이 평균 0인 대칭 분포, 시작값도 평균 0, 자르기도 대칭 → 모든 날 모든 선수의 기대값 0. 타자 항과 투수 항이 같은 분포라 `cond[타자] − cond[투수]`의 기대값도 0. 크기를 0.04로 키워도 이 부분은 그대로 0이다.
- **2차 ① 타석 확률의 휘어짐**: edge는 타자 비율에 곱한 뒤 odds 결합(`combine`, log5 꼴)을 거치므로 확률에 대해 직선이 아니다. 남는 치우침은 edge 컨디션 몫의 분산에 비례한다: 0.04² × 2 × 0.35² ≈ 0.0004 (0.02일 때의 4배). 각 결과 비율의 상대 치우침은 이 값 정도, 즉 **0.1% 안쪽**으로 본다 (추정, 12-2에서 잰다).
- **2차 ② 득점의 휘어짐**: 한 경기 안에서 같은 투수와 같은 타자들이 컨디션을 나눠 가지므로, 경기마다 타격 환경이 조금씩 오르내린다 (선발 투수 몫 edge 퍼짐 약 0.014, 타자 9명 평균 몫 약 0.005). 득점은 환경에 대해 볼록하므로 평균 득점이 아주 조금 오른다. 득점이 edge에 대해 약 2.5배로 움직인다고 보면 상대 치우침은 약 1.9 × 0.015² ≈ **0.04%** (추정). 공통 기준(경기당 득점 ±5%, 맞춤 지표 ±1%)보다 두 자릿수 작다.
- **팀 사이 격차**: 선수마다 흐름이 따로라 구단 평균 컨디션의 퍼짐은 작다 (1군 28명 평균이면 약 0.07, edge 약 0.003). 팀 승률 표준편차는 거의 그대로일 것이다 (보고만 한다).
- **AI 감독의 선택 치우침 (새로 생기는 몫)**: AI 감독이 컨디션을 보고 고르면(7.4) 실제로 타석에 서는 타자와 마운드에 오르는 투수의 평균 컨디션이 0보다 커진다. 타자 쪽은 득점을 올리고 투수 쪽은 내리므로 일부 상쇄되나 정확히 0은 아니다 (야수 라인업은 매일 고르고 선발 로테이션은 순서가 있어 고르는 폭이 다르다). **이것이 0.04에서 리그 평균을 움직일 수 있는 가장 큰 몫이다.** 12-5에서 출전 선수의 평균 컨디션(타자·투수 따로)과 리그 지표 변화를 재고, 기준을 넘으면 사용자에게 보고하고 '컨디션 반영' 성향의 폭을 줄일지 묻는다.
- 사건은 음수만 있으나 플레이어 구단 이벤트에서만 생기므로 리그 검증 도구에는 없다 (지금 경기력 이벤트와 같은 처지). 감기 사건 크기(−0.5 × 0.04 = −0.02)는 지금 경기력 −0.02와 같아 플레이어 구단에 주는 영향도 그대로다.
- **복귀 직후 하락 같은 리그 전체의 음수 사유를 넣지 않는 이유 중 하나가 이것이다** (결정, 9장 7): 넣으면 평균이 음수로 기울어 리그 지표를 다시 맞춰야 한다. 크기 0.04에서는 기울기도 두 배가 된다.

### 7.2 검증 기준

1. **효과 0 = 지금 엔진**: `condEdge = 0`이면 같은 시드에서 지금 엔진과 비트 단위로 같은 결과 (컨디션 줄기는 경기 줄기·`dayRng`·`eventRng`를 건드리지 않으므로 흐름을 계산해도 결과가 같아야 한다). 단위 테스트.
2. 공통 기준 (`condEdge = 0.04`, AI 감독 반영 전 12-3): `npm test`, `npm run validate -- --years 2025,2019,2012 --seasons 100`에서 맞춤 지표 ±1%, 경기당 득점 ±5% (`docs/engine.md` 4장). 7.1 추정대로면 효과 0과의 차이는 득점 0.1% 안쪽이다. 홈 승률·팀 승률 표준편차는 그대로인지 보고.
3. AI 감독 반영 뒤 (12-5): 2의 공통 기준을 다시 지키고, 상위 9명 타석 비중 0.708 ±0.015 유지. 출전 타자·등판 투수의 평균 컨디션(따로)과 경기당 득점 변화를 보고한다 (7.1 선택 치우침). '컨디션 반영' 성향을 모두 0으로 두면 12-3과 비트 단위로 같은 결과 (단위 테스트).
4. 측정 (맞춤 아님, `reports/condition-check.md`): 낱말 비율 (기대 약 12.7 / 74.7 / 12.7%), 낱말이 바뀌는 횟수, 좋음·보통·나쁨 날의 타자 OPS·투수 피OPS 차이 (0.04에서 좋음과 나쁨 사이 edge 차이 약 0.046), 기복 구간별 낱말 비율이 같은지 (5장), 실제 자료의 연속 경기 상관 대 시뮬 (3.2), 7.1의 2차 치우침 (효과 0 대 0.04의 득점·타율 차이).
5. 같은 시드 같은 결과, 저장 뒤 이어가기 = 끊지 않은 결과, 화면 조회(`refresh`)를 끼워도 같은 결과 (`tests/game.test.ts`).

### 7.3 저장·난수 줄기

- **난수 줄기**: 시즌 난수 뿌리에서 `cond/${날}`로 하루에 한 번 가르고, 선수 색인 순서대로 흔들림을 뽑는다. 개막 시작값은 `cond/open`. 선수 색인은 시즌 중 뒤에만 붙고 바뀌지 않으므로 (트레이드는 소속만 바꿈) 시즌 중간에 들어온 선수가 앞 선수 값을 바꾸지 않는다. 결장·2군 선수도 뽑아 순서를 지킨다.
- **저장**: 그날 흐름 값을 `PlayerStates`에 `cond: Float32Array`로 두고 시즌 저장에 넣는다. 날마다 줄기를 새로 가르므로 난수 위치는 저장하지 않는다. 시즌 저장 `format`을 올린다 (엔진 2는 예전 저장을 지우므로 변환은 만들지 않는다, 경기 엔진 2 기획안 3.7.4).
  - 다시 계산하는 길(개막부터 흐름을 다시 돌림)도 가능하지만, 저장이 더 단순하고 시즌 중 새로 생긴 선수 처리에 실수할 일이 적어 저장으로 한다 (기획 판단).
  - Float32로 저장하면 이어 할 때 Float64 계산과 끝자리가 달라질 수 있다. 계산도 Float32 배열에 넣고 읽어 쓰는 값으로 해서 "저장 뒤 이어가기 = 끊지 않은 결과"를 지킨다 (불펜 피로 `fatigue`와 같은 방식).
- **사건**: 이벤트 효과 목록(리그 상태 `events`, 이미 저장됨)에 컨디션 사건 종류를 더해 그날 값으로 읽는다 (`formToday`처럼 `condEventToday`). 따로 저장하지 않는다.
- **조작 기록(`GameAction`)**: 새 조작 없음. 컨디션은 조작으로 바뀌지 않는다 (판타지 모드에서 컨디션을 바꾸는 효과를 둘지는 이 문서 범위 밖).

### 7.4 AI 감독·AI 단장

- **AI 감독은 컨디션을 쓴다** (결정, 9장 4). 컨디션은 보이는 값이므로 경기 엔진 2 기획안 3.9.1(AI 감독은 보이는 것만 본다)에 맞는다. 라인업·선발 고르기의 선수 가치에 `컨디션 반영 성향 × (그날 condEdge × cond를 타석 가치로 바꾼 값)`을 더한다. 휴식 판단(야수 체력, 11단계)과 따로 둔다.
- **새 감독 성향 '컨디션 반영'** (`league/managers.ts` `Tactics`에 `cond` 하나 더함). 경기 엔진 2 기획안 3.9.1의 성향 표(9단계 대타·대주자 빈도, 10단계 투수 밀어붙이기·불펜 연투 허용)와 같은 틀로 만든다.

| 항목 | 정의 |
|---|---|
| 하는 일 | AI 감독이 고를 때 컨디션 효과를 얼마나 크게 보는가. 1.00 = 실제 효과만큼, 0.5 = 절반만 (컨디션을 덜 믿고 능력대로), 1.5 = 효과보다 크게 (컨디션 좋은 백업을 자주 올림) |

| 가상 감독 값 | 감독을 만들 때 범위 안에서 무작위 (감독 생성 난수 줄기, 9·10단계 성향과 같은 곳) |

| 저장 | 9·10단계 성향과 같은 곳 |
| 테스트 | 모두 0이면 12-3(AI 미반영)과 같은 결과, 모두 1.00이면 성향 없는 "효과만큼" 판단과 같은 결과 |

- 감독마다 반영 정도가 달라 같은 컨디션 낱말에도 구단마다 기용이 조금 다르게 나온다. 반영이 클수록 7.1의 선택 치우침이 커지므로 12-5에서 성향 구간별 출전 선수 평균 컨디션을 따로 보고한다.
- **AI 단장**: 쓰지 않는다. 트레이드·FA·방출 가치는 며칠짜리 상태와 무관하다 (`src/ai/value.ts` 그대로).
- 플레이어는 기용표에서 낱말을 보고 직접 정한다. AI 감독과 같은 정보다.
