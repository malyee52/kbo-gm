## 0. 요약

- 사용자 결정 (경기 엔진 2 기획안 7.1 10): 고정 홈 이점(타석 보정 ±0.013)을 없애고 **원정 거리에 따른 컨디션 감소, 원정팀 기본 컨디션 −1**로 바꾼다. "컨디션"이 무엇인지는 이 문서에서 정한다 (7.2 21).
- **추천: 안 A "팀 원정 컨디션"** — 구단 단위, 그날 일정으로만 정해지는 정수 단계(0 ~ −3). 원정 기본 −1 + 연고지 거리 단계(0·−1·−2). 상태를 남기지 않아 회복 규칙이 따로 필요 없고(날마다 새로 계산), 난수를 쓰지 않으며, 저장할 것이 거의 없다. 효과는 지금 홈 이점과 같은 자리(타석 보정 edge)에 들어간다.
- 연장·더블헤더·연전·이동일·휴식일은 컨디션에 넣지 않는 것을 추천한다. 투구 수 피로(4단계)·혹사지수(4.6)·야수 체력(11단계)이 같은 원인을 이미 선수 단위로 센다. 두 번 세지 않는다.
- 크기: 자료로 거리 효과를 가릴 수 없다 (2장, 구단-시즌 373개에서 기울기가 표준오차보다 작다). 그래서 **목표 승률에 맞추지 않고**, "리그 평균 원정 감소 = 지금 홈 이점 0.013"으로 한 칸 크기를 한 번 정하는 **평균 보존** 방식을 추천한다 (한 칸 ≈ 0.0064, 임시값). 홈 승률은 시대 묶음별 실제와 나란히 보고만 한다.
- 검증의 닻: ① 한 칸 크기 0 = 고정 홈 이점 0 엔진과 같은 결과 ② 한 칸 0.013 + 거리 단계 끔 = 지금 엔진과 같은 결과 (같은 시드, 비트 단위).

## 1. 정의 안

### 1.1 지금 엔진에서 "컨디션"이라는 말이 이미 쓰이는 곳

| 이름 (코드) | 단위·대상 | 원인 | 화면 이름 |
|---|---|---|---|
| `ctx.form` (`engine/game.ts`, P14) | 선수별 소수 edge (±0.005~0.025 정도) | 무작위 이벤트 효과(`league/events.ts` `FormBuff`), 코치(`coachEdge`, 등급당 0.0015), 스프링캠프(`camp.ts`), 판타지 모드(`teamForm`·`playerForm`) | 이벤트 선택지: "팀 경기력 −2.0", 판타지·캠프 주석: "선수단 컨디션" |

"컨디션"이라는 말이 이벤트 효과(경기력)와 새 원정 값 두 군데에 쓰이면 화면에서 헷갈린다. 이름 정리는 7장 2번.

### 1.2 안 A: 팀 원정 컨디션 (구단 단위, 그날 값, 상태 없음) — 추천

- **값**: 정수 단계, 0(홈 팀·중립) ~ −3. 양수는 없다 (홈 팀이 "좋아지는" 값이 아니라 원정 팀이 "나빠지는" 값이다. 사용자 결정의 말 그대로).
- **정하는 것** (그날 경기 한 판마다):
  - 원정 기본 **−1** (사용자 결정).
  - 거리 단계: 원정 팀 연고 도시 ↔ 홈 팀 연고 도시 직선 거리(`league/distance.ts`, `data-src/연고지.csv`)로 0~99km **0**, 100~249km **−1**, 250km 이상 **−2** (구간 임시값).
  - 홈 팀은 0. 올스타전 같은 중립 경기는 양쪽 0.
- **회복**: 없다. 상태가 없어 날마다 그날 경기로 새로 계산한다. 원정이 끝나고 홈으로 돌아오면 바로 0이다.
- **효과**: 타석 보정 edge에 `(타자 팀 단계 − 투수 팀 단계) × 한 칸 크기`를 더한다. 지금 `pa.ts`의 `batIsHome ? homeEdge : −homeEdge` 자리를 그대로 바꾼다. 원정 타자는 불리, 원정 투수가 던질 때는 홈 타자가 유리 — 투수 쪽 효과는 이 식으로 저절로 생긴다. 수비·주루·투구 수에는 주지 않는다 (지금 홈 이점도 타석 보정에만 있다. 넣으면 "지금 엔진과 같은 결과" 검증이 깨진다).
- **보이는가**: 보인다. 일정·연고지 표로 정해지는 공개 규칙이라 숫자와 사유를 그대로 보여도 숨은 능력 규칙과 상관없다 (3장).

- 좋은 점: 규칙이 한 줄로 설명된다. 날마다 같은 일정이면 같은 값 (재현·QA 쉬움). 지금 일정 생성기(P15)는 3연전 묶음이 없이 날마다 상대가 바뀌는데, 안 A는 "어제 어디 있었나"를 보지 않으므로 이 일정의 비현실성에 휘둘리지 않는다.

### 1.3 안 B: 팀 여독 (구단 단위, 누적 상태)

- **값**: 여독 점수(0 이상, 소수)를 구단마다 들고 다니고, 그날 컨디션 = 원정 기본 −1(원정일 때) − 여독 단계(여독 점수를 정수로 내림, 최대 −3).
- **올리는 것**: 원정 경기 하루마다 거리 단계만큼 (안 A의 0·1·2), 전날과 다른 도시로 옮겨 경기하면 +0.5 (임시값).
- **빠지는 것**: 홈 경기일 −1, 휴식일 −2, 0 아래로 안 내려감 (임시값).
- **효과·보이는 것**: 안 A와 같다.
- 좋은 점: "긴 원정길 끝에 지친다", "휴식일 뒤 회복"이 보인다.
- 한계: **지금 일정에는 3연전 묶음과 이동일이 없다** (날마다 상대가 바뀌고 같은 상대와 홈·원정이 번갈아 바뀐다, `season.ts` `generateSchedule`). 이 일정에서는 거의 날마다 도시를 옮기므로 여독이 실제보다 크게 쌓인다. 안 B는 일정 개편(3연전·월요일 휴식, M3 임시 규칙) 뒤에야 뜻이 있다. 상태가 생기지만 일정만으로 정해지므로 저장 없이 개막부터 다시 계산할 수 있다 (5장).

### 1.4 안 C: 선수 단위 그날 컨디션 (한 칸에 모두 합침)

- **값**: 선수마다 그날 값 하나 = 팀 원정 단계(안 A) + 이벤트·코치·캠프 경기력 + 숨은 능력 '기복'의 그날 값 + 야수 체력(11단계) 손해.
- 좋은 점: 화면에 "오늘 컨디션" 하나로 보일 수 있다.
- 한계: ① 기복의 그날 값과 야수 체력을 합친 숫자를 보이면 숨은 능력 '기복'의 크기가 경기마다 새어 나간다 (4.5 숫자 비공개 규칙과 부딪친다). 숨기면 원정 단계까지 안 보여 사용자 결정("원정팀 기본 −1")이 화면에서 사라진다. ② 야수 체력·기복·이벤트는 각자 원인·기간·대상이 달라 한 숫자로 합치면 무엇 때문에 나빠졌는지 알 수 없다. ③ 선수마다 날마다 값이 생겨 검증·QA가 어렵다. **추천하지 않는다.**

## 2. 원정 기본 −1과 거리 감소의 크기를 정하는 방법

### 2.1 원칙

- 목표 승률을 억지로 맞추지 않는다 (경기 엔진 2 6장 12단계). 홈 승률은 **보고하는 지표**이고 맞춤 대상이 아니다.
- 한 칸 크기(edge)는 시대마다 따로 정하지 않는다. 하나의 값을 정하면 시대별 차이는 구단 수·연고지 배치(거리 단계 평균)에서 저절로 생긴다.

### 2.2 실제 자료로 알 수 있는 것과 없는 것

- **연도별 실제 홈 승률** (무승부 제외, `public/data/seasons/*.json` 구단별 홈 성적 합): 1982~2026 평균 0.529, 해마다 표준편차 0.023.
  한 해 경기 수가 240~720경기라 해마다 표본 오차가 약 ±0.02~0.03이다. 해마다 퍼짐 대부분이 표본 오차이고, 1985년 0.459도 평균에서 표본 오차의 약 2.5배라 우연과 가리기 어렵다. **해마다 비교는 뜻이 작고 시대 묶음으로 본다.**

| 시대 묶음 | 실제 홈 승률 (경기 수 가중) |
|---|---:|
| 1982~1990 | 0.540 |
| 1991~2000 | 0.538 |
| 2001~2010 | 0.518 |
| 2011~2019 | 0.529 |
| 2020~2026 | 0.519 |

- **거리 효과**: 구단-시즌 373개(1982~2026)에서 "그 구단이 다른 구단 연고지까지 가는 평균 거리"와 "홈 승률 − 원정 승률"을 견주면 100km당 +0.0035, 표준오차 약 0.012 (경기 수 가중, 대략 계산). **자료로 거리 효과가 있는지조차 가릴 수 없다.** 경기 단위 자료(투구 단위 2023~2026, 약 2,100경기)로 거리 구간별 원정 승률을 내도 구간마다 약 700경기라 구간 사이 차이의 표준오차가 약 0.027로, 한 칸(승률 1%p 안팎 예상) 크기를 가리지 못한다.
- 결론: 거리 감소의 크기는 **설계로 정하는 임시값**이다. 자료는 "전체 홈 승률이 크게 어긋나지 않는지" 확인하는 데만 쓴다.

### 2.3 한 칸 크기를 정하는 안

| 안 | 한 칸 크기 | 2015~2026 평균 원정 edge | 뜻 |
|---|---|---|---|
| ① 지금 홈 이점과 같게 | 0.013 | 약 0.026 (평균 −2.0단계) | 거리 감소가 지금 홈 이점 위에 얹힌다. 리그 홈 승률이 지금(시뮬 0.53 안팎)보다 꽤 올라간다 |
| **② 평균 보존 (추천)** | 0.013 ÷ 기준 평균 단계 ≈ **0.0064** (임시값) | 0.013 (지금과 같음) | 리그 평균 홈 이점은 지금 맞춘 값 그대로, 가까운 경기는 홈 이점이 작아지고 먼 경기는 커진다. 기준 평균 단계는 **2015~2026 10구단 시대 연고지**로 한 번 계산해 고정한다 (시대마다 다시 맞추지 않는다) |
| ③ 자료 기울기 | 경기 단위 자료로 추정 | — | 2.2대로 표본이 모자라 추정값이 0 둘레에서 흔들린다. 추천하지 않는다 |

- 원정 기본 −1과 거리 단계는 같은 한 칸을 쓴다 (사용자 결정이 "기본 −1"이라 단계 단위로 말했으므로).
- ② 안에서는 시대가 바뀌면 평균 단계가 달라져 리그 홈 이점도 조금 달라진다 (예: 1982년 6구단 연고지 서울·대전·대구·광주·부산·인천). 이것은 맞춤이 아니라 결과이며 보고서에 시대 묶음 실제와 나란히 적는다.
- 한 칸이 승률로 몇 %p인지는 엔진을 돌려 잰다 (12-2, 측정 항목).

### 2.4 검증 조건

1. **컨디션 효과 0 = 고정 홈 이점 0**: 한 칸 크기 0으로 두면 `homeEdge = 0`인 지금 엔진과 같은 시드에서 완전히 같은 결과 (단위 테스트).
2. **지금 엔진 재현**: 한 칸 0.013, 거리 단계 끔(원정 −1만) → 지금 엔진(`homeEdge` 0.013)과 같은 시드에서 완전히 같은 결과. 원정 −1이면 원정 타자 edge −0.013, 홈 타자(원정 투수 상대) +0.013로 지금 식과 같다. `pa.ts`의 같은 자리에서 더해야 소수 계산 순서까지 같아진다.
3. **구조에서 오는 홈 승률 측정**: 한 칸 0으로 리그를 돌려 말 공격(끝내기) 구조만으로 생기는 홈 승률을 잰다 (지금은 홈 이점과 섞여 모른다).
4. **보고 (맞춤 아님)**: 시대 묶음별 홈 승률 실제 대 시뮬, 거리 단계별(원정 −1/−2/−3) 원정 승률이 단계가 깊을수록 낮은지, 경기당 득점 홈·원정 (지금 기준 원정 −4.6%).
5. 공통 기준: `npm test`, `npm run validate -- --years 2025,2019,2012 --seasons 100`에서 맞춤 지표 ±1%, 경기당 득점 ±5%.
6. 같은 시드 같은 결과, 저장 뒤 이어가기 = 끊지 않은 결과 (지금 테스트 그대로).

## 3. 플레이어에게 어떻게 보이는가 (정보 명세, 화면 모양은 UI 대개편에서)

- **어디에**: 그날 경기 정보(일정·경기 전 화면·직접 지휘 경기 시작 화면)에 양 팀의 원정 컨디션. 팀 화면·선수 상세에는 두지 않는다 (구단 단위 값이고 경기마다 다르므로).
- **무엇을**: 단계 숫자 + 사유. 예: "원정 컨디션 −3 (원정 −1, 이동 거리 325km −2)". 홈 팀은 "홈 경기"만. 공개 규칙이라 숫자를 보여도 된다. QA에서 재현 확인에도 쓴다.
- 다른 효과와 섞지 않는다: 이벤트·코치·캠프 경기력은 지금처럼 따로 보인다 (이름은 7장 2번). **숨은 능력 '기복'의 그날 값은 어디에도 보이지 않고, 원정 컨디션과 합친 "합계 컨디션"도 만들지 않는다** (합계를 보이면 기복 크기가 새어 나간다). 테스트: `tests/traits.test.ts`처럼 화면 소스에 기복 값이 나오지 않는지 검사하는 줄에 원정 컨디션 표시 코드가 기복을 읽지 않는지 더한다.
- 규칙 설명: 도움말 한 줄 "원정 팀은 컨디션 −1, 연고지 사이 거리가 100km 넘으면 −1, 250km 넘으면 −1 더" (값은 7장 결정대로).

## 4. AI 감독·AI 단장이 컨디션을 쓰는가

- **쓰지 않는다 (추천)**. 원정 컨디션은 한 구단 선수 모두에게 같은 크기로 들어가므로 누구를 내보낼지(라인업·로테이션·불펜)의 순서를 바꾸지 않는다. 쓸 이유가 없고, 쓰면 휴식 판단이 야수 체력(11단계)과 두 번 센다.
- AI 단장(트레이드·FA·방출 가치)도 쓰지 않는다. 연고지 거리는 구단마다 해마다 같아 선수 가치와 무관하다.
- 안 B(여독)를 고르면 "여독이 깊을 때 주전 휴식" 같은 판단을 생각할 수 있으나, 야수 체력과 겹치므로 그때도 넣지 않는 쪽을 추천한다.

## 5. 저장·재현

- **안 A**: 상태가 없다. 그날 일정(홈·원정 구단) + 그 해 거리 표로 정해진다. **난수를 쓰지 않는다** (줄기 불필요).
  - 그 해 거리 표는 시즌을 열 때 월드에 고정한다 (`World`에 구단 색인 × 구단 색인 km 표, `league/world.ts`가 `distance.ts`로 만든다. 엔진은 `league`를 가져다 쓰지 않으므로 표만 받는다). 시즌 저장(`SeasonSave`)에 이 표를 넣어 두면 시즌 도중 `data-src/연고지.csv`(좌표가 아직 임시값이라 고칠 일이 생긴다)를 고쳐도 진행 중 시즌 재현이 깨지지 않는다. 표는 10×10 안팎이라 작다. 시즌 저장 형식(`format`)을 올린다 (엔진 2는 예전 저장을 지우므로 변환은 만들지 않는다, 3.7.4).
  - 검증 도구(`validate_engine`·`longsim`·`engine2_baseline`)도 같은 월드 구성 함수를 거쳐 거리 표가 들어간다. 연고지가 없는 구단(표에 없는 계보, 판타지 모드 가상 구단)은 거리 단계 0 (원정 −1만), 데이터 검사에서 경고.
- **안 B**: 여독은 일정만으로 정해지므로 개막부터 그날까지 다시 계산할 수 있어 저장하지 않아도 된다 (연장 같은 경기 결과를 넣으면 시즌 상태 `PlayerStates` 옆에 구단별 값을 저장해야 한다 — 7장 6번에서 넣지 않기로 하면 필요 없음).
- 조작 기록(`GameAction`): 새 조작 없음.

## 7. 사용자가 정할 것

1. **정의 안**: **A 팀 원정 컨디션 (추천)** / B 팀 여독 누적 / C 선수 단위 합계.
   이유: A는 사용자 결정("원정팀 기본 −1 + 거리")을 그대로 옮기면서 상태·난수·저장이 없고, 지금 일정(3연전 없음)에서도 뜻이 맞다. B는 일정 개편 없이는 여독이 과하게 쌓이고, C는 숨은 능력 '기복'이 새어 나간다.
2. **이름**: **새 값을 "원정 컨디션"(줄여 "컨디션")으로 부르고, 이벤트·코치·캠프·판타지 효과는 화면에서 "경기력"으로 통일 (추천)** / 새 값을 "여독"처럼 다른 이름으로 부르고 "컨디션"은 이벤트 쪽에 남김.
   이유: 사용자가 새 값을 "컨디션"이라 불렀고, 이벤트 선택지 문구는 이미 "팀 경기력"이다. 바꿀 문구는 판타지 모드(`fantasy/effects.ts`·`gameday.ts`·`press.ts`·`free.ts`)와 캠프 설명의 "컨디션" 몇 군데.
3. **한 칸 크기 정하는 방법**: **② 평균 보존 (추천, 한 칸 ≈ 0.0064, 임시값)** / ① 한 칸 = 0.013 (거리만큼 홈 이점이 더 커짐) / ③ 자료 기울기.
   이유: 자료로 거리 효과를 가릴 수 없으므로(2.2) 지금 맞춘 리그 평균 홈 이점을 지키고 거리로 나눠 주는 쪽이 리그 지표를 덜 흔든다. 목표 승률 맞춤이 아니라 한 번 정해 고정한다.
4. **거리 구간**: **0~99km 0 / 100~249km −1 / 250km 이상 −2 (추천, 임시값)** / 150km마다 −1 (0~149 0, 150~299 −1, 300~ −2).
   이유: 추천 구간은 수도권끼리(27~36km)·영남끼리(36~88km)를 0으로 묶고, 수도권 ↔ 영남·호남(234~330km)을 대부분 −2로 둔다. 2026년 0·−1·−2가 26·36·28쌍으로 고르게 나뉜다 (150km 단위는 40·34·16쌍).
5. **같은 도시·같은 구장 원정 (LG·두산 잠실, 서울 구단끼리)**: **원정 기본 −1 그대로 (추천)** / 같은 도시면 0.
   이유: 사용자 결정 문장("원정팀 기본 −1")을 예외 없이 따르면 규칙이 한 줄이다. 실제 같은 구장 더비의 홈 승률은 확인하지 못했다.
6. **연장·더블헤더·연전·이동일·휴식일**: **컨디션에 넣지 않는다 (추천)** / 넣는다 (안 B 꼴).
   이유: 연장·연투는 투수 피로·혹사지수(4단계·4.6)가, 연전·연장의 야수 피로는 야수 체력(11단계)이 이미 선수 단위로 센다. 컨디션에 또 넣으면 두 번 센다. 더블헤더는 지금 일정에 없다.
7. **일정 개편 (3연전 묶음·월요일 휴식·이동일)**: **12단계 밖에서 따로 기획 (추천)** / 12단계에 함께.
   이유: 일정 개편은 시즌 길이(지금 9월 초 종료)·가을야구 날짜·투수 휴식·결과 전체를 바꾸는 큰 일이라 컨디션 단계에 묶으면 검증이 섞인다. 안 A는 일정 개편이 없어도 성립한다.
8. **시대별 이동 사정 (옛날 이동이 더 힘들었다는 배율)**: **넣지 않는다 (추천)** / 넣는다.
   이유: 근거 자료가 없다 (교통 사정 변화는 확인하지 않은 기억값). 시대 묶음 홈 승률 차이(1980~90년대 0.54, 2000년대 뒤 0.52)는 보고만 하고 맞추지 않는다.
9. **화면 표시**: **단계 숫자 + 사유 (추천)** / 말로만 ("먼 원정").
   이유: 공개 규칙이고 숨은 능력이 섞이지 않으므로 숫자를 숨길 까닭이 없다. 숫자가 있으면 QA 재현에도 쓴다.
10. **가을야구**: **정규시즌과 같은 규칙 (추천)** / 중립.
    이유: 지금 가을야구도 홈 구장에서 치른다 (`league/postseason.ts`). 실제 한국시리즈 중립 구장 경기가 있었는지는 확인하지 못했다 (확인되면 그 해만 중립으로 바꿀 수 있다).
