# 정규시즌 일정 개편 기획안

> **v1 — 사용자 결정 반영 (2026-10-22).** 9장 결정 10개와 10.8 양대 리그 결정 3개가 모두 정해졌다 (결정 기록: `결정기록.md` "일정 개편 기획안 결정"·"양대 리그 포스트시즌"). 코드는 아직 고치지 않았다. 8장 단계 하나가 개발 카드 하나다.
> 바탕: 사용자 결정 (2026-10-22, "당연히 바꿔야지") — 정규시즌 일정을 실제처럼 (연전 묶음, 월요일 휴식, 올스타 휴식, 우천 순연, 실제 개막·종료 시기). 1982~2026 어느 해로 시작해도 그 해 모양을 따르고, 2027년 이후는 2026년 모양을 따른다. 경기 엔진 2와 따로 하는 작업이다.
> 자료: 웹 조사(잼쨩, 2026-10-22, 이하 "조사값"). 자료집 "제도연표"로 확인하기 전 값이다. 양대 리그 포스트시즌·동률·올스타·연전 구성은 잼쨩 2차 조사(2026-10-22, 위키백과·나무위키·당시 신문 회고, 이하 "양대 리그 조사값")다. 팀당 경기 수와 구단별 홈·원정 성적은 시즌 자료(`public/data/seasons/*.json`, 자료집 확인)에 있다.

## 0. 요약

- **지금**: 원형 대진을 섞어 하루 한 경기씩 놓고 6경기일마다 하루를 비운다 (`src/engine/season.ts` `generateSchedule`, 엔진 2 기획안 P15). 달력은 "3월 24일 이후 첫 화요일" 개막에 그 날짜부터 하루씩 센다 (`src/game/calendar.ts`). 같은 상대와 연전이 없고, 올스타 휴식·우천·국제대회 중단이 없어 시즌이 9월 초에 끝난다 (CLAUDE.md M3 임시 규칙).
- **바꿀 것**: 연도별 일정 규칙 표(새 CSV → `public/data/schedule.json`)를 두고, 시드로 정해지는 **연전 단위 일정 생성기**를 엔진에 새로 만든다. 실제 일정 자료는 쓰지 않고 모든 해를 규칙으로 만든다 (결정 9). 날씨도 개막 때 같은 시드로 미리 굴려 **우천 취소·순연·더블헤더·잔여 경기**까지 한 번에 정하고, 화면에는 그날까지 알려진 일정만 보인다. 날씨 확률은 임시값으로 시작한다 (결정 1).
- **경기 중 비 (결정 4)**: 경기 전 취소에 더해 **강우 콜드·노게임(5회 성립 규정)**을 이번에 넣는다 (4.7). 서스펜디드(중단 뒤 이어 하기)는 엔진 2 18단계(경기 중 저장)와 함께 한다.
- **날짜 색인은 지금처럼 "개막일부터 센 달력 날짜"**로 둔다. 휴식일·올스타 휴식·국제대회 중단도 빈 날로 들어가므로, 날짜 차이로 계산하는 피로 회복·재등록 10일·부상 기간은 그대로 달력 날짜가 된다.
- **저장 (결정 5)**: 시즌 저장에 실제 일정을 넣고 시즌 저장 `format`을 올린다 (2 → 3). **예전 저장은 못 쓴다** — 엔진 2 때처럼 브라우저의 예전 칸을 지우고 한 번 알린다. 예전 생성기·예전 달력은 남기지 않는다 (6장).
- **1999·2000 양대 리그 (결정 3, 10장)**: 이 두 해만 드림·매직 양대 리그로 한다 (확정 규칙 "단일 시즌으로 통일"의 예외, 2026-10-22 사용자 결정). 리그 나눔은 시즌 자료의 `league` 칸(자료집)에서 해마다 계산하고 저장하지 않는다. 일정(1999 같은 리그 20·다른 리그 18), 리그별 순위, 리그를 건너는 포스트시즌(각 리그 1·2위, 교차 플레이오프, 조건부 준플레이오프)을 바꾼다.
- **코로나 2020·2021 (결정 6)**: 일정 모양(늦은 개막·중단·빽빽한 일정·더블헤더·월요일 경기)만 이 기획. 9회 무승부는 엔진 2 14단계, 무관중 수입은 재정 쪽.
- **국제대회 (결정 7)**: 리그가 멈춘 기간만 일정에 넣는다. 대표팀 차출 결장은 병역 혜택과 묶어 나중에 따로 기획한다.
- **2027년 이후 (결정 8)**: 2026 모양 고정 (3월 넷째 토요일 개막, 3연전, 월요일 휴식, 7월 둘째 토요일 올스타, 144경기). 미래 규칙이 바꾸는 항목만 따라간다.
- **규칙 경계**: 연장·무승부(2020 더블헤더·월요일 경기 9회 포함)는 엔진 2 14단계, 더블헤더 특별 엔트리(+1·+2)와 1군 등록은 엔진 2 13단계가 맡는다. 이 기획은 그 규칙이 쓰일 **경기(더블헤더·월요일 경기)를 만든다.** 일정과 컨디션은 묶지 않는다 (컨디션 C안: 원정 감소 없음). 연전·더블헤더 피로는 투수 피로·야수 체력·혹사지수가 맡는다.

- 확인할 자료가 있다: 시즌 자료의 구단별 `home` 성적(승-무-패)을 더하면 그 해 홈 경기 수가 나온다 (예: 2025 한화 44-2-27 = 73, LG 41-1-29 = 71, 조사값 "홀수 해 한화 홈 73"과 맞음). 생성기 검사(7장)에서 1982~2026 모든 해를 이 값과 견준다. 우천 취소된 경기가 다른 구장으로 옮겨진 경우가 있어 몇 경기 차이는 허용한다 (임시값 ±2).

### 2.4 데이터 자리

`meta.json`의 `rules`는 엔진 규칙(최대 이닝·엔트리) 칸이라 한 해 한 줄의 긴 표를 넣기 어렵다. **새 CSV**로 둔다.

- 원자료: `data-src/일정규칙.csv` (한 해 한 줄 + `2027~` 줄). 열: `연도, 구단수(검사), 팀당경기, 상대별, 연전틀, 개막일, 종료참고, 종료참고2(갈림), 쉬는기간(MM-DD~MM-DD:사유;…), 올스타일, 실제올스타경기수, 가을시작, 순연, 더블헤더금지(MM-DD~MM-DD;…), 미편성(팀당), 잔여발표, 2연전시작, 경기중비, 확인, 출처, 비고`. `실제올스타경기수`는 개막 알림의 "게임은 단순화" 문구에만 쓴다 (게임은 늘 1경기, 결정 10). `경기중비`는 4.7의 코드.
- 만들기: `python tools/build_data.py --schedule-only` → `public/data/schedule.json` (`--traits-only`·`--military-only`와 같은 방식). 선수 구성 지문(`rosterFingerprint`)에 들어가지 않는다.
- 검사(`tools/validate_data.py`): 팀당경기 = 시즌 자료 `games`, 상대별 × (구단 − 1) = 팀당경기 (1999는 묶음별), 날짜 형식, 쉬는 기간이 개막 뒤, 개막이 토요일이 아니면 경고(2020만 허용), `확인`이 `조사값`·`출처 갈림`·`확인`·`미확인` 중 하나.
- 엔진에는 `World.schedule`(그 해 한 줄)로 들어간다 (`world.ts`·`ratings.ts`가 `rules`처럼 붙인다). 자료 없는 해(2027~)는 `2027~` 줄에서 날짜를 계산한다.
- 확인 상태: 지금은 모두 `조사값`(출처 갈림 해는 `출처 갈림`). 자료집 "제도연표"로 옮겨 확인하는 일은 리그 규칙 변경 기획안 결정 1처럼 엔진 2 14단계 때 같이 하고 `확인` 열만 고친다. 개막 알림("올해 달라지는 규칙")에서 일정 항목(경기 수·연전·올스타 휴식·더블헤더)을 보일 때도 이 표를 읽는다.

## 3. 일정 만드는 방법

### 3.1 실제 일정 자료를 쓰지 않고 규칙으로 만든다

**결정 9: 실제 일정 자료는 쓰지 않고 모든 해를 규칙으로 만든다** (시작 연도 포함). KBO 공식 사이트는 자동 수집하지 않는 방침이고, 다른 곳의 경기별 일정 자료는 약관·라이선스를 확인하지 않았다. 같은 시드면 같은 일정이다. 실제 일정 자료를 넣는 길은 만들지 않는다 (입력 모양만 날짜별 [홈, 원정] 목록으로 단순하게 둔다).

### 3.2 단계

새 파일 `src/engine/schedule.ts` (순수 함수, 난수는 `Rng`만). 입력: 구단 수와 계보, 그 해 규칙 줄, 지난 시즌 순위(개막 홈), 시드. 출력: `SchedulePlan` (3.4).

1. **달력 칸**: 개막일부터 날짜를 놓고, 쉬는 기간·월요일을 빼고, 연전 틀의 요일 규칙으로 날짜를 연전 칸(길이 1~4)으로 묶는다. 개막 2연전, 올스타 뒤 4연전(`S33F`), 2연전기(`S33L2`의 후반기)도 여기서 칸 길이로 정해진다.
2. **대진 돌림**: 원형 대진 한 바퀴(구단 수가 홀수면 휴식팀 하나)를 칸마다 하나씩 쓴다. 칸 길이가 섞이는 틀(`W82`·`W83`·`T3W2`·`S33-9`·`S33L2`)은 바퀴마다 칸 길이 배정을 돌려서 상대별 합이 2.1의 구성(예: 3×4 + 2×2)이 되게 한다. 바퀴 순서는 시드로 섞는다 (지금 생성기와 같은 방식).
3. **상대별 맞추기**: 칸이 다 차면 상대별 경기 수를 센다. 모자란 경기(19차전 해의 1경기, `S33F`의 1차전씩)는 **잔여 경기 목록**으로 보낸다. 1999는 같은 리그 바퀴(3라운드)와 다른 리그 바퀴(4라운드)를 따로 돌려 20·18을 칸으로 채운다 (10.3). 넘치는 일은 생기지 않게 칸 수를 계산한다 (넘치면 검사 실패).
4. **홈·원정**: 연전 하나는 한 구장. 같은 상대와는 연전마다 홈을 번갈아 두고, 홀수 차전·잔여 경기의 홈은 2.2의 격년 규칙으로. 한 팀이 원정 연전을 연달아 몇 번까지 하는지는 조사값이 없다 → **3연속 원정 연전까지** (임시값). 이동 거리는 일정에 넣지 않는다 (컨디션 C안에 원정 감소가 없고, 실제 편성 원칙도 조사되지 않았다).
5. **개막 홈**: 2015년부터 지난 시즌 상위 5팀 (2.2). 그 전은 시드.
6. **본 일정 끝 → 잔여 경기 자리**: 잔여 경기는 본 일정 마지막 칸 뒤에 둔다. 2015년부터는 "잔여 경기 일정 발표일"(8월 하순, 임시값 8월 20일 또는 본 일정 마지막 3주 전 중 늦은 날)에 우천 순연분과 함께 다시 짠다 (4.4).
7. **검사**: 상대별 경기 수, 팀당 홈·원정, 팀당 경기 수, 월요일 경기 없음(어린이날 제외), 하루에 한 팀 한 경기(더블헤더 제외). 실패하면 시드에 꼬리를 붙여 다시 만든다 (`schedule/2`, 최대 20번, 실패하면 오류 — 테스트에서 1982~2027 모든 해 × 50시드가 실패 없이 만들어지는지 본다).

### 3.3 시대별 모양 확인 (계산)

- 2026: 15차전 × 9팀 = 135경기 = 3연전 45칸 = 22.5주 + 올스타 6일 → 3월 28일 개막이면 본 일정이 9월 초에 끝나고, 잔여 9경기 + 우천 순연(팀당 평균 약 13경기, 4.1)이 9월 말~10월 초에 들어간다. 조사값 종료일(10월 7일·12일)과 같은 범위다.
- 1991~1998: 18차전 = 3연전 6바퀴 × 7칸 = 42칸 = 21주 + 올스타 → 4월 초 개막이면 본 일정이 9월 초에 끝나고 우천 잔여 경기까지 9월 중순. 조사값(9월 18~29일)과 같은 범위.
- 1986~1990: 2연전 9바퀴(108경기)·10바퀴(120경기) × 7칸 = 63·70칸, 하루 한 팀 휴식이라 팀마다 54·60칸을 뛴다. 주 3칸이면 21·23.3주 → 3월 말 개막이면 9월 초·중순 + 전후기 공백·올스타 → 조사값(9월 8일~10월 6일)과 같은 범위.
- 1982: 80경기를 주 3~4경기로 → 3월 27일 개막이면 9월 중순. 목요일을 몇 주 여는지는 생성기가 날짜에 맞춰 정한다 (종료 참고일보다 늦어지면 목요일을 더 연다, 임시 규칙).

계산이 참고 종료일과 2주 넘게 어긋나는 해는 표의 날짜나 틀을 다시 본다 (7장 검사).

### 3.4 일정 자료 모양

```ts
interface SchedulePlan {
  opening: string;            // 'YYYY-MM-DD' 개막일 (달력의 기준)
  days: ScheduledGame[][];    // 실제로 치르는 일정 (우천 반영 뒤). 빈 배열은 경기 없는 날
  planned: ScheduledGame[][]; // 개막 때 발표한 일정 (잔여 경기 미편성분은 없음)
  cancels: [day: number, home: number, away: number, toDay: number][]; // 경기 전 우천 취소와 옮긴 날
  remainingFrom: number;      // 잔여 경기 일정 발표 날짜 색인 (없으면 -1)
}
interface ScheduledGame {
  home: number; away: number;
  dh?: 1 | 2;                 // 더블헤더 몇 차전
  rainInning?: number;        // 경기 중 비: 이 회(1~8)를 마치고 멈춘다. 5 미만이면 노게임, 5 이상이면 강우 콜드 (4.7)
}
// cancels의 노게임은 [day, home, away, toDay, 1]처럼 끝에 1을 붙인다 (경기 전 취소는 0 또는 생략)
```

## 4. 우천 취소·순연

### 4.1 얼마나 자주

- **결정 1 (2026-10-22): 임시값으로 시작한다.** 기상청 평년값은 나중 (약관 확인 뒤 잼쨩 조사로 월별 확률만 바꿀 수 있게 4.2의 월별 표를 한 곳에 둔다).
- 기준(조사값, 야구나라): 2015~2025 10구단 한 시즌 평균 65.0경기 취소 (42~85), 720경기의 약 9.0%. "순수 우천만 세는지 미세먼지·폭염 포함인지"에 따라 2023년 수가 66~72 / 85로 **출처 갈림** → 평균 65를 목표로 한다. 이 65는 경기 전 취소와 노게임(4.7)을 합친 수로 본다 (노게임도 다시 치르는 경기라서, 임시 해석).
- 2014년 이전은 자료가 없다 → **경기당 같은 비율** (임시값). 구장 수가 적어도 날씨는 같다는 가정.
- 돔 구장(`league/ballparks.ts`의 `dome`: 고척 2016~, 잠실 돔 2032 예정)은 취소 없음. 그래서 2016년부터는 같은 날씨에서도 취소 수가 조금 줄어든다.

### 4.2 날씨 모형 (임시값)

- 날마다 **전국 비** (월별 확률) + **구장별 비** 두 단계: 장마·태풍은 여러 구장이 같이 쉬고, 국지성 비는 한 구장만. 전국 비 날에 구장마다 취소 확률이 높고, 아닌 날은 낮다. 월별 비율(3~4월 낮음, 6월 하순~7월 장마 높음, 8월 태풍 중간, 9월 중간, 10월 낮음)과 두 단계 비율은 **임시값**이고, 전체 평균이 4.1 목표(65경기)에 맞게 한 계수로 맞춘다.
- 실제 월별 강수일 자료(기상청 평년값 등)는 나중 (결정 1). 그때 월별 표만 바꾸고 전체 계수를 다시 맞춘다.
- 난수 줄기: 시즌 뿌리에서 `weather`를 갈라 날짜·구장마다 `weather/<날짜>/<구장 계보>`로 뽑는다. 일정이 바뀌어도(순연으로 그 날 경기가 생겨도) 그 날 그 구장 날씨는 같다. 경기 난수(`g/…`), 하루 난수(`days`), 이벤트 난수와 섞이지 않는다.
- 한 구장의 하루 날씨는 셋 중 하나: **맑음** / **경기 전 취소** / **경기 중 비** (몇 번째 반 이닝 뒤에 멈추는지까지 같은 줄기에서 뽑는다, 4.7). 더블헤더 날은 1·2차전을 따로 뽑는다 (`weather/<날짜>/<구장>/2`). 서스펜디드는 넣지 않는다 (결정 4).

### 4.4 정하는 때: 개막 때 미리 굴린다

- 날씨는 플레이어 조작과 상관이 없다. 그래서 **개막 때 시즌 전체를 날짜 순으로 미리 굴려** 취소·순연·잔여 경기까지 담은 `days`를 한 번에 만든다. 경기 결과를 보지 않으므로(순위와 무관한 편성) 결과가 일정에 영향을 주지 않는다.
- 미리 정해 두면 저장 뒤 이어 하기·조작 기록 재현이 일정 쪽에서는 늘 같다 (6장). 하루씩 그때 굴리는 방식과 결과가 같고, 그 방식보다 저장 상태가 적다.
- 대신 화면과 AI가 미래를 보지 않게 막아야 한다 (4.5).

### 4.5 보이는 것

- 화면은 `Season.knownSchedule(day)`만 읽는다: 지난 날은 `days`(실제), 오늘부터는 `planned` + 오늘까지 생긴 순연 + (발표일이 지났으면) 잔여 경기 일정. 우천 취소는 그날 아침 소식으로 낸다 ("○○ 대 ○○ 경기는 우천으로 취소됐습니다. 9월 23일에 다시 치릅니다." — R1의 시즌 끝 잔여는 "추후 편성").
- 잔여 경기 일정 발표일에 소식 한 줄 ("잔여 경기 일정이 발표됐습니다. 우리 팀 남은 경기 ○경기, 마지막 경기 10월 4일").
- 일정 화면에 "우천 취소"·"더블헤더 1·2차전"·"순연" 표시. `GameShell`의 남은 경기 수도 알려진 일정 기준.
- AI 판단(트레이드·엔트리)은 지금도 일정을 보지 않는다. 앞으로도 `days`의 미래를 읽지 않는다 (테스트로 확인할 수는 없어 리뷰 항목).

### 4.6 더블헤더가 엔진에 주는 일

- `simulateDay`는 그날 경기를 1차전 묶음 → 2차전 묶음 순서로 돈다. 2차전 전에 1차전 피로·기록을 반영하고 엔트리를 다시 본다 (`refreshActive`).
- 피로: 같은 날 두 번 던지면 `fatigueDay`가 같아 회복 없이 쌓인다 (지금 계산 그대로). 1차전 선발은 `lastStartDay`가 오늘이라 2차전에 못 나온다. 야수 휴식 확률(`restChance`)은 2차전에서 높이는지 엔진 2 체력 단계에서 정한다 (지금은 같은 값, 임시).
- 특별 엔트리 +1(2020)·+2(2021~)는 엔진 2 13단계(1군 등록·출장 구분)에서. 그 전에는 더블헤더에도 평소 엔트리.
- 이닝 규정(2020 더블헤더·월요일 경기 9회, 2021~ 더블헤더 연장 없음)은 엔진 2 14단계 연표가 `dh`·요일을 보고 정한다. 이 기획은 경기에 `dh` 표시와 날짜만 넘긴다.
- 직접 지휘(`GameAction` `command`)는 날짜만으로 경기를 가리킨다. 더블헤더 날 우리 경기가 둘이 되므로 경기 키(`game`, 엔진 2 기획안 3.7.2)가 먼저 있어야 한다. 엔진 2가 아직 안 했으면 이 기획 6단계에서 `dh` 번호를 붙인다.
- 박스스코어·경기 로그는 지금처럼 경기마다 하나 (`GameLog`에 `dh?` 추가).

### 4.7 경기 중 비: 강우 콜드·노게임 (결정 4)

**결정 4 (2026-10-22)**: 경기 전 취소에 더해 강우 콜드·노게임(5회 성립 규정)을 이번에 넣는다. 서스펜디드(중단 뒤 다른 날 이어 하기)는 엔진 2 18단계(경기 중 저장)와 함께 하고, KBO 서스펜디드 규정은 그때 조사한다 (잼쨩).

| 항목 | 규칙 | 근거 |
|---|---|---|
| 정식 경기 성립 | 5회를 마치면 성립 | 사용자 결정 문장("5회 성립 규정"). 홈팀이 앞선 5회초 끝 성립, 성립 연도 변화는 **조사 필요** |
| 멈추는 때 | **온 이닝(말 공격까지) 끝에서만** 멈춘다: 1~8회 중 하나 | 임시 규칙. 실제 비는 아무 때나 오지만, 초 공격 끝에 멈추면 점수 되돌림·서스펜디드 규정이 걸리고 정식 경기 성립이 점수에 따라 갈린다. 온 이닝 끝에서만 멈추면 노게임 여부가 점수와 무관해 개막 때 미리 굴릴 수 있다 (4.4) |
| 노게임 (1~4회 끝) | 기록을 모두 지운다. 경기는 경기 전 취소와 같은 순연 규칙(4.3)으로 다시 편성한다 | 피로·부상은 남긴다 (실제로 던지고 뛰었으므로, 임시 규칙). 1군 연차(`activeDays`)는 그날을 센다 |
| 강우 콜드 (5~8회 끝) | 그때 점수로 끝. 기록은 그대로 남는다 | 동점이면 그 해 무승부 규칙. 무승부가 없는 해(2008, 엔진 2 14단계 연표)의 실제 처리는 **조사 필요**, 그때까지 무승부 (임시) |
| 기록 규정 | 콜드 경기의 완투·완봉·세이브·규정 이닝 셈 | 엔진 2 14단계 기록 규정이 정한다. 그 전에는 지금 기록 계산 그대로 (던진 만큼) |
| 가을야구 | 날씨 없음 | 임시 규칙 (포스트시즌 강우 콜드 폐지(2025) 같은 연표는 서스펜디드 때) |
| 연도 | 1982~ 모든 해 같은 규칙 (`경기중비` = `C5`) | 임시. 조사 결과가 다르면 CSV 코드만 바꾼다 |

- **빈도 (임시값)**: 구장 하루 날씨가 비일 때 경기 전 취소 : 경기 중 비 = 5 : 1, 경기 중 비의 멈추는 회는 1~8회 균등. 노게임까지 합친 다시 치르는 경기가 4.1 목표(시즌 65경기)에 맞게 4.2의 전체 계수를 정한다. 실제 강우 콜드·노게임 수는 조사값이 없다 → **잼쨩 조사 항목** (2015~2025 시즌별 강우 콜드·노게임 수). 조사값이 오면 비율만 맞춘다.
- **엔진**: 한 경기 함수(`game.ts`, 엔진 2에서는 해결기 위 경기 진행)가 `rainInning`을 받아 그 회 끝에서 멈추고 결과에 `rain: 'cold' | 'nogame'`을 단다. 노게임이면 `Season`이 기록·순위에 넣지 않고 피로·부상만 반영한다. 직접 지휘 중인 경기도 같은 회에서 멈추고 "비로 경기가 중단됐습니다 (강우 콜드 / 노게임)"를 띄운다.
- **미리 보이지 않게**: `knownSchedule`은 `rainInning`을 빼고 준다 (4.5). 화면·AI는 경기가 멈추기 전에 알 수 없다.
- **소식**: "○○ 대 ○○ 경기는 6회 강우 콜드로 끝났습니다 (3:2)", "… 3회 노게임이 선언됐습니다. ○월 ○일에 다시 치릅니다".

## 6. 저장·재현

### 6.1 시즌 저장

**결정 5 (2026-10-22): 예전 저장은 못 쓰게 한다.** 엔진 2 때처럼 지우고 새로 시작한다. 앞 초안의 "진행 중 시즌만 예전 일정으로 끝까지" 방식은 버렸다.

- `SeasonSave.format`을 **2 → 3**으로 올리고 `schedule: { opening, days, planned, cancels, remainingFrom }` 칸을 **꼭 있는 칸**으로 더한다. 경기는 `[홈, 원정, dh, 비 회]` 숫자 묶음으로 줄여 약 5KB.
- 불러오기: 형식 3만 받는다. 형식 2는 "일정 개편 이전 저장이라 쓸 수 없습니다 (정규시즌 일정이 바뀌어 이어 할 수 없음)"로 막는다 (지금 형식 1을 막는 `Season.restore`의 줄과 같은 꼴). 세션 저장(`GameSaveV2`)은 오프시즌에도 막 끝난 시즌의 `SeasonSave`를 담고 있어서 시즌 형식만 올려도 모든 예전 저장이 막힌다 → **세션 `format`은 올리지 않는다** (엔진 2 16단계의 세션 형식 3과 번호가 겹치지 않는다).
- 브라우저 정리: 게임을 열 때 저장 칸(자동 저장 `auto:*`·예전 `auto` 칸·수동 칸)을 훑어 시즌 형식이 3 미만인 칸을 지우고 "정규시즌 일정이 바뀌어 예전 저장을 지웠습니다"를 한 번 알린다. 엔진 2 2단계가 이 처리(예전 형식 칸 지우기·알림)를 먼저 만들었으면 기준 형식만 올려 같이 쓰고, 아직 없으면 이 기획에서 만든다 (`src/game/storage.ts`). 파일로 내보낸 저장을 불러오면 같은 문구로 거절한다.
- 예전 생성기(`generateSchedule`)와 예전 달력(3월 24일 뒤 첫 화요일)은 **지운다** (남겨 둘 저장이 없다).
- 진행 중 시즌의 일정은 저장의 `schedule`을 그대로 쓴다. 데이터를 다시 만들어(`build_data.py --schedule-only`) 규칙 표가 바뀌어도 진행 중 저장은 막지 않고 다음 시즌부터 새 표를 쓴다.

### 6.2 재현과 끊김 없음

- 일정은 개막 때 시드와 규칙 줄로 정해지고 시즌 중에 바뀌지 않는다 (4.4). 그래서 `tests/game.test.ts`의 "저장 뒤 이어 돌림 = 끊김 없이 돌림", "`refresh`를 끼워도 같음"이 일정 쪽에서 깨지지 않는다. 이어 하기는 저장된 `days`를 쓰고, 끊김 없는 쪽은 같은 시드로 만든 `days`를 쓰므로 둘이 같아야 한다 → 테스트에 "저장의 `schedule` = 새로 만든 일정" 단언을 더한다.
- 우천 취소 소식·잔여 경기 발표 소식은 그날 진행 때 `SchedulePlan`을 읽어 낸다. 진행 순서와 무관하게 같은 날 같은 소식이다.
- 조작 기록(`GameAction`)의 `day`는 지금처럼 달력 색인. 더블헤더 날 우리 경기 지휘는 경기 키가 필요하다 (4.6).
- `GameSession.replay`: 새 게임은 같은 결과. 업데이트 전에 시작한 게임은 저장이 지워지므로 재현할 일이 없다 (결정 5).
- 강우 콜드·노게임은 개막 때 정해진 `rainInning`을 따르므로 이어 하기·재현에서도 같은 회에서 멈춘다 (4.7).
- 환경 맞춤(`calibrate`)의 예비 시즌도 같은 생성기를 쓴다 (우천 포함. 리그 비율에는 영향 없고 시간만 조금).

## 10. 양대 리그 (1999·2000)

### 10.1 결정과 범위

- 사용자 결정 (2026-10-22, 9장 결정 3): 1999·2000년은 **드림·매직 양대 리그**로 한다. CLAUDE.md·기획서의 확정 규칙 "리그 방식은 단일 시즌으로 통일"을 이 두 해만 바꾼다 (전·후기 리그 1982~1988은 그대로 단일 시즌).
- 바꾸는 것: 리그 나눔, 1999 일정의 상대별 경기 수, 리그별 순위표·게임차, 리그를 건너는 포스트시즌, 순위를 문장으로 쓰는 곳 (10.6).
- 바꾸지 않는 것: 경기 엔진, 선수 능력, 트레이드(리그가 달라도 된다), FA·드래프트 같은 오프시즌 제도. 2001년부터는 지금처럼 단일 리그.
- 1982년이나 그 전 해에 시작해 자동으로 1999년에 들어가도, 1999·2000년에 바로 시작해도 같은 규칙이다.

### 10.2 리그 나눔

시즌 자료(`public/data/seasons/1999.json`·`2000.json`)의 구단마다 `league` 칸에 자료집 "리그" 열 값이 이미 들어 있다 (`tools/build_data.py`가 넣는다. 코드에서는 아직 읽지 않는다). 1999는 잼쨩 조사값과 같다.

| 해 | 드림 | 매직 | 근거 |
|---|---|---|---|
| 1999 | 두산, 롯데, 현대, 해태 | 삼성, 한화, LG, 쌍방울 | 자료집 (시즌 자료 `league`) + 조사값 일치 |
| 2000 | 현대, 두산, 삼성, 해태 | LG, 롯데, 한화, SK | 자료집 (시즌 자료 `league`). 조사값에는 2000 소속이 없다 |

- 2000년에 삼성과 롯데가 리그를 맞바꿨고, 쌍방울을 승계한 SK가 매직에 들어갔다 (자료집 기준. 리그를 다시 짠 이유는 조사하지 않았다).
- **계산 방법**: 새 함수 `divisionsFor(store, year, teams)` (`src/league/eras.ts`). 그 해 시즌 자료에서 `league` 값이 두 가지인 해만 쓰고, 게임 구단을 계보(`franchise`)로 자료 구단과 맞춰 `[드림 구단 색인들, 매직 구단 색인들]`을 돌려준다. 다른 해는 `null`(단일 리그). 연도를 코드에 박지 않고 자료를 따르므로, 자료집에 다른 해가 생겨도 같은 길로 들어온다.
- 게임 구단이 자료 구단과 하나라도 안 맞으면(자유 모드의 구단 변화, 가상 창단 등) `null`로 단일 리그 (임시 규칙). 개막 소식에 "올해는 단일 리그로 진행합니다" 한 줄.
- 리그 → 월드(`world.ts`)에서 `World.divisions?: { names: ['드림', '매직']; teams: [number[], number[]] }`로 붙인다. 엔진은 받은 묶음만 쓰고 자료를 읽지 않는다 (엔진 순수성 유지).
- **저장하지 않는다**: 연도 + 리그 상태의 구단 계보 + 자료로 언제든 같은 값이 나온다. 결산(`beginOffseason`)의 구단 변화(쌍방울 → SK 승계)는 같은 색인에서 계보만 바뀌고, 다음 해 월드를 만들 때 새 해 자료로 다시 계산하므로 순서 문제가 없다.
- 남는 위험: 진행 중인 1999 저장이 있는데 데이터를 다시 만들어 `league` 칸이 바뀌면 순위 나눔이 바뀐다. 선수 구성 지문에는 안 걸린다. 자료집을 고칠 때만 생기는 일이라 막지 않는다 (임시 판단, 검사 경고로 알림).

### 10.3 일정

| 해 | 같은 리그 (3팀) | 다른 리그 (4팀) | 팀당 | 연전 틀 | 근거 |
|---|---|---|---|---|---|
| 1999 | 20차전 (홈 10·원정 10) = 3연전 4번 + 2연전 4번 | 18차전 (홈 9·원정 9) = 3연전 6번 | 3×20 + 4×18 = 132 | `S33-99` | 양대 리그 조사값 (경인일보 1999-01-19 "동일리그 20차전·타리그 18차전, 후반기 2·3연전 혼합" 등), 시즌 자료 `games` 132·홈 66 일치 |
| 2000 | 19차전 | 19차전 | 7×19 = 133 | `S33` | 조사값 ("양대리그이나 대진은 전 구단 19차전 균등") |

**1999 짜는 법** (양대 리그 조사값을 규칙으로, 세부 배치는 임시 규칙)

- 바퀴 두 종류: **같은 리그 바퀴** = 리그마다 4팀 원형 대진 3라운드 (두 리그가 같은 날 리그 안 경기, 하루 4경기), **다른 리그 바퀴** = 드림 4팀 × 매직 4팀 교차 4라운드.
- 칸 수: 3연전 칸 = 다른 리그 24라운드(6바퀴) + 같은 리그 12라운드(4바퀴) = 36라운드 = 18주. 2연전 칸 = 같은 리그 12라운드(4바퀴) = 2연전 주(화·수 / 목·금 / 토·일) 4주. 모두 22주 + 올스타 휴식.
- 배치: 전반기(올스타 전)는 3연전만. **다른 리그 경기는 같은 리그 경기보다 약 2주 먼저 끝나고, 마지막 2주는 같은 리그 2연전만** (조사값). 나머지 2연전 주 2주는 후반기에 시드로 놓는다 (임시 규칙).
- 개막 토·일 2연전(1999-04-03 토요일)은 같은 리그 2연전 라운드 하나로 센다 (임시 규칙. 그만큼 후반기 2연전 라운드가 하나 준다).
- 홈: 같은 리그 쌍은 3연전 홈 2·원정 2 + 2연전 홈 2·원정 2 = 10·10. 다른 리그 쌍은 3연전 홈 3·원정 3 = 9·9.
- 우천 순연: 조사값 "다음 날 바로 더블헤더 또는 휴식일 편성"은 R1과 같다.
- 3.3 계산과 맞춤: 4월 3일 개막, 22주 + 올스타 → 본 일정이 9월 초에 끝나고 우천 순연까지 9월 중순. 참고 종료일 9월 19일과 같은 범위.

**2000**

- 리그 나눔이 일정에 닿지 않는다. 남는 1경기의 홈은 2.2의 홀짝 규칙을 쓰되, 시즌 자료와 견줘 리그마다 두 팀이 홈 67이 되게 한다 (임시 규칙. 자료: 두산·삼성·롯데·한화 67).
- 조사값에 2000년도 "3연전 및 후반기 2연전 혼합"이 있으나 상대별 구성이 없고 출처가 1999 기사뿐이라 반영하지 않는다 (`S33` + 잔여 1경기, 임시).

- 생성기 입력: `World.divisions`를 3.2의 입력 "구단 수와 계보"에 더한다. 일정 저장(6.1)은 그대로 (리그 나눔은 넣지 않는다).

### 10.4 순위

- `Season.standings()`는 지금처럼 **통합 승률 순**으로 둔다. 지명·외국인·2차 드래프트 순서, 방출 시장, 재정 정산, 꼴찌 판정처럼 "리그 전체에서 몇 위"가 필요한 곳은 이 값을 그대로 쓴다 (10.6, 10.8 결정 2).
- 새 `Season.divisionStandings(divs)`: 리그마다 정렬한 두 목록. 승률은 **승 ÷ (승 + 패), 무승부 제외** (양대 리그 조사값. 시즌 자료로도 `pct` 0.598 = 76 ÷ 127로 같다). 다른 해의 승률 계산식은 그 해 규칙(리그 규칙 변경 기획안 D5~D7, 엔진 2 14단계)을 따른다.
- **동률 규칙 (1999·2000, 양대 리그 조사값)**: 승률 → ① 동률 구단 사이 상대 전적 다승 → ② 동률 구단 사이 맞대결 득점 → ③ 전년도 정규시즌 순위. 타이브레이커 경기는 없다. 리그 안 순위, 통합 순위, 준플레이오프 판정(10.5)에 모두 쓴다. 상대 전적·득점은 시즌 경기 기록(`log`, 저장에 있음)에서 세고 저장 칸을 더하지 않는다. 전년도 순위는 리그 상태의 지난 시즌 기록(시작 연도는 시즌 자료의 지난해 `pct` 순). 다른 해는 지금 `rankTeams`(승률 → 승수 → 색인) 그대로.
- 게임차: 같은 리그 1위 기준 (`gamesBehind(리그 1위, 팀)`). 통합 탭에서는 통합 1위 기준.
- 주의 — 시즌 자료의 `rank`는 "최종 순위(KBO 표기)"이고 1999·2000은 **리그별 최종 순위(가을야구 결과 반영)**다. 그래서 1999 드림은 롯데(0.591)가 1, 두산(0.598)이 2로 적혀 있다. 정규시즌 리그 순위는 `pct`로 다시 정렬해야 한다 (`realYearbook`이 이미 그렇게 한다).
- 순위 문장: 새 도우미 `rankText(session, team)` → 단일 리그 해는 "3위", 양대 리그 해는 "드림 2위" (10.8 결정 2). 홈·`GameShell` 머리·시즌 끝·진행 요약·기자회견·기사·소식이 이것을 쓴다.

### 10.5 포스트시즌

**규칙** (양대 리그 조사값, 2026-10-22 사용자 결정. 1999·2000 같음)

| 라운드 | 대진 | 길이 | 홈 순서 |
|---|---|---|---|
| 준플레이오프 (조건부) | 한 리그 **3위 승률 > 다른 리그 2위 승률**이면 그 둘. 승리 팀이 2위 자리를 이어받는다 | 3전 2선승 | 1-1-1: 1차전 2위 팀 홈, 2차전 3위 팀 홈, 3차전 중립 (실제 잠실) |
| 플레이오프 ×2 (교차) | **드림 1위 대 매직 2위**(또는 그 자리 준플레이오프 승자), **매직 1위 대 드림 2위**(또는 그 자리 준플레이오프 승자) | 7전 4선승 | 2-3-2: 리그 1위 홈 1·2·6·7차전, 상대 홈 3·4·5차전 |
| 한국시리즈 | 두 플레이오프 승자 (같은 리그 두 팀일 수 있다, 2000 현대·두산) | 7전 4선승 | 통합 승률이 높은 팀이 상위. 두 팀 모두 서울 구단이 아니면 **2-2-3** (상위 1·2, 하위 3·4, 5·6·7차전 잠실 중립), 서울 구단이 있으면 **2-3-2** |

- **준플레이오프 조건은 1999·2000 두 해 모두 적용**한다 (사용자 결정, 다수 설). 2000년 신설설(일부 신문 회고)이 있어 규칙 표·연표에 **출처 갈림**을 남긴다. 실제 1999년은 매직 2위 한화(0.554)가 드림 3위 현대(0.535)보다 높아 열리지 않았고, 2000년은 드림 3위 삼성(0.539) > 매직 2위 롯데(0.504)로 열렸다.
- 승차 제한은 없다: 1993~1998 단일 리그의 "3·4위 승차 3.5경기 이상이면 준플레이오프 생략"은 1999년에 없어졌다 (양대 리그 조사값). 리그 규칙 변경 기획안 D9의 끝 해를 1998로 고친다 (16단계 문서).
- 승률이 같으면 10.4의 동률 규칙으로 가려 3위가 앞서면 연다 (조사값: 진출 경쟁 동률도 같은 순서).
- 두 리그에서 동시에 조건이 채워지는 일은 없다: 드림 3위 > 매직 2위 ≥ 매직 3위 이고 매직 3위 > 드림 2위 ≥ 드림 3위 이면 모순이다. 그래서 준플레이오프는 많아야 하나.
- **중립 경기**: 엔진에 중립 구장이 없다 → 상위 팀 홈으로 친다 (임시 규칙). 화면·소식에는 "잠실 중립 경기"로 적는다. 엔진 2 12단계(원정 거리 컨디션)가 들어오면 중립 경기 처리(두 팀 모두 원정 등)를 그때 정한다.
- **서울 구단 판정**: 그 해 홈 구장(`league/ballparks.ts`)이 잠실인 구단 (1999·2000 두산·LG).
- **출처 갈림**: 2000 준플레이오프 1차전 홈은 다수 기록이 롯데(2위 팀, 사직 대신 마산), 일부 요약은 삼성. 다수 설(2위 팀 1차전 홈)을 쓴다.
- 쉬는 날: 라운드 사이 휴식은 지금 `REST_BETWEEN`(임시값) 그대로.

**지금 구조에 얹는 법** (`src/league/postseason.ts`)

- 지금은 `seeds`(순위 순) 한 줄로 **사다리**(가장 낮은 두 시드부터, 이긴 팀이 다음 상위 시드)를 만들고, 시리즈가 늘 하나씩 열린다 (`openSeries`, `currentSeries`). 교차 플레이오프는 같은 라운드에 시리즈가 둘이라 사다리로 나타낼 수 없다.
- `PostseasonState`에 선택 칸 `bracket?: BracketNode[]`를 더한다.
  ```ts
  type Slot = { seed: number } | { winnerOf: number };      // seeds의 몇 번째, 또는 bracket 몇 번째 시리즈의 승자
  interface BracketNode { round: SeriesRound; high: Slot; low: Slot; rule?: RoundRule } // rule: 이 노드만의 길이·홈 순서
  ```
  와 `seedLabels?: string[]` ("드림 1위", "매직 2위" 등, 화면·소식용). `bracket`이 없으면 지금 사다리 그대로 (다른 해는 바뀌지 않는다). 시즌 저장 형식은 4단계에서 이미 3으로 올라가 있어 형식을 더 올리지 않는다 (선택 칸).
- 홈 순서: `RoundRule.homePattern`의 칸에 "중립" 값을 더한다 (`true` 상위 홈 / `false` 하위 홈 / `'n'` 중립 = 상위 홈으로 치고 표시만 중립). 1999·2000의 준플레이오프(3전 2선승, `[true, false, 'n']`), 플레이오프(7전 4선승, `[true, true, false, false, false, true, true]`), 한국시리즈(2-2-3 `[true, true, false, false, 'n', 'n', 'n']` / 2-3-2) 규칙은 노드의 `rule`로 준다. 리그 규칙 변경 기획안 D10~D12 연표(엔진 2 14단계)가 먼저 생기면 그 연표에 1999·2000 줄로 넣는다.
- 대진 만들기: 새 함수 `bracketFor(year, divisions, divisionStandings, 통합 순위)`. 규칙 위 표대로 준플레이오프 판정 → 노드 목록 (준플레이오프가 있으면 4노드, 없으면 3노드). 판정 근거를 대진 소식에 쓴다 ("드림 3위 삼성(0.539)이 매직 2위 롯데(0.504)보다 승률이 높아 준플레이오프를 치릅니다").
- 동시에 열리는 시리즈: 시리즈마다 다음 경기 날짜를 두고(`SeriesResult.nextDay`), `playNextGame`은 열린 시리즈 중 날짜가 가장 이른 경기(같으면 노드 순서)를 하나 치른다. 두 플레이오프가 같은 날 열리면 같은 날짜에 두 경기가 있다. 한 시리즈가 먼저 끝나면 다음 노드는 양쪽 슬롯이 다 정해질 때 연다.
- 바뀌는 함수: `startPostseason`(대진이 있으면 bracket으로), `openSeries`(열 수 있는 노드 모두), `currentSeries`(첫 번째 열린 시리즈, 기존 호출부 호환) + `openSeriesList`(화면용), `playNextGame`, `stillAlive`(지금 반복문 그대로 동작), `resultOf`(우승·준우승 = 한국시리즈 노드). `seriesMvp`·`postseasonLines`·`MVP_ROUNDS`는 그대로.
- 난수: 지금 키는 `ps/<라운드>/<그 시리즈 경기 번호>`라 같은 라운드에 시리즈가 둘이면 **키가 겹친다** (두 플레이오프의 1차전이 같은 난수). `bracket`이 있을 때만 `ps/<라운드>.<노드 번호>/<경기 번호>`를 쓰고, 사다리 키는 그대로 둔다 (다른 해 결과 불변). 경기마다 따로 줄기라 진행 순서와 무관하게 같다.
- 화면(`Postseason.tsx`): 대진표를 사다리 한 줄 대신 두 갈래로 그린다 (준플레이오프 → 두 플레이오프 나란히 → 한국시리즈). 진행 버튼은 "다음 경기"가 지금처럼 한 경기씩.
- 대진 소식(`openPostseason`): `seedLabels`로 "드림 1위 두산 대 매직 2위 한화, 매직 1위 삼성 대 드림 2위 롯데" 꼴.
- 2000 일정 참고: 정규시즌이 10월 13일(시드니 올림픽 중단 뒤)에 끝나고 한국시리즈가 11월 (조사값). 시작일은 지금처럼 정규시즌 끝 + 3일.
