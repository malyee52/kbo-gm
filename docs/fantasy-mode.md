# 판타지 모드 (AI 이야기) 설계

2026-10-12 사용자 요청: "ai api 키를 사용해 ai와 소통하며 유동적으로 진행하는 게임을 모드로".

## 0. 사용자 결정

| 질문 | 답 |
|---|---|
| 모드 성격 | **실제 리그 + AI 이야기**: 지금 KBO 리그·선수 그대로, AI가 대화·사건·기사를 즉석에서 만들어 시즌 흐름이 유동적으로 바뀐다 |
| AI 역할 | 사건 생성, 자유 대화, 기사·해설, **게임 수치에 영향**. 큰 변화도 가능 (예: 소설처럼 플레이어만 미래를 아는 회귀물) |
| 실존 선수 규칙 | **유지**: 실존 선수에게 지어낸 발언·사생활·물의를 붙이지 않는다 (CLAUDE.md "지켜야 할 규칙") |
| AI 제공자 | **여러 제공자 중 선택**: Claude(Anthropic), OpenAI, Gemini |

## 1. 지켜야 할 것

- **실존 선수**: AI에게 주는 지시문에 규칙을 넣고(발언 인용·인물평·사생활·부상 사유·물의 금지, 기록 사실만), AI가 고른 효과도 실존 선수에게는 중립 효과(컨디션 ±, 휴식)만 받는다. 대화 상대는 가상 인물(구단 직원·기자·에이전트·구단주 측근)과 게임이 만든 가상 선수뿐이다.
- **숨겨진 특수능력**: AI에게 주는 게임 상황(`context.ts`)에 넣지 않는다 (`tests/traits.test.ts`와 같은 원칙).
- **재현**: AI 답은 매번 달라 시드로 재현되지 않는다. 그래서 AI가 만든 글과 효과는 **조작 기록(`GameAction` 'ai')에 그대로 남기고**, 재현·불러오기 때는 AI를 다시 부르지 않고 기록된 효과를 적용한다. 버그 재현 정보(`reproInfo`)도 그대로 쓸 수 있다.
- **API 키**: 서버가 없는 게임이라 플레이어 본인 키로 브라우저에서 바로 부른다. 키는 그 브라우저(localStorage)에만 두고 **저장 파일·내보내기·재현 정보에는 넣지 않는다**. 화면에 "키는 이 브라우저에만 저장, 요금은 키 주인에게" 안내.
- **효과의 크기**: AI가 수치를 바꾸는 것은 정해 둔 효과 목록(화이트리스트)과 상한 안에서만 (`effects.ts`). AI가 목록 밖 효과나 상한 넘는 값을 내면 잘라 낸다.

## 3. 단계

1. **기반**: AI 설정(제공자·키·모델·연결 시험·모델 목록), 새 게임 옵션 "판타지 모드", 조작 기록 'ai', AI 기사(이번 주·시즌 정리, 글만)
2. **회귀자**: 새 게임 옵션 "회귀자 (미래를 안다)". 기억 노트(시작 뒤 실제 시즌의 순위·우승·주요 선수 기록, 자료가 있는 해까지), 역사 분기 표시("원래는 SK 우승"), AI가 회상·분기 서술
3. **자유 대화**: 가상 인물과 채팅 (단장 보좌, 수석 스카우트, 담당 기자, 에이전트, 구단주 측근). 대화 결과로 효과(신뢰·팬·컨디션 등) 제안 → 플레이어가 받아들이면 적용
4. **AI 사건**: 상황 맞춤 이벤트(글 + 선택지 + 선택지별 효과)를 AI가 만든다. 기존 무작위 이벤트와 같은 멈춤·답하기 흐름
5. **큰 변화**: 여러 주에 걸친 이야기 줄기(아크), 큰 효과 묶음 (구단주 교체·대형 투자·리그 개편 제안 등, 효과 목록 확장)

## 4. 제공자 메모 (2026-10-12)

- Anthropic: `POST https://api.anthropic.com/v1/messages`, 헤더 `x-api-key`, `anthropic-version: 2023-06-01`, 브라우저에서 부를 때 `anthropic-dangerous-direct-browser-access: true`. 기본 모델 `claude-sonnet-5-5`
- OpenAI: `POST https://api.openai.com/v1/chat/completions`, 헤더 `Authorization: Bearer`. 기본 `gpt-5.5` (OpenAI 변경 기록의 권장)
- Gemini: `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`, 헤더 `x-goog-api-key`. 기본 `gemini-3.6-flash` (공식 안내 예시, 확인 필요)
- 모델 이름은 자주 바뀌므로 설정에서 직접 고치거나 "모델 목록 불러오기"(각 제공자의 모델 목록 API)로 고른다
- Vertex AI (2026-10-12 사용자 요청): Google Cloud 서비스 계정 JSON 파일로 연결 (`src/fantasy/vertex.ts`). 브라우저에서 JWT(RS256)를 Web Crypto로 서명해 `oauth2.googleapis.com/token`에서 접속 토큰을 받는다(메모리에 50분).
  Gemini는 `publishers/google/models/{model}:generateContent`, 이름이 claude로 시작하는 모델은 `publishers/anthropic/models/{model}:rawPredict`(본문 `anthropic_version: vertex-2023-10-16`). 지역 기본 global (지역 없는 호스트 `aiplatform.googleapis.com`).
  JSON 안의 비밀 키가 브라우저에 저장된다: 권한을 "Vertex AI 사용자"로만 준 계정을 권한다. 브라우저에서 토큰 서버·Vertex 주소를 막지 않는지는 아직 실제 키로 확인하지 못했다

## 5. 삽화 (NovelAI, 2026-10-12)

사용자 결정: **가상 인물·장면 + 구단 색 느낌**, **글마다 자동**.
- 글(기사 등) → 글 AI가 영어 그림 태그(가상 인물·장면만, 이름·글자·로고 금지) → `sanitizeTags`로 한글·선수 이름·로고·글자 태그 제거 → 구단 색 유니폼 태그(`colorWord`)와 기본·금지 태그 → NovelAI
- 글 AI 키가 없으면 글 종류별 정해 둔 장면 태그
- 그림은 게임 상태에 영향이 없어 조작 기록에 남기지 않고, 이 브라우저 IndexedDB `kbo-gm-art`에 WebP로 줄여 둔다 (저장 파일·내보내기에 없음)
- 브라우저 호출 허용(CORS) 확인 (2026-10-12): image.novelai.net, oauth2.googleapis.com, aiplatform.googleapis.com, api.openai.com, generativelanguage.googleapis.com, api.anthropic.com 모두 허용

## 6. 3~5단계 (2026-10-13, 사용자 "5단계까지 알아서 진행해")

- **효과** (`src/fantasy/effects.ts`): 구단주 신뢰·팬 만족도·자금·관중률·선수단/선수 컨디션·휴식·잠재력(가상 선수만). 출처별 상한: 대화 < 사건 < 이야기 절정.
  AI는 선수를 이름으로 말하고, 우리 구단 선수 이름으로 id를 찾는다 (없거나 겹치면 버림). 목록 밖·실존 선수 잠재력·절정 전 큰 변화는 버리고 이유를 남긴다
- **대화** (3단계, `cast.ts`·`ai.ts chatTurn`): 가상 인물 5명(단장 보좌·수석 스카우트·담당 기자·선수 에이전트·구단주 비서실장, 이름은 게임 시드로 정해지고 실존 선수 이름과 겹치지 않는다).
  대화마다 이야기 기록에 남고, AI가 제안한 효과는 "받아들인다/넘긴다" 선택지가 된다 (받아들여야 적용)
- **사건** (4단계, `makeEvent`): 글 + 선택지 2~3개(선택지마다 효과). 정규시즌에 진행 버튼을 누르고 나면 마지막 사건 뒤 10일이 지났을 때 AI가 저절로 만든다 (AI 키가 있을 때, 답을 기다리는 사건이 없을 때). 홈에 알림
- **이야기 줄기·큰 변화** (5단계): 사건마다 AI가 이야기 줄기(제목·줄거리·절정·끝)를 이어 간다. 줄기가 세 번째 사건을 넘으면 절정 상한(arc)과 큰 효과를 쓸 수 있다:
  구단주 교체(신뢰 새로 시작), 큰 자금(±100억), 전설적인 가상 유망주 입단(다음 개막, `addFantasyProspect`)
- 재현: 글·선택·효과·줄기는 모두 조작 기록('ai'·'ai-off'·'ai-choice'·'ai-choice-off')으로 남아 저장·불러오기·재현에서 같다 (`tests/fantasy-story.test.ts`)

## 7. 협상: 설득이 게임 판단을 바꾼다 (2026-10-13 사용자 요청)

"AI를 설득한다면 더 좋은 조건으로 트레이드가 되는 등 게임 시스템을 건드리는 것이 가능해야 한다" (`src/fantasy/negotiate.ts`)
- AI는 단장의 말을 읽고 태도(stance −3~+3)만 정한다. 실제 판단은 게임 엔진이 하고, 태도가 엔진 값에 들어간다 (말만으로 터무니없는 거래가 되지 않게)
- **트레이드**: 트레이드 화면의 "설득하기" (상대 구단 운영팀장, 가상 인물). AI에게는 제안 내용·상대 구단 성향·엔진 평가(받아들일 만함/조금 모자람/많이 모자람)를 준다.
  태도 × 2런 = 호감(±6런, 14일) → `ai/trade.ts evaluateTrade`의 이득에 더한다. 다시 협상하면 바뀐다(쌓이지 않음), 같은 구단은 3일 쉬었다
- **FA·비FA 다년 계약**: "에이전트 설득" → 그 선수 요구액 할인(태도 + 최대 10%)·할증(태도 − 최대 6%). FA는 우리 제시의 수락 기준에, 다년 계약은 요구 연봉에 들어간다. 선수마다 오프시즌 한 번
  - (2026-10-29 사용자 결정 "말한 대로 이행") 에이전트가 대사로 구체 조건(연봉·기간)에 동의하면 답의 `deal`(억 원, 기간)로도 받는다 (`agreedDeal` 효과 → `fantasy.deals`).
    그 연봉 이상·그 기간으로 낸 FA 제시는 요구액·다른 구단 제시와 관계없이 반드시 계약하고, 비FA 다년 계약은 그 기간의 요구 연봉이 합의 연봉이 된다. 할인·할증 한도는 걸지 않는다.
    숫자가 아니거나 0 이하·최저 연봉 미만·100억 원 초과·우리 지출 상한 초과·기간 1~10년 정수 밖이면 버린다 (`sanitizeDeal`). 화면 설득 칸에 "합의 조건"과 그 조건으로 제시·계약하는 단추.
    (2026-10-29 사용자 "합의면 무시") 합의 조건 제시·다년 계약은 외부 FA 영입 한도·샐러리캡·계약금 자금·라운드 마감 재검사를 보지 않고, 외부 FA 영입 수에도 넣지 않는다.
    계약금이 자금 + 모기업 FA 지원 한도를 넘으면 자금이 0 아래로 내려가 시즌 결산의 긴급 지원(적자 보전, 구단주 신뢰 감소)으로 간다. 캡 초과는 개막 캡 제재를 평소대로 받는다.
    합의가 아닌 것: 기간이 다르거나 연봉이 낮은 제시, 다음 오프시즌(합의는 그 오프시즌만), 다년 계약 기간 범위 밖의 기간
  - 깎인(할증된) 우리 FA 제시는 깎기 전 값으로 다른 구단 제시와 견준다 (전에는 깎은 값 그대로 견줘 다른 구단에 늘 졌다)
- 결과는 이야기 기록(효과 tradeGoodwill·demandDiscount)으로 남아 재현된다

## 8. 자유 모드 (AI 진행, 2026-10-13 사용자 결정)

사용자: "기본 모드에 AI를 더하는 게 아니라 AI와 함께하는 완전 자유 모드". 결정: 자유 입력 + 기존 화면도 씀 / 바꿀 범위는 거의 전부 / 판타지(AI 보조)와 자유 모드 둘 다 둔다 / 설득·판정은 AI가 직접, 안전망 없음.
- 새 게임 "게임 모드": 기본 / 판타지 (AI 보조) / 자유 모드 (AI 진행). 자유 모드는 판타지의 기능(대화·사건·회귀자·삽화)을 모두 갖고, 판타지 화면 첫 탭이 **행동**
- **행동**: 무엇이든 글로 쓰면 게임 마스터(AI, `src/fantasy/free.ts`)가 판정·연기하고 결과 이야기와 조작(FreeOp)을 낸다. 조작은 이름 → id로 바꿔 이야기 기록에 남고 바로 적용된다 (판단 상한 없음, 값의 범위만)
  - move(우리·다른 구단 모두, 방출), create(가상 선수), ability(능력·잠재력 20~80 등급, 실존 선수 포함), contract, cash, teamCash(다른 구단), trust, fans, teamForm·playerForm·rest
  - 경기는 엔진이 치른다. 실존 선수에게 발언·사생활·물의를 붙이지 않는 규칙만 지킨다
- 트레이드 화면·FA 화면의 "설득하기"도 자유 모드에서는 게임 마스터가 직접 판정한다 (받아들이면 그 자리에서 성사)
  - FA 시장(FA 단계)의 선수에게 낸 move·contract는 그 자리에서 FA 계약으로 확정한다 (`Off.signFaDeal`, 보상·계약금은 보통 계약과 같고 외부 FA 한도·캡은 보지 않음). contract만 내면 우리 구단과의 합의. 전에는 FA 항목이 열린 채 남아 마감 때 다른 구단 계약·무적 선수로 덮였다 (2026-10-29)
- 시즌 중 새 선수: 개막 때 빈 자리(가상 선수 12명, 투수·야수 반씩, `openReserves`)를 월드에 소속 없이 넣어 두고, create가 하나를 채워 구단에 넣는다 (월드 크기를 바꾸지 않아 저장·불러오기·재현이 그대로). 결산 때 쓰지 않은 자리는 지운다. 오프시즌에는 리그에 바로 (`addFreePlayer`)
- 시즌 중 소속 이동은 Season.transfer + 재정 이동 기록(league.marketMoves), 리그 소속은 결산 때 따라간다. 능력 변경은 리그 선수와 월드 선수를 함께 바꾼다

## 9. AI 판정 7단계 (2026-10-13 사용자 요청)
