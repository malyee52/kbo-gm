### 0.2 사용자 결정 (바꾸지 말 것)

- 잠재력 규칙에 선수별 예외를 두지 않는다 (최원준 2026 .355·204안타도 같은 규칙, 고점 등급 약 63).
- 젊은 선수 성장 속도(2005 시작에서 2010년 리그 재능 실제 대비 +17%)는 사용자가 직접 플레이해 보고 정한다.
- 도전 시나리오 시놉시스: 시즌 선택 시놉시스(기획안 11장) 말투 + 실존 선수·감독 이름. 개막 전까지의 사실만, 마지막은 질문.
- 구단 배분은 난이도마다 고르게 맞추지 않는다.
- 잠재력·등급 기준표 (2026-10-12): 실제 기록의 시즌 가치(WAR 비슷한 값, 스탯티즈 눈금 맞춤, `tools/war.ts`) → 등급 = 40 + 5 × 승 (8승 이상 = 80).
  사용자가 "10승 = 80"으로 벌리려다 취소하고 **리그 수준 보정**을 두기로 했다: 1982 0.80 · 1983~85 0.85 · 1986~90 0.90 · 1991~97 0.93 · 1998~2008 0.96 · 2009~ 1.00
  (`engine/eras.ts leagueQuality`, 기록만으로는 리그 수준을 가려낼 수 없어 역사로 정한 표). 방식은 **A**(게임 가치 계산을 기준표에 맞추기):
  선발 기준 0.4(선발·구원 겸업 에이스), 시대별 선발 등판 수·투구 한계, 선발 대체 선수 수준·구원 가중 조정, 등급 환산을 기준표 눈금으로,
  고점·역사 재현 능력은 평균 회귀 절반(`seasonRegressScale` 0.5), 고점은 리그 수준을 시작 연도 기준으로 바꾼다.
  확인: `npx tsx tools/benchmark_peaks.ts > reports/peak-benchmark.md` (기준 대비 게임 잠재력 차이 평균 투수 −0.8·타자 0.0)

### 0.3 측정 결과 (2026-10-12, 역사 재현 기준)

- 시즌 도전 AI 운영 클리어 비율 (`tools/challenge_odds.ts --kind season --seeds 8`): 쉬움 평균 40%(평균 순위 2.4), 중간 38%(2.7), 어려움 6%(7.3).
  쉬움·중간이 비슷한 것은 중간 팀들도 실제로 강팀(절반이 정규시즌 1위)이었고 한국시리즈 패배가 운이었기 때문이라 그대로 둔다.
- 팀 승률 표준편차 1990~2026: 실제 0.080, 시뮬 0.064 (예측 기준 0.063). 득점 변동계수는 실제 0.091 / 시뮬 0.082로 비슷하고,
  실점 변동계수가 실제 0.097 / 시뮬 0.069로 좁다. 투수 안타·홈런 회귀를 줄여도 0.075까지만 올라 (잡음 안) 넣지 않았다.
  남은 차이는 기록이 없는 팀 수비 차이로 본다. 고치려면 실제 팀 인플레이 타구 처리율(투수 능력으로 설명되지 않는 몫)을 그 시즌 주전 야수 수비에 나눠 주는 방식이 후보다.

## 2. 작업 규칙 (사용자 결정·메모리)

- 한국어로 답하고 스스로를 "클짱"이라 부른다.
- **업데이트마다 바로 커밋·푸시하고 배포까지**:
  1. 브랜치 만들기 (`git checkout -b 이름`, main에서)
  2. 커밋 (끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`)
  3. `git push -u origin 이름`
  4. 브라우저(Chrome "Browser 1", GitHub 로그인됨. "Browser 2"는 로그인 안 됨)로 PR 만들고 병합. PR 본문 끝에 `🤖 Generated with [Claude Code](https://claude.com/claude-code)`
  5. 배포 확인: 배포 사이트의 `assets/index-*.js` 이름이 바뀌는지 curl로 본다 (GitHub API는 자주 rate limit)
  - main에 직접 푸시하지 않는다.
- PR 만들기 요령:
  - compare 페이지(`/compare/main...브랜치?expand=1`)에서 제목·본문은 JS로 넣고 `form.requestSubmit()`. 페이지가 안 넘어가도 PR이 만들어져 있는 경우가 많다: compare 페이지를 다시 열면 "View pull request" 링크가 보인다.
  - 병합: PR 페이지에서 "Merge pull request" 버튼 → "Confirm merge" 버튼을 JS로 클릭. 그 뒤 `git fetch`로 main 확인.
  - navigate 직후 javascript_tool이 "browser-internal URL" 오류를 내면 한 번 더 부르면 된다.
- **배포 사이트에서 게임하지 않는다.** 사용자와 같은 IndexedDB를 쓴다. 화면 확인은 로컬 dev 서버로 한다.
  - 띄우기: `npx vite --port 5179 --strictPort --host 127.0.0.1` (주소 `http://127.0.0.1:5179/kbo-gm/`)
  - 끝나면 PowerShell `Get-NetTCPConnection -LocalPort 5179`로 PID를 찾아 끈다.
- 실존 선수는 기록 사실만 쓴다 (부상 사유·사생활·인물평·지어낸 말 없음). 잘못으로 읽힐 일은 실명 없이.
- 긴 편집은 Python 스크립트를 job tmp 폴더에 써서 실행한다. bash heredoc에 한국어·백틱·작은따옴표가 섞이면 깨진 적이 있다.
- 균형을 건드리면 장기 진행으로 확인한다.
  - `npx tsx tools/flow_longterm.ts --seasons 20 --seeds diag-a,diag-b [--start 2005]`: 상위 270명 기여 합. 2026 시작 2045년이 시작 대비 -1~-3%면 정상.
  - 실제 자료 기준값(상위 270명): 2005 4300, 2010 4446, 2015 5612, 2020 5762.
  - 이 도구는 GameSession을 거치지 않는다 (코치·성향·AI 트레이드 빠짐).
- 시드에 기대는 테스트(`tests/owner.test.ts` 지금 m7-loop-10)는 엔진이 바뀌면 깨질 수 있다. 깨지면 시드를 바꾸고 주석에 이력을 적는다.
- 사용자 저장이 멈췄다고 하면: 붙여 준 재현 JSON(`opts`·`at`·`actions`)을 `GameSession.replay`로 돌려 재현하고, 테스트로 남긴다 (예: `tests/lineup-foreign.test.ts`).
