> 사용자가 고른 항목: 이벤트 멈춤/자동, 트레이드 제안만 따로(실제 제안일 때만), 1군 이탈 N일 이상, N연패, 트레이드 마감일, 육성선수 등록일.

> "시즌 끝까지 버튼은 그냥 진짜 시뮬레이션으로 넘겨 완전자동이야, 그 이외 버튼은 어떤걸 스킵하고 어떤걸 멈출지 하는 버튼을 만들어"

### 1.1 요구

1. **시즌 끝까지 = 완전 자동.** 무엇이 생겨도 멈추지 않는다.
   - 이벤트는 자동 선택. 지금도 첫 번째 선택지로 처리한다. 시즌 마지막 날 생긴 이벤트는 `answerEvent(0)`로 조작 기록에 남긴다.
   - 1군 선수 부상·이탈로도 멈추지 않는다. **지금은 멈춘다**: `GameShell.advance`가 `session.advance(…, !autoEvents, true)`로 부르고, `attention`이 생기면 멈춘다. 이걸 끈다.
   - 끝나면 진행 요약 창은 그대로 띄운다 (사용자가 요약 창을 원했다).
2. **하루·일주일·한 달 버튼**에는 무엇에서 멈추고 무엇을 건너뛸지 고르는 설정(토글)을 둔다. 예:
   - 이벤트: 멈춰서 직접 고르기 / 자동 선택(첫 번째 선택지)
   - 1군 선수 부상·이탈: 멈춤 / 건너뜀. 며칠 이상일 때만 멈출지도 고를 수 있으면 좋다. 지금은 `ATTENTION_DAYS` = 3.
   - 후보: 트레이드 제안 이벤트만 따로 멈춤, 연패(N연패)에서 멈춤, 마일스톤·신기록 기사에서 멈춤, 트레이드 마감 직전에 멈춤, 육성선수 등록 가능일(5월 1일)에 멈춤, 가을야구 진출 확정·탈락 때 멈춤 등.
     어떤 항목을 넣을지는 사용자와 먼저 정한다. 기본값은 지금 동작(이벤트·부상 멈춤)으로 둔다.

### 1.3 설계 제안

- **설정 저장 위치**: 멈춤 설정은 게임 결과를 바꾸지 않는 화면 편의 설정이다. 다만 이벤트를 자동으로 고르면 결과가 달라진다.
  - 자동 선택은 지금처럼 진행할 때 첫 선택지로 처리한다. 재현할 때도 같은 자리에서 자동 처리되므로 조작 기록이 필요 없다.
  - 그래서 설정 자체는 리그 상태에 넣지 않고 **브라우저 설정**(localStorage, try/catch)이나 세션 메모리에 둬도 된다. 저장 파일에 남기고 싶으면 `league`가 아닌 별도 필드로.
- **UI**: 진행 버튼 옆에 "⚙ 멈춤 설정" 작은 팝오버(체크박스). 또는 저장·설정 화면에 "진행" 섹션.
- **시즌 끝까지**: `advance(10000, …, true)`에서 `stopOnAttention`을 false로. 시즌 마지막 날 이벤트 자동 답 처리는 유지.
- 테스트: 설정별로 멈추는지와 재현이 같은지 (`GameSession.replay`).

## 2. 작업 규칙 (사용자 결정·메모리)

- 한국어로 답하고 스스로를 "클짱"이라 부른다.
- **업데이트마다 바로 커밋·푸시하고 배포까지**:
  1. 브랜치 만들기 (`git checkout -b 이름 origin/main`)
  2. 커밋 (끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`)
  3. `git push -u origin 이름`
  4. 브라우저(Chrome, GitHub 로그인됨)로 PR 만들고 병합
  5. Actions API로 배포 성공 확인 (`gh` CLI 없음)
  - main에 직접 푸시하지 않는다.
- PR 만들기 요령:
  - compare 페이지(`/compare/main...브랜치?expand=1`)에서 제목·본문은 JS로 넣는다. `HTMLInputElement` value setter + `input` 이벤트.
  - "Create pull request" 버튼은 ref 클릭이 자주 안 먹는다. 스크린샷으로 좌표를 보고 눌러야 한다.
  - "Merge pull request"도 ref 클릭이 안 먹으면 좌표로 누르고, "Confirm merge"는 ref로 누른다.
  - 성공 여부는 `curl https://api.github.com/repos/malyee52/kbo-gm/pulls?state=all` 로 확인한다.
- **배포 사이트에서 게임하지 않는다.** 사용자와 같은 IndexedDB를 쓴다. 화면 확인은 로컬 dev 서버로 한다.
  - 띄우기: `npx vite --port 5176 --strictPort --host 127.0.0.1`
  - 끝나면 `netstat`으로 PID를 찾아 끈다.
- 실존 선수는 기록 사실만 쓴다 (부상·사생활·인물평 문구 없음). 감독·코치는 실존 인물 이름만 쓰는데 자료가 없어 코치는 이름 없이.
- 긴 편집은 Python 스크립트를 job tmp 폴더에 써서 실행한다. bash heredoc에 한국어·백틱을 넣으면 깨진 적이 있다.
- 균형을 건드리면 장기 진행으로 확인한다.
  - `npx tsx tools/flow_longterm.ts --seasons 10 --seeds diag-a`: 상위270 기여합, 2035년 기준 약 6200~6500.
  - 단, 이 도구는 GameSession을 거치지 않는다. 그래서 코치·성향·AI 트레이드 같은 세션 기능은 빠진다.
