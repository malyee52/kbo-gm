## M3 첫 플레이 버전 — 완료 (2026-10-08)

한 팀을 골라 한 시즌을 끝까지 치를 수 있는 최소 게임.

완료 기준: 팀 선택부터 144경기 종료와 최종 순위 확인까지 막힘 없이 진행되고, 중간 저장과 이어하기가 된다.
결과: 자동 테스트(`tests/game.test.ts`)와 브라우저 수동 확인(2026 LG, 시작 → 엔트리 이동 → 시즌 끝까지 → 결과 → 자동 저장 불러오기) 통과.

- [x] 엔진을 하루 단위로 진행할 수 있게 바꾸기 → `Season` 클래스 (`src/engine/season.ts`). 바꾸기 전과 같은 시드의 결과가 완전히 같음을 해시로 확인
- [x] 팀 선택 화면 → `src/ui/StartScreen.tsx`
- [x] 선수단 화면: 1군과 2군 사이 엔트리 이동 (인원·외국인 한도 검사, AI 위임 전환)
- [x] 일정 진행: 다음 경기, 하루, 일주일, 시즌 끝까지
- [x] 순위표와 경기 결과 화면 (달력, 박스스코어는 플레이어 구단 경기만)
- [x] 선수 기록 화면 (선수 상세, 리그 부문별 순위)
- [x] 저장과 불러오기 (IndexedDB 자동 저장 + 3칸, JSON 파일 내보내기·가져오기)
- [x] 시즌 종료 결과 화면
- [x] 한 시즌 완주 테스트 케이스 작성과 실행 (17개)

화면 목록은 `docs/design.md` 13장. 플레이어 구단의 1군 엔트리는 플레이어가 정하고, 라인업과 투수 교체는 AI 감독이 한다.

M3에서 정한 임시 규칙 (근거 없이 정한 값, 나중에 확인):
- 개막일: 3월 24일 이후 첫 화요일, 월요일 휴식. 올스타 휴식·우천 순연 없음 → 9월 초에 시즌이 끝난다.
- 직접 정한 1군에서 뛸 수 있는 야수가 10명, 투수가 9명보다 적으면 2군에서 임시로 올린다 (`MIN_ACTIVE_*`).
- 1군 말소 뒤 재등록 제한 기간은 넣지 않았다 (규정 확인 필요).

M3에서 남긴 것:
- 포스트시즌 경기는 치르지 않고 진출권만 표시한다.
- 난이도 선택은 M7에서 시작 화면에 추가한다.
- 선수 상세의 통산 기록은 직전 3시즌만 보여준다 (브라우저가 그 범위만 불러옴).
- 라인업 배치가 포지션을 거의 고려하지 않는다 (예: 1루수가 유격수로 나옴). 수비 모델이 없어 `positionFit`이 가치 위주로 고르기 때문. 수비 모델과 함께 손본다.

## M4 트레이드와 AI 구단 — 완료 (2026-10-08)

완료 기준: 미리 적어 둔 악용 시나리오에서 AI 구단이 손해 보는 거래를 거절한다.

- [x] 선수 가치 함수 → `src/ai/value.ts`. 현재 능력(대체 선수 대비 런), 나이별 성장 추정(잠재력 모델 전 임시), 포지션 희소성. **연봉 부담은 연봉 자료가 없어 빠짐 (M5에서 추가)**
- [x] 구단 성향 판정: 우승 도전과 리빌딩 → `src/ai/trade.ts` (순위, 20경기 전에는 전력 순위, 주축 나이)
- [x] 트레이드 제안과 수락 규칙: 선수 가치 합이 아니라 트레이드 전후 구단 전력 차이로 판단. 요구안 묻기 포함
- [x] 트레이드 화면 → `src/ui/screens/Trade.tsx`
- [x] AI 구단의 엔트리 관리: 기존 자동 엔트리가 트레이드 뒤 바로 다시 짜도록 연결 (외국인 한도 포함, 테스트로 확인)
- [x] 악용 시나리오 목록 작성 → `docs/trade-exploits.md`
- [x] 시나리오별 테스트 실행

M4에서 정한 임시 규칙 (근거 없이 정한 값, 나중에 확인):
- 트레이드 마감 7월 31일 (실제 규정 날짜 확인 필요). 한쪽 최대 4명. AI 구단은 트레이드 뒤 야수·투수 18명, 포수 2명 이상을 남긴다.
- 나이별 연간 변화량, 성향별 시즌 가중치, 최소 이득(2런 또는 내주는 가치의 8%), 구원 투수 가중 1.3, 예비 선수 몫 15%.

M4에서 남긴 것:
- AI 구단끼리의 트레이드, AI가 먼저 플레이어에게 제안하는 기능은 없다.
- 제안 횟수 제한이 없어 수락선을 더듬어 찾을 수 있다 (`docs/trade-exploits.md`의 "막지 않은 것").
