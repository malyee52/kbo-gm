## 0. 요약

- 1·2차(틀, 브리핑 홈, 결정함, 기용 보드) 다음으로 **우선 화면 다섯**의 세부 배치를 정한다: 선수 상세, 경기 중계·박스스코어, 시즌 > 순위·기록, 영입 > 트레이드 작업대, 오프시즌 단계 화면 (2장).
- 다섯 화면은 **공통 부품**을 함께 쓴다: 등급 칸, 리그 평균 대비 표시, 용어 풀이, 표 부품(열 묶음·정렬·거르기), 상태 낱말, 짐작 문구 칸 (1.3). 공통 부품을 먼저 만들면 화면마다 같은 것을 다시 만들지 않는다.
- 곧 들어올 기능(능력치 v2, 엔진 2 수동 경기 A, 컨디션, 일정 개편, 규칙 알림)은 **자리만 먼저 만들고, 그 기능이 들어올 때 채운다**. 자리마다 "언제 채우나"를 적었다 (1.2, 각 화면의 "채우는 때").
- 지금 엔진이 세는데 화면에 없는 것: **투구 수** (`BoxPitcher.np`, `PitLine.np`). 박스스코어·선수 기록·등판 기록·기용 보드·다음 경기 카드·중계 점수판에 자리를 정했다 (2.2.4). 타자가 본 공 수는 기록 칸이 없어 엔진 쪽 작은 일이 필요하다.
- 트레이드는 지금 **AI가 받아들이면 그 자리에서 성사**된다(`session.proposeTrade`). 카드의 순서(협상 → 최종 검토)대로 하려면 "합의 → 확정" 단계가 필요하다. AI 판단은 난수 없이 결정적이라 엔진·재현을 바꾸지 않고 화면에서 만들 수 있다 (2.4, 7장 4).
- 공통 기능 넷(다른 구단 보기, 전체 검색, 관심 명단, 표 보기 저장)은 작업량·이점을 정리해 사용자 결정으로 넘긴다 (4장).
- 만드는 순서는 개발 카드 열한 장으로 나눴다. 엔진 2·능력치 v2·일정 개편·규칙 알림과 맞물리는 곳을 표시했다 (5장).

## 2. 우선 화면 다섯

와이어프레임은 데스크톱 1440×900(왼쪽 메뉴 184px 뺀 본문)과 휴대폰 390×844 기준이다. `[ ]`는 단추, `( )`는 탭·전환, `▾`는 펼침.

### 2.1 선수 상세

어디서든 선수 이름을 누르면 열리는 창 (지금 `PlayerDetail` 한 장짜리 긴 창을 탭으로 나눈다).

#### 2.1.1 창 모양

- **데스크톱**: 본문 오른쪽에서 열리는 넓은 판 (폭 720px, 본문 위에 겹침). 뒤 목록이 왼쪽에 보여서, 판을 연 채 목록의 다른 선수를 누르면 판 내용만 바뀐다. 판을 닫으면 목록의 스크롤·선택·키보드 초점을 되돌린다 (짚쨩 안1 5장). 가운데 큰 창으로 할지는 7장 3.
- **휴대폰**: 전체 화면. 위쪽 머리는 접혀서 한 줄(이름·자리·상태)로 붙고, 탭은 가로로 밀린다. 닫기는 왼쪽 위 `←`와 뒤로 가기.
- Esc로 닫힌다. 판 안 탭은 이 브라우저에 기억 (마지막에 본 탭으로 열림).

#### 2.1.2 머리 (탭과 상관없이 늘 보임)

```
┌ 데스크톱 ─────────────────────────────────────────────────────────────┐
│ ▌두산  #52 김OO   2B · SS     29세 · 우투좌타 · 7년차        [☆관심] [×] │
│        유형: 교타자  ·  컨디션 좋음 · 연속 안타  ·  1군                  │
│        종합 61 / 잠재 64 (확신 보통)   연봉 3.2억 · 계약 2028까지       │
│        [기용 보드에서 보기] [트레이드에 넣기] [비교에 넣기]               │
├────────────────────────────────────────────────────────────────────────┤
│ (요약) (능력) (기록) (계약·이력) (투수 등판)                              │
└────────────────────────────────────────────────────────────────────────┘
```

- 구단 색 띠, 등번호(자료에 있으면), 이름, 자리(주 포지션 먼저, 수비 가능 자리 뒤에), 나이(추정이면 "약 29세"), 투타, 연차.
- **유형 이름**(능력치 v2 1.11, 예: 교타자·거포·똑딱이). 투수는 성향 글 한 마디(예: "땅볼 유도형"). 16-7 전에는 비움.
- **상태 낱말**: 컨디션(12단계 뒤), 결장(사유 규칙은 1.1), 병역, 1군/2군/육성.
- 종합 등급 / 잠재 등급: 잠재 표시 방식은 7장 5 (추천: 숫자 하나 + 확신 낱말 높음·보통·낮음). 31세 이상은 잠재를 숨긴다 (지금 오프시즌 화면 규칙과 같게).
- 단추: 우리 선수면 `기용 보드에서 보기`, 다른 구단 선수면 `트레이드에 넣기`(외국인·오프시즌이면 흐림 + 사유), 공통 `비교에 넣기`(트레이드 비교 칸 2.4.3과 같은 칸). `☆관심`은 4장 3 승인 때만.
- 휴대폰 머리: 첫 줄 이름·자리·나이, 둘째 줄 상태 낱말, 등급·단추는 요약 탭 맨 위로 내린다.

- **핵심 능력**: 타자는 맞히기·컨택·파워·선구·주력 + 주 포지션 수비 (v2 전에는 컨택·파워·선구안·주력·수비). 투수는 구위·제구·장타 억제(7장 밖, v2 결정 11 대로)·체력 "약 N구"·투구 효율.
- **올해 기록**: 타자 타율·출루율·홈런·OPS, 투수 평균자책·이닝·탈삼진·WHIP(선발이면 투구 수 평균도). 리그 평균 대비 표시. 최근 10경기 꺾은선(브리핑 전력 변화와 같은 부품).
- 상세에서 더 보이는 것: 핵심 능력에 잠재 등급과 변화, 올해 기록 표본, 세이버 2개(wRC+·FIP), 스카우트 메모 전부.
- 휴대폰: 한 줄 평 → 상태 → 올해 기록 → 핵심 능력 → 메모 순으로 한 줄씩.

- **포수**: 수비 묶음에 도루 저지·블로킹·프레이밍을 더한다. 자료가 없어 추정값이라는 뜻의 "추정" 배지 (능력치 v2 1.4).
- **용어 풀이 예** (게임이 새로 쓰는 문구): 맞히기 "방망이를 낸 공을 맞히는 힘. 높을수록 헛스윙과 삼진이 적다." / 2S 대처 "두 스트라이크에 몰려도 삼진을 덜 당한다." / 끈질김 "타석마다 공을 많이 보게 한다. 상대 투수의 투구 수가 는다."

### 2.2 경기 중계·박스스코어

세 갈래로 나눈다: (1) 자동 진행(B)의 **경기 결과** 화면, (2) 수동 경기(A)의 **공 단위 중계**, (3) 자동 진행 중 **위기 끼어들기** 창. 지금 `GameCast`(문자 중계·하이라이트)와 `CommandView`(타석 물음, 미리보기)는 A가 들어오는 17단계에서 (2)로 바뀐다. 그 전에는 (1)만 새로 만든다.

```

│ LG   0 0 1 0 0 0 1 0 0   2  7  1  3                                      │

- **머리**: 날짜·경기 시각(임시 규칙)·구장·차전. 일정 개편 뒤에는 "더블헤더 1차전", "강우 콜드(7회)", "노게임", "순연 경기" 표시 (일정 개편 기획안 4.7, 15단계).

- **승·패·세이브(·홀드)**: 이닝과 **투구 수**를 함께.

- 휴대폰: 라인스코어는 R·H·E만 고정하고 이닝은 가로 밀기. 탭 셋은 위 고르기 칸. 박스스코어는 팀 하나씩 (팀 이름 고르기).

#### 2.2.2 공 단위 중계 (A 수동 경기, 17단계)

엔진 2 3.4의 규칙을 화면으로 옮긴다: 타석 사이에는 늘 묻고, 공 사이에는 "멈춤"을 눌렀을 때만 묻는다. **한 번 던진 공은 되돌리지 않는다** — 되돌리기·미리보기 단추를 두지 않는다 (3.7.3).

```
┌ 데스크톱 ──────────────────────────────────────────────────────────────┐
│ 두산 3 : 2 LG   7회 초  1아웃                 ◇ 2루 주자 ○ (주력 좋음)   │
│ B ●●○  S ●○  O ●○          투수 박OO  투구 수 87 (체력 약 95구)          │
│ 타자 김OO 3번 LF  오늘 2타수 1안타 · 올해 .298        [멈춤 ❚❚] [속도 ▾] │
├────────────────────────────────┬──────────────────────────────────────┤
│ 공 단위 중계                    │ 작전 (지금 수비)                      │
│ 7회초                           │  투수: 박OO 87구 · 컨디션 보통        │
│  1구 볼            B1 S0        │  [투수 바꾸기 ▸]  [고의4구]           │
│  2구 헛스윙        B1 S1        │  [피치아웃]  [전진 수비]              │
│  3구 파울          B1 S2        │  [대수비 ▸]                           │
│  4구 볼            B2 S2        │  (구종·코스 지시: 나중 단계)           │
│  5구 2-2에서 헛스윙 삼진        │                                       │
│ 김OO: 유격수 쪽 땅볼, 6-4-3 병살 │  [다음 타석 ▶] (지금 작전 그대로)      │
├────────────────────────────────┴──────────────────────────────────────┤
│ [자동으로 끝내기 ▾  AI 감독이 공 단위로 계속(기본) / 빠르게 끝내기]       │
└──────────────────────────────────────────────────────────────────────────┘
```

- **점수판(위, 고정)**: 점수·이닝·아웃·주자 그림(누에 주자 점, 누르면 주자 이름·주력 낱말), 볼카운트 B·S·O 점, 투수 이름·**투구 수**·체력 "약 N구"(보이는 한계, 실제 한계는 숨김), 타자 이름·타순·자리·오늘 기록·올해 타율.
- **공 단위 중계(왼쪽)**: 공마다 한 줄 `n구 결과 B·S`. 타석이 끝나면 굵은 줄로 결과("2-2에서 헛스윙 삼진", 타구 유형·방향 "유격수 쪽 땅볼, 6-4-3 병살"). 1단계 A는 구종이 하나라 공마다 구속을 쓰지 않는다 (20단계에서 구종·구속 칸). 공 4개 고의4구 시대(1982~2017)는 공 4개가 실제로 찍히고, 폭투·포일이 나면 그 줄에 적는다.
- **작전 판(오른쪽)**: 공격일 때 `강공 / 번트(희생·스퀴즈) / 도루 / 히트앤드런 / 대타 ▸ / 대주자 ▸`, 수비일 때 `투수 바꾸기 ▸ / 고의4구 / 피치아웃 / 전진 수비 / 대수비 ▸`. `▸`는 후보 판(기용 보드 후보 창과 같은 표: 이름·최근 기록·상태·관련 능력, 투수는 오늘 투구 수·휴식일·연투). 고른 작전은 그 자리에서 확정되고 줄에 "작전: 도루" 표시가 남는다.
- **물음 때**: 타석 사이에는 판이 켜진 채 멈추고 `다음 타석 ▶`(지금 작전 그대로, 키보드 Space)를 누를 때까지 기다린다. 공 사이에는 `멈춤`을 누르면 다음 공 전에 멈추고 판이 켜진다. 멈췄다가 아무것도 고르지 않고 `계속`해도 결과가 같다 (엔진 2 3.4).
- **속도**: 공 사이 간격 느림·보통·빠름 (브라우저에 기억). 타석이 끝날 때 한 번 더 쉰다.
- **자동으로 끝내기**: 기본은 "AI 감독이 공 단위로 계속"(A 계속), 고를 수 있는 것은 "빠르게 끝내기"(B로 전환) (엔진 2 결정 7장 5). 누르면 확인 한 줄("남은 경기를 AI 감독이 지휘합니다").
- **경기 중 저장**: 물음마다 자동 저장(3.7.3). 상태 줄 저장 표시가 "경기 중 자동 저장"이 된다. 경기 중 창을 닫으면 브리핑 홈 다음 경기 카드가 "경기 중: 7회초 3:2 · [이어서 지휘]"로 바뀌고 결정함 맨 앞에 "진행 중인 경기"가 생긴다(진행을 막는 일).
- **요약 / 상세**: 요약은 점수판 + 타석 결과 줄만(공 줄은 접힘), 상세는 공 줄 전부 + 타자·투수 오늘 상대 기록 + 작전 후보 표의 능력 열.
- **휴대폰**: 점수판 두 줄(점수·이닝·아웃 / B·S·O·투구 수)을 위에 고정, 가운데 중계 줄, 아래 고정 영역에 `[멈춤] [작전] [다음 타석 ▶]` 세 단추. `작전`은 아래에서 올라오는 판. 주자 그림은 점수판 오른쪽 작은 마름모.
- 물음 수가 많다(타석 사이만 해도 경기당 약 75번). 줄이는 설정은 7장 6 (제안).

### 2.4 영입 > 트레이드 작업대

#### 2.4.1 흐름과 지금 엔진

다섯 단계: **후보 보드 → 최대 3명 비교 → 제안 구성 → 협상 → 최종 검토**. 위쪽에 단계 표시줄을 두고, 앞 단계로는 언제든 돌아간다.

- 지금 엔진: `session.proposeTrade`는 AI 평가가 `accept`면 **그 자리에서 성사**시키고 조작 기록 `trade`를 남긴다. 평가만 하는 `session.evaluateTrade`가 따로 있고, AI 판단은 난수를 쓰지 않는다 (`src/ai/`).
- 그래서 카드 순서(협상 → 최종 검토 → 성사)는 **화면에서 "평가 → 합의 → 확정"으로 나눠** 만들 수 있다: 협상 단계의 "보내기"는 평가만 하고, 상대가 받아들이면 "합의"가 된다. 최종 검토에서 `확정`을 눌러야 `proposeTrade`(다시 평가 + 성사)가 돈다. 엔진·조작 기록·재현은 그대로다. 합의 뒤 날짜·명단이 바뀌면 확정 때 다시 평가해 달라지면 알린다.
- 이 방식으로 할지는 7장 4. 지금 방식(받아들이면 바로 성사)을 고르면 "최종 검토"가 "보내기 전 검토"로 앞당겨진다 (협상과 순서가 바뀜).
- 위험: 받아들일 안을 성사 없이 여러 번 확인할 수 있게 된다. 지금도 거절은 대가 없이 반복되므로(M4 "제안 횟수 제한 없음") 새 악용이 크지는 않지만, `docs/trade-exploits.md`에 한 줄 더한다.

```

│ 상대 [전 구단 ▾]  자리 [전체 ▾]  나이 [~ ▾]  계약 [~ ▾]  ☐ 우리 약한 자리만   │
│ 이름   팀   자리   나이 종합 잠재  연봉   계약   상태      [비교 +]          │
│ 박OO   KT   2B     27   58   63   1.8억  2027   1군       [+]              │

- 기본은 전 구단 선수 (지금은 구단을 먼저 골라야 함). "우리 약한 자리만"은 우리 1군 주전 등급이 낮은 자리(약자)부터 걸러 준다 (보이는 능력만).
- 상대 구단 성향 "우승 도전 / 리빌딩"(`TENDENCY_LABEL`)을 팀 이름 옆 작은 꼬리표로 (이미 엔진이 정하는 값).
- 외국인·오프시즌·마감 뒤는 줄을 흐리게 + 사유. 마감 날짜는 지금 임시 규칙(7월 31일).
- 선수 상세의 `트레이드에 넣기`·`비교에 넣기`가 이 보드의 비교 칸과 제안판으로 연결된다.
- "선수 내놓기"(지금 `shop` 모드: 우리 선수를 내놓고 다른 구단 제안 받기)는 후보 보드 위 고르기 칸 `(데려오기)(내놓기)`로 둔다. 내놓기는 ③ 제안 구성의 반대 방향(받은 제안 목록 → ⑤ 검토)으로 바로 간다.

#### 2.4.3 2단계 비교 (최대 3명)

```
┌ ②비교 ──────────────────────────────────────────────────────────────────┐
│              박OO (KT 2B 27)    최OO (LG RF 31)    우리 2B 주전 김OO       │
│ 종합 / 잠재    58 / 63(보통)     62 / —             55 / 57              │
│ 맞히기         ▮▮▮▮▯ 55          ▮▮▮▮▮ 60           ▮▮▮▯ 48               │
│ 파워           ...                                                       │
│ 올해 OPS       .781 ▲            .823 ▲             .702 ▼               │
│ 수비 (그 자리)  2B 61             RF 55              2B 52                │
│ 계약           1.8억 · 2027      4.5억 · FA 앞      1.2억 · 2029          │
│ 상태           1군 · 컨디션 보통   결장 · 6/20 복귀    1군                  │
│              [제안에 넣기]       [제안에 넣기]                             │
└──────────────────────────────────────────────────────────────────────────┘
```

- 셋까지 나란히. **오른쪽 끝 칸은 늘 "우리 같은 자리 주전"**(자리가 다르면 첫 후보의 자리 기준)이라 바꾸면 얼마나 나아지는지 보인다.
- 행은 선수 상세 요약 탭의 핵심 능력 + 올해 기록 + 수비 + 계약 + 상태. 상세에서는 능력 탭 전부.
- 가장 좋은 칸에 굵은 글자 (색만으로 구분하지 않는다).
- 휴대폰: 두 명씩 (셋째는 가로 밀기). 우리 주전 칸은 맨 위 한 줄 요약으로.

#### 2.4.4 3단계 제안 구성

```
┌ ③제안 ───────────────────────────────────────────────────────────────────┐
│ 우리가 내줄 것 (최대 4명)          │ 받을 것 · 상대 KT (리빌딩)            │
│  [선수 고르기 ▸]                   │  박OO 2B 27  58/63                     │
│  이OO P 24  52/60                  │  [선수 고르기 ▸]                        │
│  지명권 [2028 2라운드 ▾]           │  지명권 [ ▾ ]                           │
│  현금 [ 0.0 ] 억 원                │                                        │
│ ─ 바뀌는 것 ─────────────────────────────────────────────────────────────│
│ 1군 29→29 · 소속 66→66/68 · 캡 대상 연봉 +0.6억 (상한까지 3.1억)           │
│ 우리 2B 깊이: 주전 등급 55 → 58 · 상대 KT 야수 18명 → 17명 (거절될 수 있음 ⚠)│
│                           [상대가 원하는 조건 묻기]  [④ 협상으로 보내기 ▶]  │
└──────────────────────────────────────────────────────────────────────────┘
```

- 양쪽 최대 인원은 규칙 값(`ruleOf(league, 'maxPerSide')`, 지금 4명)을 그대로 쓴다.
- **바뀌는 것**: 정원(1군·소속/정원), 캡 대상 연봉 변화(캡이 있는 해), 자리 깊이(주전 등급 변화, 포수 수, 투수·야수 수). AI 최소 인원(야수·투수 18명, 포수 2명)은 **상대 쪽에 걸릴 때도** 미리 경고한다 (엔진이 `reject-roster`로 거절할 일을 보내기 전에 알림).
- `상대가 원하는 조건 묻기`(지금 `askPackage`): 상대 요구안을 우리 쪽 칸에 채워 보여 준다(바로 보내지 않음).
- 휴대폰: 내줄 것 / 받을 것을 위아래로, "바뀌는 것"은 접힘 상자, 아래 고정 단추 `협상으로 보내기`.

#### 2.4.5 4단계 협상

```
┌ ④협상 ── KT 단장 ───────────────────────────────────────────────────────┐
│ 보낸 안 #3: 이OO + 2028 2R ↔ 박OO                                         │
│ 답: "박OO는 저희 내야의 중심입니다. 투수 한 명이 더 있으면 생각해 보겠습니다." │
│ 거절 이유: 가치가 모자람                                                    │
│ [상대 요구안 보기]  [③으로 돌아가 고치기]                                    │
│ ─ 이 상대에게 보낸 안 ─────────────────────────────────────────────────── │
│ #1 거절 (가치)   #2 거절 (선수단 규칙: 상대 포수 2명 아래)   #3 거절 (가치)  │
└──────────────────────────────────────────────────────────────────────────┘
```

- 답 문장은 지금 `TradeEvaluation.message`. **거절 이유는 엔진이 주는 구분만** 보인다: `reject-value`(가치), `reject-roster`(선수단 규칙), `reject-invalid`(잘못된 제안). 가치 차이 숫자(`detail`)는 보여 주지 않는다 (지금 규칙: 화면에 수치를 그대로 보이지 않음).
- 전수조사 남은 문제 "트레이드 요구안 거절 사유 구분 없음"은 요구안(`askPackage`)이 실패할 때도 같은 세 구분으로 이유를 보이면 줄어든다 (엔진이 이유를 돌려주게 하는 작은 일, U2-6 메모).
- **보낸 안 기록**: 이 상대에게 오늘 보낸 안 목록 (화면 상태, 저장하지 않음).
- 상대가 받아들이면 "합의" 표시 + `⑤ 최종 검토로 ▶` (7장 4가 추천대로일 때). 지금 방식이면 여기서 성사.
- 휴대폰: 답 상자 → 이유 → 단추 → 보낸 안 목록(접힘).

#### 2.4.6 5단계 최종 검토

```
┌ ⑤최종 검토 ─────────────────────────────────────────────────────────────┐
│ KT와 합의한 안                                                             │
│  내줌: 이OO (P 24, 52/60, 0.9억 · 2028) · 2028 2라운드 지명권              │
│  받음: 박OO (2B 27, 58/63, 1.8억 · 2027)                                   │
│ 정원 1군 29 · 소속 66/68 · 캡 대상 +0.9억 (상한까지 2.2억)                 │
│ 받은 선수는 2군에 등록됩니다. 되돌릴 수 없습니다.                            │
│                                  [취소]   [트레이드 확정]                   │
└──────────────────────────────────────────────────────────────────────────┘
```

- 선수·계약·지명권·현금·정원·캡·"받은 선수는 2군"(지금 소식 문구 그대로). 확정 단추는 한 번 더 누르는 확인(`ConfirmButton`).
- 확정 때 다시 평가해 결과가 달라졌으면 "상대가 생각을 바꿨습니다" + ④로.
- 성사 뒤: 결과 한 줄 + `기용 보드에서 자리 정하기` 단추.

### 2.5 오프시즌 단계 화면

#### 2.5.1 흐름

- 결산(성장·연차·은퇴·병역) → 8단계: FA → FA 보상선수 → 2차 드래프트·특별 지명 → 외국인 선수 → 신인 드래프트 → 연봉 협상 → 정원 정리 → 개막 준비 (`STAGES`, `STAGE_LABEL`).
- 자리: 단계 화면은 **영입 > 계약·지명**(지금 `Offseason.tsx`) 하나에 둔다 (메뉴 자리 고정 원칙). 브리핑 홈 오프시즌 카드(1차)가 지금 단계·남은 처리를 보여 주고 이 화면으로 연결한다. 성장·입대는 전력 메뉴 그대로.

```
┌ 영입 › 계약·지명 ────────────────────────────────────────────────────────┐
│ 2027 오프시즌   ✓FA ✓보상 ●2차 드래프트 ○외국인 ○신인 ○연봉 ○정원 ○개막 준비 │
│ ┌ 이 단계에서 할 일 ───────────────────────────┐ ┌ 곁 칸 ───────────────┐ │
│ │ 2차 드래프트: 우리 차례 2번 · 보호 명단 35명   │ │ 지명권 장부           │ │
│ │ [후보 표] ...                                  │ │ 캠프 · 다년 계약      │ │
│ └────────────────────────────────────────────────┘ │ 이 오프시즌 소식      │ │
│ 남은 처리: 우리 지명 1건 (안 하면 자동 지명)        └───────────────────────┘ │
│                          [다음: 외국인 선수 ▶]                                 │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **단계 표시줄**: 지난 단계 ✓, 지금 ●, 남은 단계 ○. 휴대폰에서는 지금 단계로 저절로 밀린다(2차에서 만듦). 지난 단계를 누르면 그 단계 기록(소식 묶음)을 읽기 전용으로.
- **이 단계에서 할 일**: 지금 단계 판(지금 `FaPanel`·`CompPanel`·…). 표는 공통 표 부품으로 바꿔 열 묶음·정렬·거르기를 같게 한다.
- **남은 처리**: 결정함의 오프시즌 항목(1차 `decisions.ts`) 중 이 단계 것. 남은 처리가 있는데 `다음`을 누르면 확인 창에 그 목록과 "넘기면 일어나는 일"(예: "우리 FA 제시가 없으면 선수는 떠납니다", "지명하지 않으면 자동 지명")을 보인다. 지금은 화면에 경고만 있고 확인 창은 없다.
- **곁 칸**: 지명권 장부(드래프트까지), 캠프, 다년 계약, 이 오프시즌 소식 (지금 구성 그대로).

## 6. 다른 게임에서 옮기지 않은 것

- 탭으로 나눈 선수 창, 소식·결정 모아 보기, 열을 고르는 기록 표는 장르에 흔한 정보 구조라 참고했다 (사용자 지시 "FM·OOTP 참고"). 그림·아이콘·색 배합·탭 이름·능력 이름·문구는 이 게임의 것을 쓴다 (탭 이름 "요약·능력·기록·계약·이력·투수 등판"은 이전 기획안 3장에서 이어받은 이 게임의 이름).
- 능력 이름은 능력치 v2 기획안(결정기록의 낱말과 이 게임 엔진 손잡이)에서 왔다. "스카우트 메모"·"확신 낱말"·"합의 → 확정"은 이 문서가 새로 붙인 이름이다.

## 7. 사용자가 정할 것 (번호 순, 하나씩)

1. **리그 평균 대비 표시 방식** (1.3, 이전 기획안 결정 6이 답 없이 남음): ① 요약은 ▲▼ 모양 + 색, 상세는 리그 백분위 "상위 8%" (추천) / ② 모두 색 점 / ③ 모두 차이 숫자 ".312 ▲.045" / ④ 모두 백분위. 이유: 초보는 좋다·나쁘다만 보면 되고, 하드코어는 어디쯤인지가 궁금하다. 모양(▲▼)을 함께 써서 색을 못 보는 사람도 읽는다.
2. **요약 모드에서 등급 숫자**: ① 숫자 + 낱말 함께 (추천) / ② 낱말·막대만, 숫자는 상세에서. 이유: 같은 선수를 두 모드에서 다른 말로 읽게 되면 헷갈리고, 20~80은 이미 게임 곳곳(기용 보드·후보 표)에 숫자로 있다.
3. **선수 상세 창 모양 (데스크톱)**: ① 오른쪽에서 열리는 넓은 판, 뒤 목록이 보임 (추천) / ② 가운데 큰 창. 이유: 목록에서 선수를 차례로 눌러 넘겨 보기 쉽고, 트레이드 비교·기용 보드와 함께 쓰기 좋다.
4. **트레이드 "합의 뒤 확정"**: ① 상대가 받아들이면 "합의" → 최종 검토 → 확정 때 성사 (추천, 카드 순서) / ② 지금처럼 받아들이면 바로 성사 (검토는 보내기 전). 이유: 실수로 성사되는 일을 막고, 엔진·재현을 바꾸지 않는다. 받아들일 안을 미리 확인할 수 있게 되는 점은 지금도 거절이 공짜라 차이가 작다.
5. **잠재 등급 표시 (27세 이하 스카우트 오차)**: ① 숫자 하나 + 확신 낱말 "높음·보통·낮음" (추천) / ② 범위 "55~65" / ③ 숫자만. 이유: 범위를 오차 폭 그대로 그리면 실제 값이 늘 그 안이라 정답 경계를 알려 주는 셈이 된다. 숫자 + 낱말이 "흐린 짐작" 결정 취지에 맞다.
6. **수동 경기 물음 줄이기 (제안)**: 타석 사이 물음이 경기당 약 75번이다. ① "물음 줄이기" 설정을 둔다: 켜면 주자가 있거나·7회 이후·투수 교체를 판단할 만한 때(AI 감독이 교체를 고민하는 때)만 멈추고, 나머지 타석은 지금 작전 그대로 넘어간다 (추천) / ② 엔진 2 결정대로 늘 묻는다. 이유: 처음 해 보는 사람도 한 경기를 끝까지 지휘할 수 있다. 멈춤 여부는 난수를 쓰지 않아 결과가 같다 (엔진 2 3.8 끼어들기와 같은 성질).
7. **다른 구단 보기 (제안, 4장 1)**: 넣는다 (추천) / 넣지 않는다. 이유: 트레이드 작업대와 바로 이어지고 작업량이 중간이다.
8. **표 보기 저장 (제안, 4장 4)**: 넣는다 (추천) / 넣지 않는다. 이유: 표 부품 위에 얹는 작은 일이다.
9. **관심 명단 (제안, 4장 3)**: 넣는다, 세션 저장에 담음 (추천) / 브라우저 저장 / 넣지 않는다. 이유: FA·트레이드 준비에 쓰이고, 저장 파일과 함께 다녀야 한다.
10. **전체 검색 (제안, 4장 2)**: 넣는다, 맨 나중에 (추천) / 지금 선수 검색으로 충분. 이유: 은퇴 선수·옛 경기를 찾을 일이 여러 시즌 뒤에 생긴다.

다른 기획에 남은 결정 중 이 화면에 걸리는 것 (여기서 묻지 않음): 능력치 v2 결정 10 적극성 표시(능력 탭 한 줄), 결정 11 투수 장타 억제(투수 능력 줄), UI 2차 보고의 추천 점수 식·AI 맡기기 바로 적용·결정함 '1군 빈자리'.
