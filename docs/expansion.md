# 확장 기획 초안 v0.1

작성일 2026-10-09. M8까지 끝난 뒤의 확장 후보를 모아 평가하고 순서를 제안한다. 공개 검토(라이선스·권리)는 이미 배포 중이라 이 문서에서 다루지 않는다 (`docs/release-1.0-gaps.md`).
확정된 것은 없다. 사용자가 고른 항목만 기획서(`docs/design.md`)에 옮기고 마일스톤에 올린다.

## 1. 지키는 것

확장을 해도 바꾸지 않는 원칙이다.

- 실존 인물 규칙 (기획서 7장): 실존 선수에게 구체적 사건·부정적 꼬리표를 붙이지 않는다. 숨겨진 특수능력도 실존 선수는 긍정·중립만.
- 데이터와 코드 분리: 새 제도·수치는 `data-src/`나 `params.ts`에 두고, 가상 선수 데이터로 바꿔도 돌아가야 한다.
- 재현성: 난수는 `Rng`만, 같은 시드·같은 조작은 같은 결과. 새 조작은 모두 `GameAction`으로 남겨 재현(`replay`)이 깨지지 않게 한다.
- 근거 없는 값은 "임시값"으로 표시하고, 리그 평균이 틀어지지 않는지 `npm run validate`로 확인한다.
- 플레이어는 단장이다. 경기 중 작전은 AI 감독이 한다 (기용표만 플레이어).

## 2. 평가 기준

| 기준 | 뜻 |
|---|---|
| 재미 | 플레이어가 내리는 결정이 늘거나, 결정의 결과가 더 또렷해지는가 |
| 비용 | 엔진·리그·화면 중 몇 층을 건드리는가. 저장 형식이 바뀌는가 |
| 검증 | 자동 테스트나 검증 스크립트로 맞는지 잴 수 있는가. 실제 기록과 대조할 수 있는가 |
| 임시값 | 근거 자료 없이 정해야 하는 값이 얼마나 많은가 |
| 권리 | 실존 인물 규칙·데이터 권리에 닿는가 |

## 4. 추천 순서

재미 대비 비용이 좋고 기존 부품 위에 바로 얹히는 것부터. 한 단계가 끝날 때마다 테스트·검증·문서를 갱신하고 배포한다.

1. **확장 1 — 운영의 깊이 (A1, A2, A3, E5)**: 모두 오프시즌 단계와 보호 명단 부품 재사용. 저장 형식은 그대로(선택 필드). 사용자가 직접 제기한 투타 전향을 먼저.
2. **확장 2 — 감독과 서사 (C1, D3, D4, E3)**: 감독 성향은 엔진 조정값을 구단별로 나누는 것이라 검증 가능. 기록실·기사·역사 화면은 있는 자료를 보여 주는 일.
3. **확장 3 — 재정 상세형 (B1~B4, E1)**: 가장 크고 임시값이 많다. 관중 자료를 얼마나 모을 수 있는지에 달렸다. 모델을 먼저 문서로 정하고 수치는 longsim으로 맞춘다.
4. **확장 4 — 엔진 정밀화 (C2, C4, A5, D1, D2)**: 재미보다 정확도·완성도. 검증 지표가 있어 뒤로 미뤄도 손해가 적다.

보류: C3 구장 효과(자료 없음), D5 선수 성격(권리), E2 경기 보기(저장·성능 부담).

## 5. 항목별 설계 메모

바로 착수할 확장 1만 조금 더 적는다. 나머지는 고르면 그때 쓴다.

### A1 투타 전향
- 조작: 오프시즌 "정원 정리" 단계에서 2군 선수 한 명을 전향. `GameAction` `convert`로 기록.
- 실존 선수: 반대 역할의 실제 기록이 있을 때만 (커리어 인덱스), 그 기록으로 능력 산출. 없으면 전향 불가 (실존 인물에게 없는 커리어를 만들지 않는다).
- 가상 선수: 새 역할 능력은 잠재력에서 나이 여유분을 뺀 값보다 낮게 시작 (-10런 안팎, 임시값). 잠재력은 그대로.
- 제한: 시즌당 구단 1명, 전향 뒤 2시즌 재전향 불가 (임시값). AI 구단은 하지 않는다 (1차).
- 화면: 선수단 2군 표에 "전향" 버튼, 선수 상세에 전향 이력.
- 테스트: 전향 뒤 저장·재현 일치, 실존 선수 제한, 1군 엔트리 투수·야수 수 규칙.

### A2 2차 드래프트
- 주기: 2년마다 (홀수 해 오프시즌, 임시값. 실제 시행 연도는 제도연표에서 확인).
- 순서: 드래프트 단계 앞 별도 단계 `draft2`. 보호 명단 35명(임시값) + 자동 보호(신인 1~2년차, 외국인, 군 보류). 3라운드, 역순. 지명 보상금은 장부.
- 플레이어: 보호 명단 편집(ProtectEditor 재사용), 지명은 드래프트 화면과 같은 틀.
- AI: FA 보상선수와 같은 가치 함수. 필요 포지션 가산점.
- 테스트: 보호 인원, 자동 보호, 이동 뒤 정원, 재현.

### A3 창단 보호 명단 화면
- 결산 때 창단이 있으면 `applyTeamChanges`가 특별 지명을 바로 하지 않고 단계 `expansion`을 열어 플레이어가 20명을 고른 뒤 마감. AI 구단은 지금처럼 자동.
- 저장: `OffseasonState.expansion` 필드 추가 (선택). 이전 저장은 없음.

### E5 자동 QA 리포트
- `tools/longsim.ts`에 `--report` 옵션: 시드 여러 개 × N시즌의 지표(득점, 승률 분산, 선수 수, 연봉 합, 은퇴·입대 수, 특수능력 효과)를 표로 `reports/`에 저장. 확장마다 전후 비교.

## 6. 사용자가 정할 것

1. 확장 1의 네 항목(A1 투타 전향, A2 2차 드래프트, A3 창단 보호 명단, E5 QA 리포트)으로 시작해도 되는지, 빼거나 더할 것이 있는지.
2. 재정 상세형(B)을 할 것인지, 한다면 관중·수입 자료를 모을 수 있는지 (없으면 전부 임시값).
3. 감독 성향(C1)에서 플레이어가 감독을 고르는 것까지 넣을지, 구단 고정으로 둘지.
4. 보류 세 가지(구장 효과, 선수 성격, 경기 보기)를 정말 보류할지.
